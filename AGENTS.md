# Instructions for agents working in PersAI

## Mandatory six-step delivery cycle for EVERY stage and package (owner decision 06 November 2026)

1. **Inventory before building:** inspect current `main`, status register, actual code and tests. Never create a second storage, search, or execution mechanism.
2. **Specify behavior:** user actions and natural-language dialog scenarios, interface, APIs/contracts, success/error/cancel states, permissions and acceptance criteria. Default to dialog first; justify separate screens.
3. **Small sequential PRs:** one verifiable user-facing slice, dedicated tests, dependencies and remaining work.
4. **Architecture gate before AND after:** record C0-A and C3-B for the actual diff, same authoritative store/writer/reader, ACL/CAS/undo, provenance, restore and search/index lifecycle.
5. **CI → merge:** fix mandatory CI to SUCCESS on exact SHA; verify target; merge to `main` and verify actual new `main` content. Do not claim a finished PR based on one passing test.
6. **Milestone APK + physical check:** build signed APK at functional milestones; check affected scenarios on the actual phone when performed. Report automated CI, release APK and physical Android tests **separately**; write NOT_RUN_PHYSICAL when untested, never claim PASS.

Read canonical full Russian wording in [PLAN.md](PLAN.md#обязательное-правило-реализации-каждого-этапа-и-пакета-решение-владельца-06112026) and gates in [docs/DEVELOPMENT_GATES.md](docs/DEVELOPMENT_GATES.md). Apply this cycle to each future step, not only UI PRs.

## Mandatory checkpoint for EVERY implementation step (owner decision 26 October 2026)

Read and follow **[docs/DEVELOPMENT_GATES.md](docs/DEVELOPMENT_GATES.md)** for **every** task and PR, not only mobile UI. This is an actionable project rule; Cursor also has an always-applied rule in `.cursor/rules`.

Choose REUSE/EXTEND/REPLACE/NEW with reason, surface P1 privacy/TOCTOU or migration risks before broad changes. Report PASS/GAP/BLOCKED. See `docs/DEVELOPMENT_GATES.md` and the retrospective `docs/architecture/MEMORY_PR_RETROSPECTIVE_2026-10-28.md` for existing memory risks.
- **Before coding:** refresh actual `main`/PR status; check `PLAN.md` §2, `Plans/ROADMAP_STATUS.md` and **all relevant ACTIVE feature subplans/OpenSpec** (exclude archives and redirect stubs) for current requirements and contradictions; examine existing code and tests. Check approved references and relevant best practices. For substantial UI or architecture work compare **current verifiable** sources/analogues and adapt them to Android, local-only storage and Nebula; preserve user decisions. Update stale plans before/alongside code. Avoid redundant research for trivial changes; state N/A with a reason.
- **Memory Engine 96-case evidence:** use `Plans/MEMORY_SCENARIO_MATRIX_2026-10-27.md` for actual scenario requirements AND update the matching row in `Plans/MEMORY_96_SCENARIO_ACCEPTANCE_2026-10-28.md` only when concrete evidence changes. Partial unit fixtures must stay PARTIAL; do not mark 96/96 DONE mechanically. No second roadmap or test-for-status shortcut.\n- **At the end of EACH partial implementation:** review **only the implemented slice and its genuinely affected regressions**, not future features. Run relevant success/error/lock/rollback/backup/UI tests as applicable; mark actual PASS/FAIL/NOT RUN/NOT IMPLEMENTED with exact SHA.
- **Mandatory second final review: PLAN CONFORMANCE.** Compare the **actual diff and verified behavior** against the applicable current-step requirements in `PLAN.md` **and feature subplans/OpenSpec**. Report MATCH / PARTIAL / DEVIATION / NOT IMPLEMENTED (future) / NOT VERIFIED. Fix unjustified departures before declaring completion, or explicitly justify and synchronize PLAN, status register and subplans/specs if an approved change is needed; do not quietly redefine requirements after coding. - **C3-B architecture AFTER every PR:** re-run the exact same operation→source→writer→reader→ACL/CAS/undo→backup/index map against the actual diff; compare to C0-A, inspect new callers and race/partial failure conditions, simplify safely, log DEFERRED with exact trigger.
