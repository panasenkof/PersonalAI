# PersAI — инструменты LLM, сквозные поручения и кандидаты сценариев

**Статус: DESIGN / СЦЕНАРИИ НА ВЫБОР ВЛАДЕЛЬЦА, НЕ РЕАЛИЗАЦИЯ. 06.11.2026.** Документ уточняет принцип [«диалог прежде экранов»](DIALOG_FIRST_UX.md) и действующую архитектуру; **не создаёт** новую постоянную задачу №92, отдельную очередь PR или самостоятельный агентный runtime. Исполнительный порядок всегда в [PLAN.md §2](../PLAN.md#2-что-делаем-дальше--единственная-рабочая-очередь), фактические статусы №1–91 — в [ROADMAP_STATUS.md](ROADMAP_STATUS.md). Сценарии ниже — варианты для выбора, **не утверждённые требования**. После выбора владельца выполнить отдельную матрицу сценарий → существующие средства → пробелы → инструменты → безопасность → этап → тесты; только затем менять приоритеты/контракты по согласованию.

## 1. Что проверено в main, а не только задумано

Срез кода `main@6d2a82be`, 06.11.2026; разработка 9A5 продолжается, поэтому перед реализацией сверять **новый** HEAD, а не полагаться на этот снимок.

- `mobile/src/direct-agent/engine.ts` и `tool-catalog.ts`: единая функция вызова LLM с типизированными function tools, лимитом вызовов и результатом, который модель получает обратно. У модели уже есть `search_local_notes`, `read_local_note`, `search_local_source_segments`, `list_local_sources`, `read_local_source_segment`, `list_local_notes`, `count_local_notes`, предложение факта/заметки с подтверждением, `search_web` / `read_web_page` в разрешённых конфигурациях. Наличие в каталоге зависит от доступных callback/провайдера.
- `mobile/src/direct-agent/chat-store.ts` и `article-selection.ts`: для узких формулировок есть отдельная **read-only** выборка сохранённых ссылок по теме/дате сохранения с пагинацией, без вызова LLM; 9A1–9A4. Это **не** универсальный маршрутизатор поручений; найденная ссылка ≠ прочитанная статья.
- `mobile/src/direct-agent/document-synthesis.ts` уже обрабатывает загруженные большие текстовые вложения порциями; это **не** генератор экспортируемого иллюстрированного DOCX/PDF из найденных источников.
- `mobile/src/direct-agent/web-tools.ts` содержит ограниченные расходы на один ход (в данном срезе до трёх поисков и трёх чтений страниц); для широкой подборки нужен явный контролируемый бюджет с точным отчётом о покрытии.
- `Plans/MESSENGER_IMPORT_NO_N8N.md`: целевой импорт Telegram/MAX по ссылкам/Android Share ещё не равен доступу агента к истории Telegram. Не обещать произвольное чтение чатов; искать только в разрешённом, **уже импортированном** содержимом. `Plans/ASSISTANT_FEATURES.md` №64/76 — почтовые внешние действия и полномочия запланированы, но инструмент отправки письма из диалога сейчас отсутствует.

## 2. Новое обязательное архитектурное правило

**Удобство естественного поручения сначала, реальное исполнение — только через проверяемые инструменты приложения.** Не создавать под каждую фразу особую regex-команду или отдельный экран, если её можно выразить композицией существующих безопасных операций; узкие быстрые маршруты, подобные 9A1, допускаются, но должны иметь совместимый контракт и возможность последующего многошагового уточнения.

1. **Единый реестр возможностей**: расширять `direct-agent/tool-catalog.ts` / `engine.ts` и существующие сервисы; каждый инструмент имеет строгую схему аргументов, доступный scope, тип эффекта (`read` / `proposal` / `external_action`), бюджет, условия вызова, обработку ошибки, подтверждение и проверку фактического результата. Провайдеры/модели используют единый контракт; неподдерживаемые функции не рекламируются LLM.
2. **Память**: SQLCipher `repository.ts` / `agent-catalog.ts`, `direct-agent/memory.ts` и source retrieval остаются едиными reader/search/writer. Время/происхождение импорта/тип/полнота фильтруются на устройстве **до** передачи модели; проверять ACL, AppLock, профиль, version и consent. Для Telegram использовать `origin_platform` только если действительно сохранён импортом, а не угадывать по названию.
3. **Доказательное обобщение**: подборка → фактически прочитанные версии → фрагменты / source IDs → итог с проверяемыми ссылками. Указывать «найдено», «прочитано», «не прочитано», точную дату сохранения/публикации и ограничения. Ссылку без доступного текста не пересказывать как прочитанную статью.
4. **Документы и медиа**: отдельный ограниченный экспортный адаптер поверх уже существующего содержимого; итог в чате + сохраняемый документ. Вложения и изображения только при наличии разрешённого источника/прав; нет данных — не выдумывать. Внешние URL и медиа считаются недоверенными данными, не инструкциями для агента. Поддержка PDF/DOCX/изображений — предмет отдельного целевого PR и проверок на устройстве, а не автоматически реализованная функция этапа 9.
5. **Внешнее действие**: подготовка → предпросмотр адресата/темы/тела/вложений → явное разрешение в пределах полномочия №76 → действие с operation ID → проверка подтверждения сервиса. Письмо не объявлять отправленным по факту начала HTTP-запроса; при таймауте сначала выяснить исход, не повторять отправку вслепую. Удаление, рассылка, платежи и изменение защищённых данных требуют отдельных границ.
6. **Многошаговые задачи**: один текущий executor, не новый фоновый агент и не второй журнал. Явный plan/steps/progress/partial/failed/cancelled/completed, отмена остатка, budget токенов/вызовов, ограничения Android AppLock/background; возобновление только после проверки разрешений и версии источников. Пользователь может уточнить или отменить задачу в том же диалоге.
7. **Динамическая доступность**: LLM получает только те инструменты, которые реально разрешены сейчас. Без почты — предложить документ/черновик, не обещать отправку; без сети — локальная подборка; при блокировке — отказ в чтении; чувствительные записи — не отправлять внешней модели.
8. **Тестируемые границы**: 0/1/5/20/100+ источников; точная/семантическая тема, UTC и локальное время, версии/дубли/частичные источники, отсутствие сети/прав, AppLock, смена профиля, отмена в середине, превышение бюджета, повтор после неопределённого результата. Никаких заявлений DONE без CI на SHA, C0-A/C3-B и фактического Android QA (или `NOT_RUN_PHYSICAL`).

Новые большие механизмы не запускать без решения владельца.

## 4. Два исходных сквозных сценария — образцы приёмки, не DONE

- **B01** «Проведи ревизию моих заметок за последнюю неделю из Telegram, выбери по ИИ, напиши статью и отправь по email». Проверить: только уже импортированные сообщения; правильный provenance и локальный интервал; выбранные/отвергнутые/непрочитанные материалы; исходники; качественный текст; экспорт; предпросмотр и подтверждение отправки; фактический delivery receipt либо честная ошибка. Без интеграции почты возможен только черновик.
- **B02** «Найди в интернете статьи по ИИ за неделю, собери иллюстрированный документ и дай выжимку в этот чат». Проверить: явный web consent и дата публикации; список реально прочитанных страниц; качество источников/изображений/ссылок; файл можно открыть; краткий ответ с проверяемыми ссылками; при ограниченном бюджете честная частичная выдача.

## 5. Идеи для голосования — НЕ В ПЛАНЕ РЕАЛИЗАЦИИ до выбора

Стабильные идентификаторы **S01–S24** нужны для голосования в чате. Короткие формулировки здесь — анкета, а не утверждение готовности.

### А. Материалы, поиск и исследования
- [ ] **S01**: Telegram за неделю → отобрать ИИ → написать статью → согласовать и отправить email.
- [ ] **S02**: Интернет за неделю → найти ИИ-статьи → иллюстрированный документ со ссылками + выжимка в чате.
- [ ] **S03**: Сравнить мои сохранённые материалы с новыми статьями из интернета; выделить новые факты и противоречия.
- [ ] **S04**: Собрать сравнительную таблицу моделей/технологий по своим материалам и свежим источникам.
- [ ] **S05**: «Найди разговор/заметку об X», покажи связанные записи, файлы, фото и источник.
- [ ] **S06**: Разобрать несколько больших PDF/аудио/заметок, извлечь доказательные выводы и цитаты.

### Б. Порядок, память, фото
- [ ] **S07**: Предложить тематические разделы, теги и объединение дублей; показать безопасный preview/undo.
- [ ] **S08**: Найти старые/устаревшие/противоречащие сведения и предложить обновления, не переписывая молча.
- [ ] **S09**: «Где лежит предмет?» — найти фото, подпись и контекст в моей памяти.
- [ ] **S10**: Найти похожие фотографии или документы по образцу из камеры/галереи и текстовому описанию.
- [ ] **S11**: По человеку/проекту построить хронологию событий, разговоров, решений и материалов.
- [ ] **S12**: «Из этих заметок сделай единый конспект» — сохранить отдельный результат, исходники не трогать.

### В. Создание материалов и коммуникации
- [ ] **S13**: Сделать статью/отчёт из заметок + интернета с оглавлением, иллюстрациями, ссылками, DOCX/PDF.
- [ ] **S14**: Из заметок, фотографий и текста подготовить презентацию для выступления.

### Г. Задачи, сопровождение, обучение
- [ ] **S19**: По заметкам и переписке собрать мои обещания, открытые вопросы, сроки и предложить задачи.
- [ ] **S20**: Каждую неделю по моему разрешению готовить тематическую сводку и присылать в согласованный канал.
- [ ] **S21**: Отслеживать выбранную страницу/тему в интернете и сообщать только о значимых изменениях.

- [ ] **S23**: Помочь выбрать товар/услугу: сравнить актуальные параметры/цены с моими требованиями, сохранить вывод.

После отметок владельца: оставить только выбранные ID, описать для каждого вход → действия → ожидаемый результат → варианты ошибок → разрешения → смежные сценарии, а **затем** построить матрицу повторно используемых инструментов и распределение по существующим этапам. Не счесть отсутствие отметки согласием и не переводить всё голосование в обязательные задачи.
