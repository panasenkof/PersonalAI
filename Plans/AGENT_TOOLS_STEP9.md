Часть маршрутов по фото (`vision-chat-search.ts`) и тематическим подборкам (`article-selection.ts`/`chat-store.ts`) имеет также быстрый локальный маршрут; LLM теперь может выбрать/продолжить подборку через прежний каталог (#384/#389), но **не** получил полную доказательную оркестрацию выжимки. Сохранение результата в заметку и канонический writer существуют в приложении, но это **не доказывает**, что модель может произвольно вызвать их как tool.

**Чего пока нет в каталоге:** фото-поиска как model-callable tool, доказательной оркестрации чтения всех выбранных статей и контекстного уточнения, внутренних действий с выбранными заметками и сохранения фото с пояснением; общего action/approval/receipt для соответствующих будущих операций; внешних mail/calendar/share tools и video-vision. Первая узкая read-only подборка уже добавлена в #384; не объявлять 9T-R1 или весь 9T завершёнными без доказательного multi-read. Эти последующие возможности относятся к другим этапам.

**Пакет 9B / рабочий контекст модели:** [AGENT_TASK_WORKSPACE_STEP9](AGENT_TASK_WORKSPACE_STEP9.md). [#393](https://github.com/panasenkof/PersonalAI/pull/393) сохраняет выбранные ID/version, [#394](https://github.com/panasenkof/PersonalAI/pull/394) подключает проверенное чтение пачками, [#395](https://github.com/panasenkof/PersonalAI/pull/395) — `workspace_put/get/list/clear` как временные **недоказанные** черновики `TaskState` в SQLCipher. Это не отдельная долговременная память, не копия источников, не второй writer и не новое разрешение на личные/внешние действия. Проверять merge/CI #395 по точному SHA. Полный 9T-R1 с реальной моделью и 9T-R2 (фото-tool) пока остаются открытыми.

**Узкий следующий slice 9B — дочитывание выбранной длинной статьи.** `read_selected_article_chunk(selectedIndex, offset, budget)` вызывается в обычном LLM-диалоге для одного из **ранее выбранных** ID/version; модель не выбирает произвольный record ID. Budget 100–6000 символов; `offset=nextOffset` из предыдущего доказанного фрагмента, `hasMore` и `evidence.startChar/endChar` описывают только **прочитанный диапазон**. Даже если дочитан конец, нельзя заявлять о полном охвате начала/середины без их чтения; сохранённая заметка не является оригиналом удалённой веб-страницы. Stale/private/AppLock/cancel и повреждённые evidence не должны передавать контент. Используется тот же `options.read` / canonical SQLCipher reader, без новой базы или writer. Приёмка: >6000 символов за несколько последовательных вызовов, EOF без преувеличения, отказ при подмене ID/индекса/версии, плохом evidence/блокировке. Это **частичный 9B**, не завершённая 9T-R1 или 9C; физический Vivo отдельно.


## 2. Цель 9T

По команде в обычном диалоге **сама модель** при поддержке function calling выбирает и вызывает проверенный инструмент PersAI, получает фактический результат, предлагает следующий безопасный шаг, а после явного решения пользователя приложение применяет **ровно разрешённое действие** существующим writer с проверкой версии/ACL. Это проверяется по trace/receipt, а не по словам модели «сделано».

### Минимальные пользовательские цепочки для DONE 9T

**9T-R1 (read):** «Найди мои сохранённые статьи о локальных LLM за неделю, покажи все страницы и дай краткую выжимку». Модель получает совместимый search/list/read tool (либо пользуется существующим быстрым маршрутом, который отдаёт контекст/handles для дальнейшего LLM-чтения), выводит точные даты и total/hasMore, действительно дочитывает источники, не считает 5 записей всеми.

**9T-R2 (different app function):** «Найди в моей памяти фотографию красного велосипеда у дерева, покажи её и похожие». Через единый каталог/адаптер существующего photo-search используется **локальный** индекс, результат представляет реальные note IDs + image handles, без скрытой передачи изображения внешней модели и без двойного индекса. При отсутствии модели/индекса — точная ошибка/вариант ручного поиска, не ложный результат.

**9T-W1 (approved internal action, вместе с №56/18/20):** «Найди сохранённую статью про X и предложи перенести её в раздел “ИИ”». Модель вызывает read tool, формирует версионированное `proposal`; приложение показывает **конкретную** запись, старый/новый раздел, последствия для поиска/ACL и подтверждение. Только после `confirm` существующий `note-actions.ts` с CAS/ACL выполняет перенос и сообщает реальный receipt/undo; повтор, stale version, locked profile и отказ не изменяют запись. Безопасное действие scope не означает разрешения на удаление, слияние, пересылку, редактирование вложений или внешний доступ.

**9T-W2 (existing proposal compatibility):** «Запомни, что я предпочитаю короткие ответы». Проверить существующий `draft_memory_fact` с явным подтверждением и проверенным фактом сохранения, не плодить второй writer/proposal state.

9T-R2 допускается сделать после 9T-R1 отдельным небольшим PR, если для него нужны ресурсы/визуальное QA. 9T-W1 реализуется **в пакете №56/18/20** как первое узкое подтверждённое действие; не включать неограниченный CRUD раньше DIALOG-ADMIN этапа 13.

## 3. Обязательный инструментальный контракт

- **Один реестр:** `direct-agent/tool-catalog.ts` + `engine.ts`; адаптеры тонко вызывают существующие `local-memory/agent-catalog.ts`, `repository.searchMemory`, `direct-agent/memory.ts`, `source-retrieval`, `media/vision-chat-search`, `note-actions` и consent workflow. Отсутствующая capability **не объявляется модели**. Одно имя функции/строгая JSON-schema + проверка аргументов, typed results и версионирование контракта.
- **Эффекты:** поддерживаемые сегодня `read`, `proposal`, `conversation`. Запись `internal_confirmed_write` — НЕ свободный вызов модели: LLM может только создать предложение; выполнение в **user-owned confirmation callback** с повторной проверкой (scope, AppLock, record ID/version, доступности writer). `external_action` (email/calendar/Share/schedule) только после №76 в этапе 10; не расширять union типов заранее как «готовый» инструмент.
- **Scope:** внешняя LLM видит только разрешённые ordinary/standard данные, которые приложение выбрало в текущем unlocked профиле. Фильтр collections/sensitivities/record_status/version/time **до** выдачи модели. `private/secret/Документы` не отправлять модели, даже если она попросила `read ID`. Выбранный пользователем локальный поиск закрытого текста не означает автоматического grant для внешней LLM.
- **Результат:** `found/empty/read/partial/pending_confirmation/applied/failed/cancelled` и доказательства (source IDs, revision, exact count/hasMore, coverage, receipt/undo); не выдавать «успешно», если реально есть только предложение или недостоверный receipt. Скрипты в HTML/PDF/заметках не могут вызвать инструмент — это untrusted input.
- **Бюджет:** ограничение количества tools, объёма фактически прочитанных байт, времени, числа страниц/переходов и LLM-вызовов; при limit — честный partial и продолжение по явной команде, а не скрытая фоновая задача. Агентский prefetch увеличен до **12**, но в сумме остаётся **24 тыс. символов**; `searchMemory` выдаёт до **100 ранжированных кандидатов**, это **не** полный список всех совпадений. Для точных значений, регрессионных тестов, порогов и остающейся приёмки см. [SEARCH_RECALL_BUDGETS_STEP9](SEARCH_RECALL_BUDGETS_STEP9.md).
- **Приватность/ошибки:** запрет двойного потока в интернет, строгие app lock/profile-switch/AbortSignal, повторная ACL/CAS на read/write, no silent mutation; cancellation не объявлять успешным commit, idempotency/undo где реально обеспечено, error codes без раскрытия персонального содержимого.
- **UI:** обычный чат — прогресс, результаты с источниками и изображениями, компактная карточка предложения `confirm/edit/cancel`, точный итог и undo. Не дублировать экран функции без причины.

## 5. Приёмочные проверки и передача будущим этапам

- **Сценарии**: `9T-R1`, `9T-R2`, `9T-W1`, `9T-W2` плюс соответствующие S05/S07/S12/A07 в [AGENT_SCENARIO_ACCEPTANCE.md](AGENT_SCENARIO_ACCEPTANCE.md). Выполнение сценария в чате должно иметь **trace с подтверждённым tool call**, пользовательский результат, source ID/receipt, а не только красивый ответ.
- **Провайдер**: с function calling и без него; текстовый offline fallback; инструмент не должен рекламироваться LLM, если `provider` не умеет tools или нет разрешения/ресурсов. При ошибке получить объяснение, исходные данные/черновик сохранить.
- **Сбой/защита**: 0 и 100+ записей, stale ID, чужой collection, AppLock во время операции, смена профиля, network abort, превышение бюджета, malicious prompt из статьи, нет модели embedding или фото, подтверждение не той записи. Проверить однозначное `NOT_RUN/PASS/FAIL` и точный SHA.
- **Архитектура**: перед и после каждого функционального PR C0-A/C3-B, PLAN conformance. CI SUCCESS на точном head SHA, merge main+verification, на рубеже APK/Android отдельно. Ни один документационный PR не объявляет реализацию.
- **Передача этапу 10**: новый внешний адаптер по №62/64/76 подключается через **этот** контракт. Никаких собственных tool runtimes, второй очереди предложений и отдельного реестра для почты/календаря.

Согласование: **пользователь просил внести отсутствие универсального app-tool bridge в этап 9**. Эта спецификация удовлетворяет просьбе только в части разработки плана; фактические функции появятся после отдельных реализационных PR, тестов и подтверждения результата.
