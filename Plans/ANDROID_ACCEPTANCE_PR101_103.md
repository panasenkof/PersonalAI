# PersAI — контрольная Android-приёмка PR #101, #102 и #103

**Историческая матрица именно PR #101–103.** Они давно в main; этот документ не задаёт следующий выпуск/очередь. Актуальные SHA и наблюдения: [UI_U5_ACCEPTANCE.md](UI_U5_ACCEPTANCE.md), [PLAN.md](../PLAN.md).

**Дата чек-листа:** 23.10.2026. **Статус:** НЕ ПРОВЕРЕНО пользователем на физическом телефоне. Этот документ не утверждает, что APK уже опубликован. Пакет охватывает исправление viewport, фирменную иконку и компактный composer. Отложенные performance/нагрев, экран «Защищено» и полное восстановление зашифрованной копии не входят.

## 0. Правильный APK перед началом (обязательно)

1. Открыть [GitHub Releases](https://github.com/panasenkof/PersonalAI/releases) и найти новейший **PersAI Android test** release, выпущенный **после** слияния #103, с коммитом `0d5535c02f110f3d605a45fd8db530b4450d0a4d` или его последующим потомком с теми же изменениями. Совпадение названия/номера релиза **без проверки SHA недостаточно**.
2. Последний найденный при составлении чек-листа [b339-a1](https://github.com/panasenkof/PersonalAI/releases/tag/android-test-b339-a1) — **только #101**, он **не подходит для всех трёх проверок**. Если релиз после #103 отсутствует, **не устанавливать старый для общей приёмки**, отметить «блокер: APK ещё нет».
3. Скачать прикреплённый к release `PersAI-android-test-....apk` (не временный `android-ui-apk` из PR CI), установить **поверх** текущей PersAI, без удаления приложения. Важны прежние package ID `com.paigent.app` и ключ подписи. При ошибке несовпадения подписи/понижении версии **не удалять приложение и данные**; прислать текст ошибки.
4. Зафиксировать точное имя APK, release tag, SHA, модель телефона/версию Android, обычный или увеличенный шрифт; открыть существующий диалог и убедиться, что сохранённая история и заметки остались доступны. Не требуется раскрывать API-ключи или показывать личную память на скриншотах.

## A. PR #102 — значок и стартовый экран (без LLM-запросов)

- [ ] A1. На рабочем столе **и в списке приложений** PersAI — утверждённая насыщенная тёмно-космическая иконка REF-ICON-A (голубое ядро, фиолетово-циановые дуги), не старый светлый логотип, не обрезана и не пикселизована. Проверить круговую/скруглённую маску, если поддерживает launcher.
- [ ] A2. При закрытии и новом открытии приложения видна согласованная заставка на тёмном фоне, без белых углов, растяжения и старого символа.
- [ ] A3. При поддержке Android 13+ и лаунчера включить *Тематические значки* — монохромная версия различима и не выглядит сплошным квадратом. При отсутствии опции: **Н/П**, а не ошибка.
- [ ] A4. Если launcher кеширует старую иконку, перезапустить launcher/телефон и повторить, **не удаляя приложение**. Если не помогло — скриншот (рабочий стол + список приложений).

## B. PR #101 — стабильный диалог (2–3 коротких LLM-запроса)

- [ ] B1. В существующем **длинном** диалоге прокрутить вверх, открыть Gboard касанием поля, набрать/стереть несколько строк. История не исчезает и не меняет положение скачком; ввод всегда над клавиатурой.
- [ ] B2. Набрать 2–3 предложения, нажать **очистку** поля, сразу снова печатать. Курсор остаётся в поле, Gboard не закрывается сам по себе, пустой экран не начинает листаться.
- [ ] B3. Отправить небольшой запрос, например «Объясни в двух предложениях, что такое VPN». Gboard скрывается именно при отправке; вопрос виден, статус возле сферы меняется по реальной стадии, ответ **появляется рядом со своим вопросом**, а по завершении не исчезает/не перескакивает. Сфера остаётся видимой в шапке.
- [ ] B4. Попросить длинный ответ («Составь подробную инструкцию из 12 пунктов…»). Начало ответа остаётся читаемым; приложение не переносит читателя насильно к концу каждого фрагмента. Во время генерации вручную прокрутить вверх — положение чтения сохраняется, автоматическая прокрутка не побеждает жест.
- [ ] B5. После прокрутки вверх нажать **«↓ К последнему»**. Лента возвращается к последнему сообщению; кнопка не перекрывает поле ввода и исчезает при достижении конца.
- [ ] B6. Переключиться из текущего диалога в другой, затем в Память и обратно. Не появляются чужие сообщения, не теряется черновик; работающий LLM-ответ не обрывается из-за смены вкладки. Для проверки фонового ответа дополнительный запрос не обязателен.

## C. PR #103 — компактные действия Home (без лишних LLM-запросов)

- [ ] C1. Под полем ввода **один ряд из пяти значков** слева направо: **Файл, Камера, Голос, Улучшить, Отправить/Стоп**. Ничего не переносится на вторую строку, особенно при открытом Gboard; кнопка улучшения рядом с микрофоном, Send справа.
- [ ] C2. Проверить каждую кнопку: Файл и Камера открывают **импорт в память** (это ещё НЕ вложение в чат); Голос запускает диктовку или понятную ошибку разрешения; Улучшить меняет существующий текст с возможностью вернуть исходный; Отправить работает, во время ответа превращается в Стоп.
- [ ] C3. При длинном удержании значка появляется локальная подсказка рядом с ним и **не закрывает** поле/клавиатуру; у значков остаётся удобная область касания.
- [ ] C4. В Android настройках шрифта увеличить размер примерно до ×1,3–×1,5, снова открыть Home, Gboard и историю. Значки остаются в одном ряду, ввод доступен, строки не обрезаны. При возможности включить TalkBack: имена всех пяти действий озвучиваются. TalkBack без возможности проверить → **Н/П**, не PASS.

## Что сообщить после проверки

Отметить каждый пункт **+** (полностью работает), **−** (дефект), **?** (не успел/не проверял), **Н/П** (нет функции у устройства). Для «−» указать: код B3/C1 и т.п., модель телефона, Android, выпуск APK, что нажали, ожидаемое и фактическое поведение; по возможности приложить короткую запись экрана без личных данных. Один и тот же недостаток не надо описывать трижды.

**Критерии выхода:** нет потери данных и непредвиденного открытия Gboard; стабильные якоря вопроса/ответа, ручное чтение и кнопка вниз; новая иконка/заставка без обрезки; пять доступных действий в один ряд. «CI PASS» — не статус приёмки. P0/P1 устранять отдельным исправлением и автоматическим регрессионным сценарием, P2 вносить в реестр. После этой приёмки двигаться к завершению U1, затем U2–U5.
