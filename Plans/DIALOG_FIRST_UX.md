# PersAI — диалог как основной интерфейс (DIALOG-FIRST)

**Решение владельца 06.11.2026. Статус: обязательный продуктовый и UX-принцип для ВСЕХ новых функций с этого дня.** Очередь только [PLAN.md §2](../PLAN.md#2-что-делаем-дальше--единственная-рабочая-очередь). Массовое преобразование уже существующих экранов — отдельный **отложенный пакет DIALOG-ADMIN на этапе 13** внутри №65/89, не новая №92 и не задача ближайшего этапа 9.

## Продуктовая цель

**В идеале обычному пользователю достаточно одного диалога с PersAI.** Через текст или голос человек узнаёт, ищет, выбирает, создает, правит, организует и управляет своими материалами, а ассистент показывает результат и понятные контекстные действия прямо в сообщении. Технические экраны перестают быть обязательной навигацией для повседневных задач.

Это цель постепенного упрощения, **не инструкция немедленно удалить вкладку «Память», все настройки, системный выбор файла, прямое редактирование, восстановление или резервирование**. Диалог не должен быть единственным способом исправить ошибку, выбрать точный файл, восстановить доступ и проверить последствия. Использовать преимущества диалога там, где он действительно уменьшает число шагов.

## Обязательное правило для нового функционала — действует уже сейчас

1. **Сначала описать естественный запрос.** Для каждой функции задать 2–5 реплик человека (включая неоднозначную и ошибочную), ответ с результатом, продолжение «а теперь…», отмену и поиск исходника. Проверить текст/голос, отсутствие дополнительного экрана, работоспособность без сети для локальных задач.
2. **Диалог — начальная точка.** Пользователь не обязан искать меню ради действия, которое можно однозначно сформулировать и безопасно исполнить в чате. Обычные результаты — карточки, короткая подборка, текст, ссылка на оригинал, компактные действия подтверждения в потоке. Сохранять видимый прогресс, ошибки и возможность повторить/уточнить.
3. **Повторно использовать действия приложения.** Вход из чата маршрутизирует намерение в тот же существующий reader/search, write-service, ACL/CAS/undo, source/provenance и backup, что и непосредственный UI. **Никакого второго агента, writer, отдельного хранилища или самостоятельной реализации операций только для чата.**
4. **Модель предлагает — приложение проверяет.** LLM не получает прямой SQL/file API и не решает по догадке, какую запись изменить. Намерение превращается в проверенную структурированную операцию со stable IDs, revision, scope и разрешениями, повторно проверяемыми непосредственно перед записью. Текст импортированного документа — данные, не указания выполнить команду.
5. **Опасные действия — с наглядным preview.** При совпадениях показать кандидатов и попросить выбрать; при архивации/удалении/слиянии/удалении вложения/пакетных правках показать точные объекты, связь с источниками, число, обратимость и последствия. Никаких скрытых permanent-delete/групповых изменений по одному ответу LLM, обязательное подтверждение необратимого, сохранение Undo/восстановления там, где оно поддерживается. Не выдавать отмену уже отправленного во внешний сервис за реальную.
6. **Физический и доступный резервный путь.** AppLock, секреты, резервное восстановление, права ОС, файловый picker и продвинутые массовые операции могут требовать отдельного экрана. Он должен открываться контекстно из диалога и возвращать результат в него, а не добавлять новую постоянную вкладку. Direct UI сохранять, если он быстрее, безопаснее или доступнее; не принуждать пользователя к многословному чату ради одного простого нажатия.
7. **Не перегружать чат UI.** Избегать панелей из десятков кнопок, повторного «редактировать», дублей меню. Краткие inline действия, «Показать ещё» для длинных результатов, единый стиль Nebula, визуальный размер второстепенных кнопок без нарушения touch target/экранного чтения. Тестировать 320/390/430dp и крупный шрифт.
8. **Сохранность/приватность важнее удобства.** Вся пользовательская память остаётся локальной по выбранной политике; не отправлять private/secret во внешний ИИ. Нельзя стирать оригинал, версию, пользовательские исправления, ссылки, историю и сопутствующие файлы ради удобства диалога. Оговорить недостаточное покрытие поиска и неполный OCR/ASR.

**Выбор новой формы:** в описании каждой функциональной задачи отметить `CHAT-FIRST: YES / PARTIAL / NO (reason)`, сценарий реплика→результат→подтверждение→отмена и перечень оставленных прямых экранов. Принцип не заменяет C0-A/C3-B, CI, Android QA и единую очередь.

## Отложенный пакет DIALOG-ADMIN — №65/89, этап 13

**Статус: DEFERRED.** Не начинать массовую миграцию старого интерфейса в ходе 9A–9C и следующих частей 9–12. Когда настанет очередь, до кода составить **инвентаризацию текущего интерфейса и операций** и полноценный OpenSpec по поддержанным сценариям.

### Обязательный набор сценариев

| Реплика в диалоге | Результат / защита |
| --- | --- |
| «Создай заметку про ремонт велосипеда и прикрепи эти фото» | Подтверждаемый черновик, выбор файлов через ОС, один авторитетный writer; оригиналы сохранены |
| «Добавь этот PDF в заметку про страховку» | Поиск точной заметки, проверка прав, preview и append без потери прежних вложений/текста |
| «Удали лишний PDF из этой заметки» | Выбор точного вложения, preview влияния на источники/извлечения, undo/restore по имеющимся гарантиям |
| «Исправь дату замены свечей» | Выбор события; время события и правки не смешиваются, версия/свидетельства сохраняются |
| «Перенеси последние рецепты в раздел Кухня» | Нумерованный список кандидатов, выбор, предварительная проверка scope/ACL и CAS |
| «Найди повторы этих статей и предложи объединить» | Только предложение, различение совпадающей ссылки и другой версии, сохранение ссылок/ручных пометок |
| «Удали старые заметки о поездке» | Показываются все конкретные кандидаты, выбранный scope, исключения, прогноз последствий; корзина по отдельному подтверждению |
| «Верни удалённое фото» | Контекстный поиск корзины, восстановление именно выбранного объекта, реальный итог |
| «Очисти корзину» | Отдельный защищённый финальный сценарий с числом/типами/последствиями, прямым подтверждением и честной невозможностью Undo |
| «Где хранятся мои файлы и сколько места занимают?» | Честная сводка по измеренным данным, ссылки на предметы и настройки; не фантазировать точные объёмы |

### Перед реализацией проверить

- **До/после в UX:** инвентарь операций в Home/Memory/Note/Import/Share/Trash/Settings, кликов и ошибок; показать, что для обычных задач диалог короче и понятнее. Не добавлять экран «управление через чат» как новую вкладку.
- **В архитектуре:** intent→typed proposal→read/search→preview→confirm→single existing writer→result/receipt/undo. Источник/вложение/ревизия, право доступа, model-output validation, результаты partial failure, resume, revoke, lock/profile switch, idempotency.
- **В тестах:** омонимы и два похожих файла, устаревший результат поиска, lock между подтверждением и записью, отмена, неподтверждённая массовая операция, файл с тем же именем, прерванный импорт, отказ в разрешении ОС, restore/backup и запрет на silent delete. На телефоне — Back, keyboard, TalkBack, голос, 320–430dp.
- **Стоп-критерий:** для каждого удаляемого UI-пути доказать равноценную безопасную альтернативу и отсутствие увеличения числа действий для типичных пользователей. Если не доказано — оставить прямое действие и не делать чистку интерфейса ради концепции.
