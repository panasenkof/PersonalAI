# AIRequest → PersAI Memory Engine: выборочная проверка пригодности
Дата: 26.10.2026. Проверен реальный repo panasenkof/AIRequest, ветка master. Решение владельца: по возможности **ничего не заимствовать**, только доказанную необходимость. Итог: копирования кода и внешних зависимостей **нет**.

## Что просмотрено
- README.md: агент 1С, отдельные graph.sqlite / search.sqlite / field_hints.sqlite, версия поискового индекса, правила, строгая проверка результата, provenance и eval.
- src/aizapros/search_index.py: объекты/рёбра/FTS и графовая сигнатура, кеш с признаками версии входных данных.
- src/aizapros/context_cache.py: маленький кеш, зависящий от снимка исходных данных.
- src/aizapros/eval_provenance.py: hashes входных тестов, кода, конфигурации и источников для сравнимости запусков.
- docs/knowledge-audit-and-eval.md, docs/harness-quality-audit-20261006.md: различение структурной проверки и проверки смыслового результата, запрет сравнивать несовместимые прогоны.

## Оценка переносимости
| Приём AIRequest | Для PersAI | Решение |
| --- | --- | --- |
| SQLite graph + FTS + кеш | Уже используется в PersAI; новый формат отличается предметной семантикой | Не переносить код |
| Индекс зависит от версии/хеша источника/модели | Нужен для multimodal index и race detection; уже записан в плане №66/83 | Сохранить в контракте M0 и тестах; реализовать нативно |
| Разделять «синтаксис принят» и «результат семантически подтверждён» | Прямо применимо к проверке памяти: модель сказала ≠ пользователь подтвердил ≠ есть evidence | Внести в тесты и статус хранения |
| Фиксация provenance набора eval и несовместимости сравнений | Полезно, особенно при смене embedding/LLM и корпуса | Взять принцип; без общего пакета и новых зависимостей |
| Агентный critic/repair цикл для запросов 1С | Не нужен базовой памяти, увеличивает вызовы и риски | Не переносить |
| Специализированная база метаданных 1С и BSL-проверки | Неприменимы | Не переносить |
| Встроенный веб-сервер, Python-обвязка и отдельный runtime | Противоречат mobile-first/без сервера | Не переносить |

## Итог
**Ни одной библиотеки/файла из AIRequest в PersAI не добавлять.** Фактически полезен только независимый инженерный контроль качества: статус «найдено → подтверждено источником → подтверждено пользователем», fingerprint эталонов и отказ от сравнения разных версий моделей/корпусов. Это уже реализуемо собственным TS/SQLite кодом и связано с существующими планами №44–53, 66, 83. Любое будущее заимствование — только отдельное ADR с измеренным преимуществом и отдельным разрешением.
