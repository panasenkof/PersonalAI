# Память PersAI после нового движка — UX/UI этап M4-UX
Дата: 26.10.2026. Статус: M4-UX частично в реализации — U-M5/U-M6 первый typed temporal review screen отдельным PR (CI pending); остальной UX0–UX4 запланирован, НЕ реализован. Основание: Plans/MEMORY_ENGINE_ARCHITECTURE.md и уже утверждённые docs/design/MEMORY_VISUAL_LIBRARY_2026-10-24.md, docs/UI_UX_REDESIGN.md.

## Зачем переделывать интерфейс
Переход от «записи с текстом» к людям, объектам, утверждениям, эпизодам и источникам меняет задачи экрана. Старый редактор заметки недостаточен для навигации по родственникам/машинам, истории смены работы и выбора конфликтующих источников. Но **визуальную библиотеку, стили Nebula, Home-сферу, сетку с картинками и основной чат не ломаем**. Требуется эволюция IA и сценариев, не новая оболочка.

## Навигация: максимум пользы при прежних трёх вкладках

> **Разнообразие содержимого:** [матрица источников](MEMORY_CONTENT_COVERAGE.md) уточняет карточки анализа, обследования, врачебного/кулинарного рецепта, веб-статьи, поста мессенджера и видео-закладки. Без обязательного распознавания материала показывать тип, заголовок, пользовательскую пометку, избранное/«прочитать позже», доступность оригинала и локальную/облачную приватность. Доменный экран (например, временной ряд анализов) расширяет общую библиотеку, не превращается в отдельную основную вкладку.


- «Главная»: остаётся чатом со сферой, единой строкой ввода/микрофоном и файлами. Из ответа «Из памяти» открывает конкретный источник, подтверждённый факт или фрагмент. Не превращать каждый диалог в память автоматически.
- «Память»: прежняя визуальная сетка недавних элементов и разделов + единый поиск; результаты фильтруются по виду «Все / Люди и объекты / Факты / Разговоры и файлы» только когда действительно нужны. По умолчанию один общий список, без перегрузки.
- «Настройки»: безопасность, обработка данных локально/в облаке, управление индексом, полное забывание, резервирование; продвинутые параметры не показывать в обычном редакторе.
- Новых обязательных вкладок не создавать. У всех сущностей стабильный deep link/ID; поиск работает без знания раздела.

## Принципы
1. Сначала изучать лучшие паттерны аналогичных приложений и Apple Human Interface Guidelines как **референс качества**, адаптируя к Android Material 3, TalkBack, IME/Back и режимам системных окон. Не копировать iOS навигацию буквально.
2. Сначала сценарии/дизайн-система/спецификация состояния, затем код и UX-аудит. Прежде чем менять старую библиотеку, проверить соответствие реальным объектам и фактам в тестовом движке.
3. Сущность/факт/эпизод/источник различимы визуально, но без технических слов «node», «edge», «vector» и сырого JSON. Точность, степень уверенности и временной интервал видны там, где влияют на правильность ответа.
4. Статусы: обработка/индексация/ошибка/локальная модель отсутствует; не показывать запись как пустую, когда поиск недоступен. Отсутствие фото-описания не отменяет фото-поиск, если индекс построен.
5. Доступы: обычный предпросмотр закрытых данных внутри локального AppLock допустим, передача в облако — только после политики допуска; при блокировке нет изображения и незашифрованных кешей.
6. Главная навигация из текущего приложения сохраняется; убрать только экраны/поля, ставшие действительно излишними после сквозного анализа.
7. Никаких обязательных вопросов при каждом импорте: обычная заметка может остаться документом; пакет вопросов только если смысловая связь, идентичность или конфликт требуют подтверждения.
8. Экран фото/документов открывает оригинал, а не только OCR; понятный источник происхождения и результат повторной обработки. Обычный редактор не изменяет оригинал.

## Сценарий пакетной очистки
[Детальные UX и политики](MEMORY_HYGIENE.md): «Память → Ревизия» или запрос агента → локальный read-only анализ → объяснимые группы с индивидуальными исключениями → сравнение/проверка затронутых источников и фактов → предварительный расчёт → отдельное подтверждение → отчет/Undo. Не вводить глобальную кнопку «Выбрать всё» в библиотеке; здесь групповое действие управляет **предложенной** частью, а пользователь видит каждый исключённый элемент и применяемый уровень (скрыть/архив/корзина). Затронутые чужие/закрытые материалы, медицинские документы, byte savings и текущие права не угадывать. Для неразрешённого конфликта версий конкретный элемент остаётся нетронутым и переходит в список ошибок.

## Дизайн-этапы и зависимости
- UX0 (после M0, до UI-кода): карта переходов от старых записей к объектам/источникам, IA, 9 пользовательских потоков, референсы и обновление компонентов/токенов; выдать проектные экраны на 320/390/430dp. Согласовать с memory contracts до реализации M4.
- UX1 (после API M1–M3): библиотека, карточка объекта, поиск и открытие конкретного источника. Никаких placeholders функций как готовых.
- UX2: просмотр хронологии и противоречий, batch proposals, связь через людей, объяснимость и privacy.
- UX3: история/корзина/восстановление/забывание, **групповая ревизия с исключениями и preview (U-M10)**, регрессии Share/импорта, реальные медиа; Android QA и accessibility.
- UX4: после M5 — фото/аудио/видео результаты с таймкодами и смешанными типами, тест на похожие, но не идентичные фотографии.

## Проверка
- Проход Лиза: сохранить отношение «сестра», аудио/сообщение «Лиза», найти разговор, различить mention и participant; UI показывает источник и степень уверенности.
- Машина: два события замены свечей по годам; карта/таймлайн не объявляют старое событие устаревшим.
- Работа: «где работал год назад» открывает историческое состояние и его источник, неизвестный день не дорисован.
- Конфликт: два несовместимых значения; видны оба источника, можно оставить нерешённым без потери.
- Одноимённые люди: UI предлагает кандидатов, не сливает автоматически; отказ не предлагается вновь без нового evidence.
- 320dp, 390dp, 430dp, fontScale 1.5, TalkBack, Back/Cancel, клавиатура Gboard, системный Share, сломанный оригинал и экран блокировки.
- 100/1000/10000 объектов, пустая память и 1 сохранённый источник; виртуализация списка и измерение задержки.
- Новая UI-реализация не начинается, пока M1–M3 не дадут стабильные read/write/search API и фикстуры. Дизайн/референсы готовятся заранее и могут корректировать поля API.

**28.10.2026 · U-M5/U-M6 первый вертикальный срез (PR, CI pending):** [экран ручной проверки временных предложений](../openspec/changes/memory-temporal-review-ui/proposal.md): вход из standard-коллекции, старый/новый факт и цитаты, отдельное подтверждение окончания с известной или неизвестной датой, keep both/defer/dismiss, CAS/undo. Не означает готовую общую очередь связей/биографических утверждений, UI timeline/источников, batch editing или full search. QA и исходный функциональный контракт U-M5/U-M6 остаются открытыми.

AppLock сбрасывает обе группы. **Новая основная вкладка, второй статусный журнал или второй поиск не создаются**. Нет автоматической генерации кандидатов от LLM и нет группового принятия — отдельные будущие UX/logic проверки в M4.
