## 1. Цель и базовые принципы
Пользователь должен иметь возможность сказать: «Проанализируй мою память за год, убери ненужное, **но сначала покажи весь список, дай исключить что угодно и оцени последствия**». Запускать вручную из «Память → Ревизия» или по запросу в чате; предложенная периодическая ревизия допускается только после явной настройки. Обычное сохранение заметки не инициирует модальную массовую чистку.

**Возраст ≠ устарелость ≠ неинтересность ≠ отсутствие доказательств ≠ разрешение удалить**:
- Старый чек, медицинский анализ, рецепт врача, договор, старое состояние места работы и замена свечей — ценные исторические записи. Никогда не выбирать для удаления только по возрасту или по тому, что появились более свежие данные.
- Статья на тему ПО может быть историческим источником и ссылкой для последующего поиска, даже если описывает старую версию. «Устаревшая информация» — основание **предложить проверить или архивировать**, не факт ложности или неценности.
- Видео, сохранённое «на потом», но не открывавшееся год, — кандидат на *переоценку интереса*, не доказанный ненужный материал. «Не открывали» зависит от того, видит ли PersAI все открытия, и требует оговорки полноты.
- Однажды недоступная ссылка (timeout/403/429/login/геоблокировка) не равна удалённой странице. Даже 404/410 надо перепроверять с учётом времени и политики запроса. Если у статьи сохранён локальный снимок, он ценен при неработающей ссылке.
- Похожие фотографии, статьи и тексты — **кандидаты на семантический дубль**. Два одинаковых blob-хеша не всегда дублирующие пользовательские контексты; одинаковый URL может содержать разные версии статьи.
- Пользовательское «Сохранить навсегда», pin/keep и явный запрет чистки перекрывают любые эвристики. Важные источники, на которых основаны активные утверждения, не должны удаляться скрыто.

## 2. Варианты реализации и выбор
| Вариант | Обработка | Плюс / риск |
| --- | --- | --- |
| А — локальные детерминированные правила | Точные совпадения хеша/URL со снимком, явно устаревшие **производные** индексы, пользовательские статусы «прочитано/готово», необязательные сроки и группы «давно без подтверждённого использования» | Быстрый, офлайн, объяснимый. Не знает, потерян ли интерес и ценен ли материал |
| **Б — гибрид (рекомендуется)** | Правила → bounded поиск дубликатов/связей/тем/версий → ограниченное локальное LLM-/embedding-объяснение для неоднозначных **разрешённых** кандидатов → групповой dry-run → выбор человека | Экономит время пользователя, защищает связанное знание. Ни confidence, ни скоринг не запускают удаление |
| В — периодический куратор (только после Б) | По явной настройке предлагает дайджест, применяет **только разрешённые** housekeeping-операции (устаревшие rebuildable индексы, безопасный orphan-cache) | Удобен позднее; исходники/факты/медиа не удаляются автономно по «оценке неинтересности» |

Выбор для PersAI — **Б с реализацией А как первым этапом**. В неразблокированном профиле анализ не работает; локальная модель не получает доступ к тайным данным только потому, что она локальная. Облачный ИИ **не получает память для ревизии по умолчанию**, а для health/secret не включать общий фоновый внешний анализ.

## 3. Кандидаты, причины и предложения
| Группа анализа | Проверяемый сигнал | Предлагаемое действие по умолчанию | Особые ограничения |
| --- | --- | --- | --- |
| Списки точных дублей | Тот же binary SHA + размер / канонический URL с **тем же** snapshot revision, общие заметки и источники | Свести **повторное хранение байтов**, сохранить все смысловые ссылки, комментарии, ownership и версии | Экономия bytes только после удаления последней лишней физической копии; перенос ссылок проверять FK/CAS |
| Семантически похожие статьи и посты | Текстовая близость, одно происхождение, совпадающие ключевые разделы, разные авторы/времена | «Возможные повторы» с side-by-side сравнением; архивировать после просмотра | Сходство не означает дубликат, независимый источник и подтверждение не терять |
| Похожие материалы устаревших версий | Явная версия API/ПО, подтверждённая версия документа/обновление с датами | «Оставить новое в активных, старое в архив» | Редко применимо к историческим статьям; не закрывать факт из-за новой публикации |
| Видео и «Прочитать позже» | Длительное пребывание в очереди, отсутствие **известных** открытий, несвязанный backlog | «Интересно ещё?»: архивировать / сохранить / открыть / вернуться позднее | Нет сигнала «неинтересно» без ответа пользователя |
| Проекты/поездки/временные подборки | Подтверждённое завершение эпизода, статус задачи, даты материалов, явное отношение к теме | Архивировать **подборку**; показать связанные источники | «Завершён проект» ≠ «удалить проектную историю» |
| Недоступные URL | Повторная проверка публичной ссылки с явно отличимыми результатами (404/410 vs 403/429/timeout) | «Проверить», «оставить закладку», «архивировать», «удалить URL только с согласием» | Не проверять приватные/токенные ссылки без явного разрешения; локальный snapshot сохранять |
| Ненужные производные данные | Смена версии модели, пересчитанный embedding, старый OCR-cache, временные изображения/незавершённые jobs | Housekeeping без трогания оригиналов, после проверки, что данные rebuildable | Не очищать пользовательские исправления OCR/ASR; учитывать занятый кэш/неполные транзакции |
| Материалы, помеченные самим человеком | Явный статус «не нужно», «прочитано», «решено», истёк срок конкретной пользовательской задачи | Пакетный архив/корзина по предварительной настройке | Не подменять «прочитано» на «не нужно», тем более при нескольких ссылках и источниках |

**Скоринг для *порядка просмотра*, не для автоудаления:** свежесть и давность подтверждённого использования, pinned/marked-important, статусы пользователя, связность с действующими проектами, наличие независимых источников, уникальность evidence, точный hash/semantic similarity, доступность URL, физический объём и уверенность в оценке. Весовые коэффициенты и пороги — проверяемый eval, не произвольные «0.86 вероятности ненужности». Для каждой группы обязательны `reason_codes`, объяснение, ограничения наблюдения и тип рисков. Отсутствие обращений/избранного — слабый сигнал, не критерий удаления.

## 4. Уровни воздействия и политики
1. **Скрыть из активной выдачи** / перевести в «отложенное» (без утраты оригиналов и исторического поиска).
2. **Архивировать** материал или тематическую подборку (оригинал, алиасы, теги, цитаты, истории сохраняются, доступно `include_archived`).
3. **В корзину** с отдельным сроком восстановления и датой будущего удаления, без выдачи обычному поиску. По умолчанию **не очищать корзину физически без явной политики**, даже если срок истёк; можно отдельно включить правило с предупреждением.
4. **Финально уничтожить** как отдельную специализированную операцию с повторным явным подтверждением после dry-run, указанием охвата и доступных backup. Не автопредлагать финальное удаление sensitive/исторической цепочки по возрасту.
5. **Свернуть только производные индексы/cache** с rebuild по требованию — отдельная безопасная housekeeping-операция, не равна удалению источника.

Архив/корзина/физическое удаление **не синонимы** «устарело». `valid_to` исторического факта, состояние просмотра, статус пользовательской закладки и состояние lifecycle её хранения — разные оси. Для медицинских данных и документов с сохранением истории предлагать архив и ручную ревизию, исключить из возрастных bulk-trash кандидатов по умолчанию. «Завершившееся назначение» не равняется «врачебное назначение более не нужно».

## 5. Предварительный dry-run по всему графу, а не отдельным фактам
Планировщик оценивает **группы** (collection, topic, episode, duplicate cluster, date range, source type, read-later), ищет connected components/зависимости:
- Покрытие: сколько источников, source revisions, segments, linked objects, claims/evidence, пользовательских аннотаций, медиа, attachments/parts, search units/vector/FTS, истории/решений, архив/корзина, чатов, в каких коллекциях упоминается.
- Уникальность доказательств: нельзя уничтожить последний оригинал, единственное доказательство принятого факта или ссылку из другой заметки без **явного решения о результате**. Предлагаемые исходы: «оставить» / «архивировать» / «сохранить исходник без индекса» / «отозвать зависимые утверждения» / «перепривязать к подтверждённому альтернативному доказательству». После purging не оставлять claim как будто он всё ещё подтверждён из удалённого источника.
- **Разделять очистку представлений и содержимого**: удаление из одной подборки ≠ физическое удаление общего оригинала; ссылки из других коллекций, чатов и фактов остаются.
- Учёт веса: отдельно «элементов можно скрыть», «байтов освободится сразу», «потенциально после истечения корзины», «только reclaimable caches». После SQLCipher/VACUUM реальное уменьшение файла может быть меньше. Не обещать освобождение размера базы после скрытия/архива.
- Приватность: анализ и отображение зависимостей только в текущем разрешённом профиле; скрытые secret-источники не раскрываются даже через причину кандидата, групповые счётчики или рекомендации внешней LLM.
- **Не удалять доказательства подсказкой модели**. LLM возвращает предложения с ссылками на id/version и объяснение; детерминированный планировщик проверяет допустимость и каскады.

## 6. Экран ревизии (M4-UX)
Вход: память → меню → **«Ревизия памяти»**; команда «Предложи, что можно почистить» открывает тот же read-only dry-run. UI использует существующую дизайн-систему Nebula, не переделывает главную страницу.

**Обзор:** «Кандидаты: 84 материала в 5 группах. Рекомендуется архивировать 43, рассмотреть дубли 12, проверить 29. Безвозвратное удаление: 0. Последняя полная ревизия: дата». Не показывать ложные точные цифры bytes/проверок, которых не было.

**Карточка группы:** краткая причина, возможный эффект, **тип операции, данные о связях и пользе**, например «Видео “на потом”, сохранённые больше года назад · 18. Из них 4 добавлены в проекты, 2 закреплены». Быстрые варианты «Архивировать предложенные», «Сохранить», «Позже», «Открыть 18». Тема имеет раскрывающийся виртуализированный список элементов.

**Каждый материал:** название, обложка, источник/дата, личная пометка, какие записи и факты на нём основаны, обоснование, предложенное действие, управляемый выбор. Действия:
- **Исключить из текущей очистки** (снимает выбор, оригинал и связи не меняются).
- **Всегда сохранять / Закрепить** (отдельный признак pin/never_suggest; отменяемая настройка).
- **Отложить предложение** на заданный срок (причина/решение сохраняются, не повторять на каждом скане).
- **Поменять действие** (например, вместо «В корзину» → «Архивировать»).
- Открыть, сравнить, посмотреть **«Почему предложено?»**, «Какие связи затронет?» и зафиксировать ложное срабатывание.

**Нельзя навязывать глобальное «Выбрать всё»** вопреки установленному UX библиотеки. Для ревизии допустимо действие **«Применить рекомендуемое к этой группе»**, а любой элемент можно сразу исключить перед подтверждением. Массовая операция с необратимым действием требует отдельного выделения/повторного явного подтверждения; не смешивать удаление с архивацией одной кнопкой.

**Экран перед применением:** по выбранным операциям показать список/число затронутых, зависимые факты/коллекции/оригиналы, что будет скрыто/архивировано/перемещено в корзину, что **останется**, прогноз bytes с оговорками, пропущенные защищённые и исключённые, оставшиеся unknown/stale. Кнопка по умолчанию «Архивировать N», «В корзину N» лишь после явного выбора. «Отмена» ничего не меняет.

**Результат:** выполнено/пропущено/конфликт версий/не удалось; Undo-пакет для обратимых операций и «Восстановить» из корзины. Сообщить о backup-ограничениях до физического удаления.

## 7. Детерминированное применение, жизненный цикл и синхронизация
Поскольку план может устареть за время подтверждения, `cleanup_plan` — **read-only снимок решений** с `plan_id`, `created_at`, `rules_version`, `profile_id`, `scope`, `groups`, `candidate_ids`, `reason_codes`, `observed_versions`, `predicted_effects`, `excluded_ids`, `pinned_ids`, `requested_actions`. До исполнения обязательна **повторная проверка** версии каждого target и критических зависимостей, прав, pin, размера. Если изменились — исключить этот кандидат и отправить на пересмотр, а не применить stale plan.

Для группы из сотен элементов: индексировать idempotent `cleanup_operation/batch_id` и `item_results`; группы разбивать на атомарные транзакционные подгруппы с resume после сбоя. Каждая подгруппа сохраняет состояние применения и возможность undo, без «полусохранённых» source_media/claims. Записи перемещаются в корзину согласно одним ACL-правилам; фоновые индексы не оживляют удалённое (version/tombstone gates), и никакой вывод LLM не воскрешает старое содержимое.

После физического purge соблюдать SQLCipher/wal/FTS/vector/обложки/logs/backup-cache lifecycle, FK/ref-count оригиналов, отсутствие «сирот». Полное удаление из сторонних уже экспортированных копий **не гарантируется**; пользователь должен видеть это до подтверждения. SQLite `secure_delete`/checkpoint/VACUUM и использование шифрования оценивать на нативном Android, не обещать побайтовую зачистку флеш-носителя. Для частичной «экономии места» сначала удалять пересоздаваемые cache и дубли blobs, не клиническую историю.

> **Технический шаг №79а, PR на проверке (26.10):** создана аддитивная schema v7 для пользовательских `pinned/never_suggest/skip_until` с CAS и сохранением в шифрованных backup; `MemoryHygieneService.dryRun` показывает затрагиваемые связи, наблюдения, вложения, ревизии и неопределённые зависимости. **Он ничего не архивирует и не удаляет.** Новый API пока без пользовательского экрана и без семантического группировщика; это не выполненная №79б/в/г. Результат CI и нативного Android подтверждать отдельно.

## 8. Поэтапная доставка без второго roadmap
- **M1 / №66/79а:** определить lifecycle, pin/never_suggest/skip_until, статусы пользовательских пометок, versioned source, связи ref-count/ACL, `dryRunImpact`/проверки каскадов. Не включать фоновую AI-чистку и не блокировать основной CRUD.
- **M3 + №79б / 65:** первая локальная детерминированная ревизия: точные дубли, read-later backlog, закончившиеся коллекции, rebuildable obsolete indices. Только предложения и dry-run; никакого автопуржа оригиналов.
- **M4-UX / №79в:** групповой экран, исключения, pin, postpone, групповой preview, архив/корзина, undo, ошибки, TalkBack/320–430dp, существующая библиотека.
- **Позже №79г / M5–M6:** семантическое сопоставление / версии веб-статей / предложение по интересам, независимая синтетическая и Android-оценка, опциональная периодическая ревизия. Полная глубокая ревизия медицинских/secret документов — только по явному запросу локально и без вывода закрытой информации.

## 9. Приёмка и отрицательные сценарии
1. Статья-оригинал доказательство трёх claims → архив сохраняет цитаты; purge требует решения о зависимых доказательствах, в обычном поиске не возникает неснабжённых источником подтверждений.
2. Одна фотография в трёх заметках и двух коллекциях → снятие из одной подборки не освобождает байты и не ломает остальные ссылки.
3. Анализы за 2018/2022, рецепт врача 2021 и два ТО в 2023/2025 → не предлагаются к уничтожению лишь из-за возраста или появления нового значения.
4. 20 старых видео «посмотреть позже», 3 pin, 2 важные для проекта, 5 исключены вручную → итоговая группа правильно исключает все охраняемые и перечисляет выбранные; нажатие «Отмена» оставляет без изменений.
5. Две почти одинаковые статьи с разными уточнениями → не объединяются по embedding; пользователь видит side-by-side и source identity.
6. Ссылка 403/429/time-out, другая 404, третья с офлайн-копией → нет ложного вывода «ссылка мертва» и стирания локального snapshot.
7. Ручное исключение/«не предлагать», рестарт, reindex/model-change → тот же повод не показывается заново без новых существенных входных данных.
8. Кандидат изменён/закреплён между dry-run и Apply; профиль заблокирован → stale CAS, доступ/ACL, pin защищены; пакет выдаёт skipped/conflict, данные целы.
9. Уничтожение source с уникальным evidence, общим media blob и FTS/vector/alias → не остаётся orphan/retrievable personal data; заранее показано влияние на связанные факты.
10. Прерывание пакетной операции и повтор того же batch → только однократный результат на элемент; завершённые операции видны, undo восстанавливает разрешённые.
11. Экспорт backup до purge и restore после → UI не обещает удаление из старых копий, при восстановлении показывает риск повторного появления ранее удалённого.
12. Секретные/медицинские документы не попадают в фоновую облачную ревизию; даже имена связанных закрытых документов не выдаются обычной карточкой; locked profile работает без анализа.
13. 10/100/1000/10000 источников и 100+ кандидатов в одном пакете → bounded/paginated analysis и UI, отсутствие O(N²) глобального сравнения и неконтролируемых LLM затрат.
