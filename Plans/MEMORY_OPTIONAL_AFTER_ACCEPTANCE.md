# PersAI · необязательные улучшения памяти после приёмки базового движка

**Решение владельца от 28.10.2026:** завершить M1–M4, проверить реализацию и провести архитектурную консолидацию; **не уходить в бесконечный улучшайзинг**. Этот документ хранит идеи на будущее, но **не является активной очередью, дополнительными обязательными задачами или критерием завершения памяти**. Единственный исполнительный порядок — [PLAN.md §2](../PLAN.md); статус существующих №1–91 — [ROADMAP_STATUS.md](ROADMAP_STATUS.md). Ссылки ниже указывают на первоначальные требования, а не назначают новые номера.

## Граница текущего завершения (не переносить сюда)

Базовая память считается готовой к объявлению завершённой **только после** сквозного проверенного пути «источник → типизированные утверждения/события/связи → пользовательское подтверждение или отказ → проверяемый единый поиск → чтение оригинала/истории → исправление/undo», сохранения ACL/AppLock/CAS/provenance, M4-UX, применимых C1/Android-CI тестов, честного отчёта о C2 и архитектурной консолидации C3 без параллельных writer/search. Обязательные дефекты, безопасность, потеря данных, migration/restore-совместимость **никогда** не становятся «необязательным улучшением». Отдельный физический C2 не объявлять PASS без устройства.

[96 сценариев](MEMORY_SCENARIO_MATRIX_2026-10-27.md) — **полный реестр поведения и рисков**, его не сокращаем. Для каждого фиксируем `C1_PASS_EXACT_SHA / PARTIAL_C1 / REVIEW_REQUIRED` и отдельно C2; нереализованный *необязательный* сценарий указывается как отложенный, **не как PASS**. Закрытие базового объёма и закрытие всего будущего функционала — разные утверждения. Базовая приёмка не подменяет утверждённые обязательные сквозные кейсы.

## Защита от бесконечного расширения

1. **Без автозапуска:** никакой агент, PR, тест или подсказка не переводит строку из этого списка в активную разработку автоматически. В основной план она возвращается **только по прямому решению владельца** или при доказанном блокирующем дефекте/потере данных (последнее — исправление, не новая функция).
2. **Одна возможность — одна демонстрируемая потребность:** перед стартом проверить, нельзя ли решить её через текущий SQLCipher repository, source/provenance, одну search pipeline, existing preview/actions и UI. Не вводить новую таблицу/очередь/модель без объективной причины.
3. **Ограниченная работа:** сначала фиксируется пользовательский результат и 2–5 проверяемых критериев, максимум один bounded spike. Если метрики не подтверждают пользу — закрыть как отклонённую гипотезу без следующей итерации.
4. **Гейты остаются:** C0-A до и C3-B после каждого PR, тесты применимых сценариев, exact-SHA CI и безопасность. Не объявлять непроверенное устройством протестированным.
5. **Единственный критерий остановки текущего этапа:** M1–M4 закрыты по согласованной базовой приёмке; запланированные C3-упрощения выполнены и доказаны тестами; оставшиеся строки данного файла явно помечены **DEFERRED**. Не расширять definition of done на новые идеи.

**Не делать:** новый граф, отдельный «родственный» поиск, ещё один журнал пользовательских решений, параллельную таблицу источников, глобальную переиндексацию без версии, непрозрачный auto-purge и новый главной экран ради опциональной функции.
