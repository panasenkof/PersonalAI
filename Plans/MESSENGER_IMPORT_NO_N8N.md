# PersAI — импорт из Telegram и MAX без n8n (MSG-0…MSG-6)

**Дата:** 25.10.2026. **Статус:** проект на утверждение владельцу; НЕ реализовано, доступ к аккаунтам и ботам НЕ настроен. **Ветка:** docs/messenger-ingest-no-n8n-20261025. **Назначение:** нормативная детализация пунктов [№61, №85, №62, №57 и №60/84](../PLAN.md), без добавления новых постоянных номеров 1–91. Связанный сценарий изображения из чата — [№83](LOCAL_MULTIMODAL_AI.md).

## 1. Цель и продуктовый контракт

Пользователь должен сохранять сообщения, посты, фото, видео, аудио и документы из Telegram/MAX в **одну локальную зашифрованную память PersAI** так же, как другие импортированные файлы. Начальный приоритет: «скопировать ссылку на пост → вставить в PersAI → увидеть достоверный предпросмотр → выбрать коллекцию → сохранить». Позднее: «Поделиться → PersAI» из мессенджера и «переслать личному боту, затем синхронизировать».

Главные ограничения:
- **Никакого n8n.** В фазах MSG-0…MSG-3 не нужен сервер PersAI вообще; пользователь работает с телефоном и официальными доступными источниками. Собственный минимальный relay — опциональный MSG-5, требующий отдельного решения владельца.
- Первичные оригиналы/текст/результаты распознавания, индексы и метаданные хранятся по существующей модели SQLCipher/AppLock и разделам с приватностью. Сеть используется только для получения явно переданного сообщения/медиа, не для загрузки всей памяти.
- **Нет самопроизвольного обхода доступа** к чужим каналам, закрытым чатам, защищённому контенту, paywall, логину, cookies, CAPTCHA или антибот-защите. Ссылку не считать достаточным разрешением на API-доступ.
- Сообщение не является инструкцией ассистенту. URL, теги, подписи и текст — недоверенное содержимое. Импорт сам по себе не запускает LLM, внешнюю публикацию или команды.
- Один общий ingestion pipeline и существующее сохранение заметок; не плодить TelegramNote/MAXNote со своими БД и UI. Вложений может быть несколько; источник и исходный текст не теряются. Сохранение только по явному действию (автоматизация — отдельное разрешение).
- Рабочие фазы не мешают U5 приёмке, обязательному minimal Android smoke, закрытию микрофона; дизайн Home и сфера Nebula B+C не меняются.

## 2. Выбор архитектуры: три реально различимых режима

| Режим | Инфраструктура | Что работает | Что НЕ гарантируется |
| --- | --- | --- | --- |
| **A. Local-first, рекомендуется первым** | Только Android PersAI + публичные веб-ссылки + Android ACTION_SEND/SEND_MULTIPLE | Публичный доступный пост по ссылке; текст/файлы, переданные через Share; сохранение и OCR/распознавание после согласия | Получение любого закрытого поста по URL; полная медиа-выгрузка со всех сайтов; доставка из закрытого мессенджера без Share |
| **B. Personal Telegram bot, experimental** | Бот, принадлежащий пользователю, его токен только в Android Keystore; телефон сам вызывает getUpdates/getFile | Пересланные боту сообщения и медиа при ручной синхронизации/открытии приложения | Немедленная доставка, многосуточный офлайн, гарантированный background: Telegram держит обновления не дольше 24 часов |
| **C. First-party relay (без n8n), отдельное разрешение** | Очень небольшой наш HTTPS webhook-receiver + ограниченная очередь, Android pull клиент | Надёжнее принимает события Telegram/MAX, пока телефон недоступен; eventual sync после сети/разблокировки | Не является zero-server; webhook уже раскрывает событие нашему серверу до локального шифрования; нельзя обещать 100% доставку без SLA |

**Рекомендация:** утвердить A и подготовку адаптеров в MSG-0…MSG-3. Режим B — опциональный Telegram-only эксперимент после MVP, с честной меткой «синхронизировать вручную; события старше 24 часов могут пропасть». Для MAX не предлагать B как промышленное решение: официальный API прямо ограничивает Long Polling тестами; рабочий MAX-бот начинается с MSG-5 webhook. Режим C отдельно согласовать по хостингу, стоимости, условиям хранения и модели угроз. Одновременный getUpdates и webhook для одного бота не использовать.

## 3. Каналы ввода и UX (без лишних экранов)

### MSG-1. Ссылка
1. Пользователь вставляет URL в общий импорт (Память → «Добавить» → «По ссылке») или использует Android Share текста/URL; PersAI распознаёт источник и обрабатывает его одним маршрутом.
2. Экран показывает **«Получаем публикацию»** с отменой; далее реальный текст, дату/автора при наличии, количество вложений, исходную ссылку и признак «частично». Никаких выдуманных медиа/автора.
3. Пользователь выбирает коллекцию/приватность, при необходимости меняет заголовок и теги, «Сохранить». Автоопределение коллекции по тегу — подсказка, не тихое перемещение секретных записей.
4. Если ссылка ведёт к закрытому контенту, бот-требованию, 403, редиректу на логин или пустому веб-представлению: показать **«По этой ссылке содержимое недоступно — откройте пост и выберите Поделиться»**. Можно создать вручную заметку-ссылку, но не выдавать её за полный импорт.
5. Для Telegram вначале разрешить проверенные публичные канальные URL с легально доступным HTML/встраиваемым представлением; бот API сам по себе не является универсальным read-by-link. Для MAX проверять конкретные публичные URL и публично доступное представление; наличие ID в URL не даёт боту полномочий читать его.
6. Не требовать от пользователя аккаунта Telegram/MAX для **публичных** ссылок, если содержание действительно доступно анонимно.

### MSG-2. «Поделиться → PersAI»
- Использовать уже существующий Android Share intake, не создавать новый роутер: принимать текст с ссылкой, plain text, единичные и множественные content:// URI; поддерживать сообщения с файлом и подписью. Из Telegram/MAX проверить реальные Android Intent MIME/type/clipData; поведение зависит от версии клиента.
- Если источник передал **лишь ссылку**, корректно вести в MSG-1; если передал файл и текст — **сохранить то, что передано**, не перекачивать файл по ссылке без причины.
- Открыть существующий черновик импорта, коллекцию и предпросмотр. Несколько вложений одного Share → одна заметка; повторная отправка не плодит дубли. Для коллекции с ограниченным доступом применять существующую политику.
- Для защиты от потери при закрытом AppLock: URI брать только с реально выданными Android разрешениями; сохранять в защищённое временное хранилище/проверенную локальную очередь **после фактического копирования**, а не полагаться на долгоживущий внешний URI. Если сохранить не удалось — понятное действие «Отправить повторно».
- Никакого чтения чужих notification/accessibility данных и требования полного доступа к аккаунту мессенджера.

### MSG-3. Личный Telegram-бот без сервера
- **Важное следствие:** один пользователь создаёт **собственного** Telegram-бота через BotFather, вводит токен в настройках PersAI; **общий** бот для нескольких телефонов без сервера с единым доступным токеном небезопасен и не входит в B.
- Привязка: приложение вызывает getMe, создаёт/проверяет персональный pairing challenge, показывает ссылку для старта диалога; подтверждает ожидаемый user_id/chat_id только после ответа от этого диалога. Нужен запрет любых иных отправителей; если доступ нескольких пользователей — отдельная спецификация.
- Сообщение боту, пересылка поста и альбом поддерживаются как входящие; форвард-атрибуция хранится **если Telegram её предоставил**, иначе «источник неизвестен». Контент с защитой от пересылки не извлекать обходными путями.
- **Теги:** простой вариант — прислать сообщение боту с #авто; для обычного Forward, где при пересылке нельзя добавить подпись, отправить **ответом на пересланное сообщение** «#авто» или использовать команду /tag в диалоге с ботом. Для альбома/нескольких сообщений связывать ответ с выбранным импортом однозначно, не угадывать по времени.
- **Без тега:** назначать коллекцию «Входящие», не требовать обязательный #сохранить; опциональная команда #сохранить пригодится как явное подтверждение/фильтр.
- В настройках «Интеграции → Telegram»: «Подключён», «Последняя синхронизация», «Синхронизировать», «Пауза», «Отключить», счётчик ожидающих/ошибок, предупреждение о риске потери после 24 часов.
- При foreground/manual sync один consumer getUpdates, сохранение cursor **только после** успешной атомарной записи полезной нагрузки в защищённую локальную очередь. Из очереди затем создаётся заметка; при ошибке payload переводится в retry/dead-letter, cursor не теряет сообщение. Не заявлять exactly-once delivery с момента отправки: есть пределы Telegram и сетевые гонки.
- При получении вложений сначала metadata/file_id; getFile/download по безопасному официальному URL с лимитами размера/типа, потоковой загрузкой и проверкой checksum; большие файлы/недоступный media показывать как неполный импорт. Проверить текущий лимит getFile, не считать, что он всегда позволяет скачать любое присланное видео.
- Бот может получить короткий ответ о статусе **только во время связи телефона с Telegram**. Мгновенный ответ при выключенном телефоне в режиме B не обещать.
- Фоновая periodic WorkManager-проверка допустима только как **best effort** после оценки батареи и ограничений ОС; min interval 15 минут не означает запуск точно раз в 15 минут. Не делать постоянный foreground service ради обычных заметок.

### MSG-4. MAX-бот: адаптер после подтверждения доступа
- Изучить и подтвердить реальную процедуру регистрации бота/модерации MAX для пользователя, права бота, размер медиа/срок действия вложений и формат пересылки. До этого не обещать, что бот можно создать в один клик.
- Официальный GET /updates — только для локального **разработческого spike**; **production MAX-бот** проектировать на webhook по MSG-5. Уведомления для групп/каналов требуют соответствующих прав бота.
- В адаптере унифицировать message_created, attachments, forward/reply provenance, метки источника и MIME. Не пытаться читать произвольные чужие посты по ссылке через GET /messages, если у бота нет доступа.
- MVP MAX: **ссылка + Android Share** без бота. После проверки регистрации и webhook запустить личный поток «переслать боту → получить в PersAI» с тем же Inbox/тегами.

### MSG-5. Минимальный собственный relay, только если владелец утвердит
- Это **не n8n и не сервер PersAI-агента**: один HTTPS endpoint для Telegram/MAX webhook, проверка секретов и allowlisted отправителей, запись события в короткоживущую очередь, token-scoped Android pull/ack; без LLM, SQLCipher, полной пользовательской памяти, индекса или логики категоризации.
- Telegram: setWebhook и secret_token; MAX: POST /subscriptions, валидировать X-Max-Bot-Api-Secret и TLS. Токены ботов — только в защищённом server-side secrets storage; не в APK и не в URL. Работать через документированные API, учитывать обновление базового MAX API хоста.
- Pairing: приложение генерирует ключ устройства и одноразовый код привязки; relay сохраняет только разрешённые sender/chat и технические идентификаторы. API телефона аутентифицируется отдельно от messenger bot token; ротация/отвязка/отзыв устройства обязательны.
- Delivery: webhook → проверка → дедупликация → **атомарная durable enqueue до 2xx** → телефон читает пачку по курсору → локально шифрует/записывает → **ACK после durable store**. При потере сети повтор безопасен; дедуп по provider+bot+chat_id+message_id+(album/item), а для edited событий фиксировать ревизии. Разрешить позднюю доставку и восстановление с checkpoint.
- **Приватность честно:** боты и relay в момент webhook имеют доступ к присланному сообщению. Relay может немедленно шифровать payload на публичный ключ телефона перед записью на диск, но это **не сквозное E2E шифрование от самого Telegram/MAX до телефона**. Не обещать обратного. Ключи обработки только в минимальном доверенном процессе, body не журналировать. Медиа-ссылки часто короткоживущие: проверить срок и скачать в защищённый временный объект с лимитом/TTL до подтверждения, иначе сохранить явный сбой.
- Зафиксировать срок хранения событий и вложений (предложение: не более 72 часов, конфигурируемо и с предупреждением пользователю; решение согласовать), максимальный объём и политику отказа. После ACK физически удалить очередь и временные медиа; отозванные/просроченные — удалить по TTL. Бэкапы relay по умолчанию **не включают сообщения/токены**.
- Хостинг/домен/сертификат, регион обработки данных, цена, доступность, обновления, политика журналов и угрозы — **отдельная архитектурная точка утверждения**, не выбирать конкретного провайдера молча. Проверить требования MAX webhook HTTPS/сертификата/порта.
- Не разрабатывать MSG-5, если A + B покрывают фактическую потребность пользователя; принимать решение по результатам реального использования.

## 4. Общий адаптер и данные (набросок для будущего OpenSpec)

Единый вход adapter.normalize(input) → MessengerImportDraft; он должен возвращать **типизированный результат**, а не произвольный текст с HTML. Общая схема (не требование миграции до проверки существующих таблиц):

| Поле | Значение / правило |
| --- | --- |
| origin_platform / transport | telegram/max/web/share; путь фактического получения обязателен |
| source_url / source_chat_id / source_message_id | При наличии и если доступ разрешён; не синтезировать отсутствующие URL |
| source_author / source_date | Только документированные метаданные, не домысливать |
| raw_text, caption, parsed_tags | Хранить исходный текст и отделить теги от содержимого; не вырезать авторский текст |
| attachments[] | original filename/type/bytes/hash/provenance; группа = одна заметка с отдельными файлами |
| collection_id, sensitivity | Явный или выбранный пользователем раздел; default «Входящие»; право доступа проверять до синхронизации/LLM |
| import_status | link_only / partial / ready / saved / retriable / denied |
| source_fingerprint | Для повтора сообщений, редактирования, URL и альбомов; отдельный режим «сохранить ещё раз» по желанию пользователя |
| last_sync_cursor / received_at / attempts | Техническое состояние в защищённом store; cursor не должен опережать сохранённые updates |

Принципы: idempotent append, no duplicated attachments, атомарное сохранение существующим сервисом заметок, версионирование корректировок, первоначальный пост не заменять поздним содержимым без явного решения. Несколько пересланных сообщений можно импортировать по одному либо явно **«Объединить в одну заметку»**; автоматическое объединение допускается только для надёжно обозначенного album/media_group.

**Связка с памятью и чатом:** импорт из мессенджера создаёт заметку с provenance; фотографии индексируются будущим №83 без обязательной текстовой подписи. Поиск «бросил фото автомобиля в чат и нашёл тот же/похожий в памяти» — отдельный E2E для №83 после готовности настоящих медиа-вложений чата, с различением сходства модели авто и идентичности конкретной машины.

## 5. Матрица источников и ошибок

| Ввод | MVP без сервера | Отрицательный сценарий |
| --- | --- | --- |
| Публичная ссылка на пост Telegram | Доступный текст/медиа и provenance, если реально доступны без авторизации | 403/логин/защищённый/неизвестный URL → «Поделиться», без фальшивого успеха |
| Публичная ссылка MAX | Только подтверждённые доступные страницы; fallback «сохранить ссылку» | API недоступен боту/страница JS-only → не обещать полный пост |
| Приватная ссылка Telegram/MAX | Не извлекается автоматически | Ясное сообщение и переход к Share / пересылке доступного сообщения |
| Share одного фото + подписи | Черновик с оригиналом и текстом | URI отозван/нет разрешения/ошибка копирования → повтор без потери других данных |
| Share альбома | Одна заметка с несколькими файлами | Лишний/недоступный файл → список частичных ошибок |
| Telegram-бот foreground | Пересылка и тег, сохранение при sync | Более 24 ч offline → честно сообщить о возможной потере |
| MAX-бот в production | Только после webhook/relay отдельным этапом | Нет модерации/прав/сертификата → функция недоступна, Share работает |

Ошибки: AUTH_REQUIRED, PRIVATE_OR_PROTECTED, UNSUPPORTED_URL, SOURCE_EXPIRED, HTTP_OR_REDIRECT_BLOCKED, MEDIA_TOO_LARGE, MEDIA_MISSING, CONTENT_PARTIAL, RATE_LIMIT, INTEGRATION_DISCONNECTED, DEVICE_LOCKED, STORAGE_FAILED. Точный код — для диагностики без раскрытия URL с секретами, токенов или содержимого сообщения.

## 6. Безопасность и приватность — обязательные тесты

1. URL allowlist и URL parser против подмены доменов (например userinfo/Unicode), редиректов к localhost/частным сетям, DNS rebinding; только HTTPS, ограничение redirect hops, bytes/timeouts, MIME sniff, запрет нестандартных схем и SSRF. Для сторонних публикаций не отправлять персональные cookie.
2. HTML и форматирование — обезвреживать; никаких выполнения JS, произвольных webview-действий, опасных внешних протоколов. Импортированный текст с «игнорируй правила» не запускает инструменты и не расширяет права LLM.
3. Политики AppLock/SQLCipher/приватности распространяются на drafts, thumbnail, download queue, OCR, provenance и временные файлы. Шифрованное staging, cleanup при отмене и удалении, запрет открытых логов/Crashlytics payload.
4. Только разрешённый telegram user_id/chat_id; лишние update/группы/подмена pairing не попадают в память. Токен через Android Keystore / серверные secrets, rotation/revoke с очисткой cursor. Токен никогда не вставлять в telemetry/screenshot.
5. Разрешения для импорта и права в памяти независимы. Запись из приватного раздела не попадает в облачный RAG автоматически. Отправка исходника в cloud LLM — отдельное пользовательское действие.
6. Проверить медиа «запрещено пересылать», приватный канал, просроченные ссылки, изменения/удаления постов, очень длинный текст/zip bomb/malformed MIME и ограничения платформы.
7. Если relay появится: ретраи webhook, проверка подписи/секрета, replay protection, per-user quotas, доступ к очереди только после pairing, TTL и audit без содержимого. Не хранить содержимое дольше согласованного срока.

## 7. Этапы, зависимости и критерии выхода

| Этап | Приоритет | PR/результат | Gate |
| --- | --- | --- | --- |
| **MSG-0: OpenSpec / инвентаризация** | P1, без ожидания будущего бота | Аудит текущего Import/Share/SQLCipher/URL safety; проверка репрезентативных публичных Telegram/MAX URL на физическом Android, согласованные поля provenance и UX состояния; fixtures | Никаких регрессий существующего импорта, явно указан поддерживаемый набор URL; решение по «создать ссылку» vs «сохранить контент» |
| **MSG-1: link importer** | P1 после MSG-0; часть №85/61 | Два адаптера публичных URL + общий parser; предпросмотр + «частично»/fallback | 3 доступных Telegram поста, до 3 доступных MAX постов (если публичное представление позволяет), 2 приватных, 404/403/redirect, >1 медиа, zero hallucination; Android smoke |
| **MSG-2: Android Share** | P1 после/параллельно MSG-1 | Реальные интенты Telegram/MAX → существующий импорт; заголовок/текст/файлы/album | Реальный телефон: фото, текст, несколько вложений, закрытая заметка, Cancel, Reopen, native UI; не потерять URI при AppLock |

| **MSG-4: MAX API spike** | P2 без обещания доступности бота | Проверка регистрации/permissions/формата событий/медиа, прототип adapter на mock fixtures | Письменный отчёт о доступе и рабочих реальных тестах; публичный импорт и Share не зависят |
| **MSG-5: optional relay webhook** | P2 только после нового явного утверждения | Наш tiny HTTPS-сервис для двух ботов, short-lived queue и pull/ACK, без n8n | Независимый security review, оператор/стоимость/TTL, бот-права/сертификаты, crash/replay/retry/cancel, подтверждение на реальном телефоне; не сливать до утверждения |

**CI:** unit fixtures Telegram/MAX parsing, безопасные URL, дедуп/курсор/ошибки; browser end-to-end public/mock sources; Android minimal smoke как обязательный, расширенный нативный сценарий как целевая регрессия функции. Не использовать реальные личные переписки или токены в публичном CI. На каждую версию — SHA/CI/сборка APK и короткая отдельная приёмка на устройстве.

**Состояние:** все MSG-0…6 запланированы, нет новой функции в рабочем APK. После утверждения начинать только с MSG-0 и MSG-1; бот/relay не включаются автоматически.

## 8. Вопросы на утверждение владельцем (решения предлагаются по умолчанию)

1. **Утвердить A (link + Share) первой очередью?** Предлагается **да**.
2. **Telegram personal bot в режиме ручного sync без сервера включить позже как эксперимент?** Предлагается **да, опционально**; не требовать от пользователя постоянного ручного контроля.
3. **MAX-бот без собственного сервера в production?** Предлагается **нет**: ограничение официального MAX API. MAX link+Share включить в MVP при наличии доступного контента.
4. **Согласие на разработку tiny relay MSG-5?** **Пока нет**; вынести отдельный выбор после результатов безсерверного MVP и реального MAX API spike.
5. **Теги:** необязательные #авто/#рецепты; без тега — «Входящие»; auto-categorization как предложение. Предлагается **да**.
6. **Сохранение:** предпросмотр и явное «Сохранить» по умолчанию; без автоматического массового чтения чужих чатов. Предлагается **да**.
7. **Поддержка приватных постов по ссылке:** не обходить ограничения; Share/пересылка только разрешённого контента. Предлагается **да**.

## 9. Риски и решения

| Риск | Контроль |
| --- | --- |
| Разные форматы сайтов и сломанная разметка публичных постов | Feature-detect + независимые adapters, тестовые примеры; «частично» и fallback |
| Пользователь ждёт мгновенного импорта по боту, а телефон спит | Отдельный статус ручного режима, явное Sync, no guaranteed background; MSG-5 если требуется |
| Потеря Telegram updates за 24 часа | Своевременный sync лишь best effort, дедуп/cursor; без гарантий при длительном offline |
| MAX API не принимает личного разработчика / нет webhook | Подтвердить регистрацию, не блокировать link+Share; отдельный gate MSG-4 |
| Большие/исчезающие медиа, альбомы | Лимиты, фиксация provenance и partial errors, тесты на источники и часы |
| Утечка токена или чужая запись попала в память | BYO token в защищённом store, проверка senders, pairing challenge, no logs, revoke |
| Изменение платформенных ToS/API | Официальные API, документация, feature flags, graceful disable |
| Приватные данные прошли через relay | Документированное ограничение webhook plaintext-in-transit, шифрование при хранении, короткий TTL и отдельное согласие |
