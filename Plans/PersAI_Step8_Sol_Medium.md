## 1. Результат и границы

Пользователь сохраняет статью, PDF или аудиозапись, видит, что именно удалось обработать, находит материал обычным поиском и открывает подтверждающий оригинал. Повторная обработка не теряет его исправления. В чате видно, какие вложения действительно доступны выбранной модели.

Основные номера: №85 — веб-импорт; №60б — обработка оригиналов; №75 — транскрипты; №84 — вложения. №77 затрагивается как контракт доказательств, но не закрывается автоматически целиком.

Не входят: новая память/поисковый движок, глобальный редизайн, сервер, бот Telegram/MAX, импорт закрытых платформ, audio/video embeddings, автоматический подбор моделей, сравнение одной и двух моделей №83.6. MiniLM для текста и EmbeddingGemma 2 для фото сохраняются. Текущий голосовой ввод Google/Whisper не переделывать под транскрипцию файлов. Голосовой PR сверить перед началом реализации; подготовка подплана не означает его приёмку или слияние.

## 2. Общие обязательные решения

1. REUSE/EXTEND: существующие SQLCipher, источник и версия, writer, очередь извлечения, source-reader, searchMemory, ACL/AppLock, backup/restore. Новая таблица или зависимость — только при доказанном пробеле и с описанием миграции/восстановления. Не вводить отдельную очередь для каждого формата.
2. Ссылка, оригинал, машинное извлечение, ручная правка и резюме различаются. Пустой результат обработки не удаляет источник. Ссылка без текста сохраняется и ищется по известным метаданным и пользовательскому комментарию.
3. Сохранить в память, прикрепить к чату и отправить внешней модели — разные действия. Никакого автоматического расширения облачной обработки. Private/secret/«Документы» не отправляются внешней модели; новый путь использует текущую политику доступа.
4. Статус операции и полнота содержимого различаются: успешное завершение задания может дать только частичный текст. UI отображает фактическое покрытие; при неизвестном общем объёме не рисует выдуманный процент.
5. Результат применяется только к тому профилю, источнику и версии, для которых запущен. Lock, удаление, смена профиля, изменение прав/источника инвалидируют поздний callback. Проверка версии и прав выполняется при записи, а не только перед запросом.
6. Повторное нажатие не создаёт вторую одновременно действующую операцию. Повтор импорта того же URL не означает автоматически тот же снимок: комментарии и прежняя версия не перезаписываются молча.
7. Все численные ограничения сверить с текущей реализацией и провайдером. До кодирования записать точные значения: размер входа, время ожидания, число редиректов, страницы/длительность за запуск, размер пакета, параллелизм, отмена. Нового общего лимита памяти не вводить.
8. Успешная запись оригинала и успешное извлечение — разные результаты. Индекс обновляется через существующий механизм после принятия версии; ручная переиндексация после каждого импорта не требуется.

Обозначения ниже — названия рабочих пакетов, а не новые постоянные номера roadmap. По умолчанию каждый пакет — один небольшой PR в main. Если он не помещается в одну проверяемую вертикаль, разделить по пользовательскому сценарию, сохранив главный номер.

### Пакет B — сохранение ссылки и понятные ошибки

Главный номер: №85. Результат: пользователь не теряет ссылку, даже если сайт недоступен.

Действия:
- В существующем предпросмотре показать URL, доступные заголовок/описание, редактируемый комментарий и необязательную коллекцию; использовать текущий маршрут назначения.
- Различить неверный URL, отсутствие сети, timeout, 403/404, необходимость входа, неподдерживаемый тип и превышение лимита.
- Предложить «Сохранить ссылку», «Повторить», «Отмена» в применимых состояниях. Сохранение только после действия пользователя.
- Не исполнять скрипты страницы, не передавать ей ключи приложения; сохранить URL-проверки и ограничения редиректов существующего загрузчика. Исходный и конечный адрес не смешивать.
- Во время загрузки выход/отмена не создаёт скрытую заметку; повторный Share не дублирует незавершённую операцию.

Проверки: успешная ссылка, offline/timeout/403/404, редирект, неправильный тип, double tap, отмена, lock/profile switch. Сохранённая link-only запись находится после перезапуска, но ассистент не говорит, что прочёл её содержимое.

### Пакет C — чистый основной текст веб-страницы

Главный номер: №85. Результат: сохраняется статья или рецепт с полезной структурой вместо меню и рекламы.

Действия:
- Расширить существующий HTML extractor. Сначала рассмотреть уже установленный parser; новую библиотеку обосновать совместимостью с runtime, размером и тестами.
- Сохранять заголовки, абзацы, списки, порядок шагов, количества и единицы. Не использовать LLM-резюме как исходный текст статьи.
- Метаданные автора/даты заполнять только при наличии основания; дата импорта не становится датой публикации.
- Отличать пустую страницу, форму входа и техническую заглушку от успешно полученной статьи. Не пытаться обходить авторизацию и антибот-защиту.
- В предпросмотре показать извлечённый текст и частичность. При неудаче остаётся путь сохранения ссылки из B.
- Принятая версия автоматически участвует в существующем поиске; старая версия/комментарий не теряются при обновлении.

Проверки на локальных HTML fixtures: статья с навигацией, кулинарный рецепт с дробями/единицами, русский текст, список/таблица, неправильная разметка, login page, пустой JS-shell, обрезанный ответ. Проверять сохранение ключевых фактов и удаление шума, а не только длину строки. CI не зависит от живого сайта.

### Пакет D — PDF с текстовым слоем и настоящими страницами

Главный номер: №60б. Результат: PDF находится по фразе, результат открывает соответствующую страницу, если viewer поддерживает это.

Действия:
- Доработать существующий native PDF extractor и source-segment контракт по карте A; не добавлять второй PDF pipeline.
- Сохранять связь сегмента с версией оригинала и реальным номером страницы. Явно согласовать 0/1-based номера между native, JS и viewer.
- Смешанный PDF может иметь доступный текст только на части страниц: показывать обработанные страницы и пробелы покрытия.
- Различить повреждение, пароль, отсутствие текста, неподдерживаемую ОС/возможность и лимит. Не обозначать каждый случай как «пустой PDF».
- При отсутствии page navigation открыть файл и честно показать известную страницу; не изображать выполненный переход.

Проверки: настоящий многостраничный PDF с уникальной фразой на последней странице, смешанный PDF, скан без текста, password/corrupt fixture, ошибка native, отмена. Сквозной тест import → extraction → search → source-reader → viewer locator. Минимальная поддерживаемая конфигурация и современный Android проверяются отдельно.

### Пакет E — OCR сканов и фотографий документов

Главный номер: №60б. Результат: документ без текстового слоя можно распознать доступным разрешённым способом.

Действия:
- Переиспользовать имеющийся OCR и очередь. В смешанном PDF распознавать отсутствующие страницы, не создавать дубли текстового слоя.
- Обрабатывать ограниченными порциями, отдавая приоритет пользовательскому поиску. Показывать готовые страницы и неготовый остаток.
- При отсутствии подходящего локального OCR оставить оригинал и явный статус недоступности; не выполнять скрытый cloud fallback. Если необходим новый runtime — вынести его выбор и совместимость в отдельный ограниченный PR внутри №60б.
- Не угадывать нечитаемые цифры, единицы и страницы. OCR-текст не считать проверенным пользователем; ручная коррекция доступна через существующий редактор.

Проверки: чёткий русский скан, повёрнутый лист, нечитаемый участок, смешанный PDF, отказ после нескольких страниц, restart/lock/cancel, защищённый документ. Для распознавания — эталонный набор и явные допуски; для хранения/покрытия — детерминированные тесты с подставным extractor. Непроверенное качество не объявлять PASS по mock.

### Пакет F — транскрипты аудиофайлов и таймкоды

Главный номер: №75. Результат: запись ищется по произнесённой фразе и открывается в подтверждённом месте.

Действия:
- Использовать назначенный для файлов ASR и существующий транспорт; системное окно Google для микрофона не объявлять API для файлов.
- Сохранить оригинал, модель/provider, версию извлечения, сегменты и покрытие. Если provider не возвращает таймкоды — сохранить текст без точного перехода, не вычислять время по длине текста.
- Для длинной записи определить в A допустимое разбиение: размер сегмента, offset, перекрытие, устранение дублей, retry только неготовых частей. Не обрезать запись молча.
- В UI показать полный/частичный транскрипт; выбор фрагмента запускает реальный seek только при наличии корректного времени.
- Не назначать «сестра/Лиза» по номеру голоса. Диаризация и идентификация человека не входят в этот пакет.
- Видео с доступной аудиодорожкой подключать только через уже поддержанный путь. Новое извлечение дорожки/кодек — отдельная вертикаль, а ссылка на ролик не считается скачанным аудио.

Проверки: короткая русская запись, тишина, неподдерживаемый кодек, сегмент со смещением, ошибка середины записи, timestamps absent/out-of-range, сеть/lock/restart. Проверить search → transcript segment → seek. Платные live-прогоны запускать только по отдельному запросу владельца; mocks не доказывают фактическое качество ASR.

### Пакет G — повторное распознавание без потери ручного текста

Главный номер: №60б; связан с №75. Результат: пользователь может улучшить машинный текст и сохранить собственные исправления.

Действия:
- Добавить «Распознать заново» к существующему просмотру вложения. Применять только поддерживаемую операцию, показывать provider и объём внешней обработки по действующей политике.
- Старый успешный результат остаётся доступным, пока новый не завершён. Ошибка не заменяет его пустотой.
- Если после последнего извлечения пользователь не правил производный текст и версия совпадает — новый результат можно принять существующим атомарным writer.
- Если есть ручные правки — сохранить новый результат как кандидат, показать текущий и новый текст и явные действия «Оставить текущий» / «Применить новый». Не делать автоматический merge произвольных строк. Пользовательский комментарий не изменять ни в одном варианте.
- Принятие проверяет CAS: редактирование, удаление или изменение прав во время обработки предотвращает устаревшую замену. Старый callback после отмены ничего не применяет.
- После принятия обновить только затронутые сегменты/индексы. Старое доказательство не должно незаметно указывать на другое содержание под прежней версией.

Проверки: OCR/ASR success, failure, ручная коррекция до и во время запуска, два запуска, отмена, удаление/смена профиля, устаревшая версия, backup/restore ручной и машинной версий. При изменении схемы — отдельная совместимая миграция и тест старого архива.

### Пакет H — дополнительные форматы и несколько вложений чата

Главный номер: №84. Результат: пользователь заранее понимает, какие файлы будут обработаны в сообщении.

Действия:
- В A определить конечный перечень форматов этого выпуска по реальным возможностям текущих адаптеров; сначала PDF/текстовые документы, затем уже поддержанные аудио. Не заявлять «любой файл» или обещать DOCX/XLSX без parser/transport.
- Переиспользовать текущий picker, attachment-компоненты и model capabilities. MIME/содержимое валидировать, не доверять одному расширению.
- Для каждого вложения показывать готовность, ошибку, удаление и отмену; ошибка одного файла не стирает остальные.
- Если модель не принимает оригинальный формат, разрешённый извлечённый текст используется только по явному и понятному контракту. Отсутствие текста не выдаётся за успешную передачу файла.
- Измерять совокупный бюджет сообщения, а не только каждого файла. При превышении предложить убрать файл/выбрать часть; не отправлять незаметно первые N символов.
- До отправки сообщить о неготовом/неподдерживаемом вложении; отправка остальных — явное действие. Смена модели повторно проверяет совместимость.
- Прикрепление к чату само по себе не сохраняет запись в память. Back/restart/cancel не должны порождать дубли или оставлять чувствительные временные копии сверх действующей политики.

Проверки: смешанный набор, одно повреждённое вложение, совокупный лимит, смена модели, double send, удаление при обработке, повтор после ошибки, отсутствие сети, отсутствие разрешённого транспорта. Проверить реально сформированный запрос адаптера, не только UI карточки.

### Пакет I — итоговая сверка и локальное упрощение

Не новая функция и не повод повторять весь аудит памяти. Проверить фактические изменения B–H: нет второго writer/search/queue, лишних копий оригинала, несогласованных статусов и обхода capabilities/ACL. Удалить доказанно ненужный код только с регрессиями; рискованное упрощение оформить с причиной и точным условием возврата.

Провести четыре сквозных сценария: статья/рецепт; PDF-инструкция; аудиозаметка; несколько файлов в чате. Дополнительно защищённый документ и ручная правка при повторном распознавании. Приёмка телефона — адресная в обычном использовании, без новой обязательной кампании 96 сценариев. Подтверждённый runtime, main, CI, APK и физический Android указать раздельно.

## 4. Порядок и правила для Sol Medium

Последовательность: A → B → C → D → E → F → G → H → I. Общую защиту ручных данных закладывать сразу при подключении каждого extractor; пакет G добавляет пользовательский повтор и выбор версии. Не откладывать предотвращение потери данных до G.

Каждый рабочий сеанс ограничен одним пакетом. Перед изменением кода исполнитель обязан:
1. Обновить состояние main/PR и относящиеся требования.
2. Прочитать найденные в A реальные модули и тесты; не создавать одноимённые альтернативы по памяти.
3. Сформулировать сценарий, ожидаемый и запрещённый результат, список файлов и C0-A.
4. Выполнить минимальную реализацию, затем релевантные unit/integration и обязательные CI проекта на конечном SHA. Для UI читать mobile-ui-ux, UI_GUIDELINES и NEBULA_VISUAL_CONTRACT; проверить Back/IME, крупный шрифт, доступность и ширины 320–430 dp.
5. Сделать C3-B и отдельную PLAN CONFORMANCE сверку фактического diff с общим планом, профильным подпланом и OpenSpec.
6. Обновить только соответствующие статусы/доказательства; записать остаток и следующий пакет. Не присваивать родителю DONE по одному успешному happy path.

При новых архитектурных фактах: не угадывать решение и не менять требования задним числом. Зафиксировать GAP, предложить минимальное совместимое решение; продолжать независимую часть. Не расширять пакет общей перестройкой приложения. Слияние/релиз — по действующему поручению владельца, подготовка плана сама их не разрешает.

## 5. Сквозная матрица обязательных проверок

| Ситуация | Ожидаемое поведение |
|---|---|
| Оригинал сохранён, extractor упал | Оригинал доступен, ошибка понятна, нет ложного «всё обработано» |
| Обработана часть страниц/записи | Указано известное покрытие и пропуски; агент не обобщает его до полного |
| Нажат повтор/два callback | Один принятый результат актуальной версии, без дубля заметки |
| Пользователь исправил текст | Исправление не исчезает без явного выбора |
| Lock/смена профиля/удаление | Нет записи или выдачи результата в неверный scope |
| Старый результат поиска | Читатель проверяет версию и доступ, не цитирует изменившийся текст как прежний |
| Нет page/time locator | Открывается оригинал без выдуманного точного перехода |
| Восстановление архива | Сохранились оригиналы, ручной текст, версии и локаторы; индексы восстанавливаемы |
| Неподдерживаемый файл чата | До отправки понятна причина; нет ложного «модель прочитала файл» |
| Нет доступа к облаку/запрещённый scope | Нет скрытой внешней отправки или подмены провайдера |

Для каждого применимого сценария фиксировать PASS/FAIL/NOT RUN и точный SHA. Проверки на fixtures отделять от настоящего parser/native/provider и от физического устройства. Полную 96-case матрицу не переписывать; выбрать и обновить только реально затронутые строки нескольких предметных областей.

## 6. Критерий завершения шага 8

Завершены объявленные сценарии импорта, извлечения, чтения источника, повторной обработки и вложений; поддерживаемые форматы, Android/provider-ограничения и лимиты указаны явно. Неподдерживаемое имеет полезный fallback, но fallback не выдаётся за реализацию требуемого OCR/ASR. Если обязательный способ ещё отсутствует, соответствующий пакет остаётся PARTIAL с точным остатком. Нельзя закрыть шаг только потому, что все ошибки красиво показаны.

Нет потери ручного текста, оригиналов, связей с источником и нарушения доступа. Required CI пройден на точном SHA; результат проверен в main после разрешённого слияния. APK и телефон отмечены фактически, без фиктивного PASS. После этого следующий шаг основного плана — 9: организация памяти и согласованный импорт Telegram/MAX.

### Визуальная система

Стиль — существующий Nebula B+C. Использовать mobile/src/design/nebula/tokens.ts, не создавать параллельную палитру. Проверенные текущие токены: canvas #070D20, surface #14213D, surfaceElevated #1D2E51, text #F6F8FF, textSecondary #ABBAD8, accent #7051DB. В Home сохранить отдельную утверждённую home-палитру и существующие компоненты: не перекрашивать чат под общий canvas. Для светлой темы использовать light tokens.

- Отступ от края 16 dp; промежутки внутри группы 8/12 dp, между смысловыми блоками 24 dp. Карточка radius 20, поле 16, нижняя панель 26; соответствующие существующие компоненты приоритетнее новых копий.
- Основной текст 16/24, вторичный 13/20, подзаголовок 18/26. Важный статус/ошибку не уменьшать до caption 11. Заголовок материала до двух строк; длинное имя файла с сохранением расширения, полное имя доступно в деталях.
- Одна залитая акцентная кнопка на экран. Вторичная — спокойная outlined/text в рамках kit; отмена не выглядит ещё одной яркой основной кнопкой. Высота основного действия минимум 48 dp, для закреплённого footer целевая 52–56 dp при наличии соответствующего варианта компонента. На крупном шрифте — minHeight, не жёсткая высота.
- Иконки одного существующего набора и толщины, 20–24 dp внутри hit area 48 dp. Никаких эмодзи вместо интерфейсных пиктограмм, новых корон или разноцветных плашек на каждый формат.
- Космический фон остаётся за непрозрачной читаемой поверхностью; не делать прозрачные текстовые поля поверх звёзд. Свечение используется сдержанно, не обводит каждую карточку. Новые сферы и анимации в импорте не нужны.
- Состояния не меняют геометрию шапки/кнопки; место под прогресс зарезервировано. Не добавлять таймерные имитации процентов или пульсацию всей карточки. Системное Reduce Motion поддерживается существующим механизмом.

### U1. Вход и выбор назначения

Три главные вкладки остаются прежними. Из «Память → Добавить» назначение уже известно; повторно спрашивать «Чат или память?» не нужно. Из composer «+» назначение — черновик чата. При внешнем Android Share показать один короткий выбор «В чат» / «В память»; затем соответствующий предпросмотр. Добавление к существующей заметке доступно из её действий и через существующий маршрут Share, если он реализован; не создавать второй picker заметок.

Панель выбора источника содержит компактные строки с иконкой и текстом, а не сетку крупных декоративных плиток. Доступны только реализованные способы. Закрыть первую панель перед системным picker или следующей поверхностью. Отмена picker возвращает прежний черновик и положение прокрутки.

### U2. Предпросмотр импорта в память

Полноэкранный маршрут «Сохранить в память». Сверху Back и заголовок; затем в таком порядке:
1. Компактная карточка источника: обложка/иконка, название, домен либо MIME/размер, фактический статус.
2. Краткое превью полученного текста, до шести строк, «Читать полностью» открывает существующий viewer и возвращает в тот же черновик. Если текста нет — понятная причина вместо пустого блока.
3. Поле «Моя заметка» с подсказкой «Что важно сохранить?»; необязательное, не перезаписывается загрузкой метаданных.
4. Строка назначения «Раздел: Входящие» с возможностью смены. У существующей заметки её название и раздел; теги необязательны, не требуют прохождения отдельного экрана.
5. Свёрнутые «Обработка» только если у пользователя есть реальный выбор. Внутри способ, provider и ограничения; не показывать внутренние job ID/CAS/версии схем.
6. Закреплённая нижняя область с единственным CTA «Сохранить в память» либо «Добавить в заметку»; при link-only — «Сохранить ссылку». Под CTA не прятать обязательную информацию о внешней отправке.

Не открывать клавиатуру автоматически при внешнем Share. При ручном вводе URL фокус нужен. Footer следует за IME, содержимое прокручивается отдельно, последнее поле и кнопка доступны. Back сначала закрывает IME; при следующем Back несохранённые ручные правки требуют выбора «Продолжить редактирование» / «Не сохранять». Без изменений выход немедленный.

До Save импорт — черновик. После подтверждённого сохранения вернуть пользователя к месту входа, показать краткое «Сохранено» с «Открыть». Если обработка продолжается, сообщение «Файл сохранён. Распознаём текст», а не «Готово». Новая запись появляется без сброса текущих фильтров и скачка списка. При ошибке записи экран остаётся с введёнными данными.

### U3. Длительная обработка и отмена

После Save работа принадлежит сохранённому материалу: закрытие viewer/смена вкладки не равно отмене. Статус и «Остановить» размещены в карточке вложения; не держать пользователя за модальным спиннером. До Save кнопка «Отмена» отменяет черновик. После Save «Остановить распознавание» сохраняет оригинал и принятые ранее результаты, прекращает оставшуюся обработку. При системном AppLock действуют ограничения защиты, а не обещание работы в закрытой базе.

Пример известного прогресса: «Обработано 4 из 12 страниц». Неизвестного: «Распознаём аудио». Частичного: «Текст получен для 4 из 12 страниц» + «Продолжить», только если возобновление реализовано; иначе «Повторить распознавание» с явным объёмом. Пакет файлов показывает собственный статус каждого элемента и итог «Готово 2 из 3»; ошибка одного не окрашивает весь экран в красный.

### U4. Чтение статьи и PDF

Статья: заголовок, домен/дата при наличии, затем читаемый текст. Авторские данные отделены от блока «Моя заметка». «Открыть сайт» рядом с источником, второстепенное; редкие действия через ⋮. Нет искусственного титульного экрана с огромной обложкой.

PDF: в рамках существующего viewer две локальные вкладки «Документ» и «Текст», не новые глобальные разделы. Оригинал сохраняет цвета и масштабируется pinch; номер страницы доступен рядом с навигацией. Текст показывает понятные границы страниц и метку частичного распознавания. Переход из поиска открывает вкладку, соответствующую доказательству, и реальную страницу; Back возвращает к тем же результатам/позиции. Нет подсветки произвольного прямоугольника, если extractor не вернул координаты.

Для OCR: «Распознанный текст» и «Исправить»; неполнота указана текстом, не только цветом. Ошибки OCR не маскировать визуально уверенным «проверено». Редактирование открывает полноэкранное поле с «Сохранить изменения», исходник остаётся доступен.

### U5. Аудио и транскрипт

Шапка: название, длительность/дата при наличии, ⋮. Под ней компактный плеер с Play/Pause, scrubber и текущим/общим временем. Далее транскрипт как обычные абзацы; таймкод — отдельная спокойная кнопка слева/над абзацем. На узком экране таймкод переносится над текстом.

Тап по таймкоду переходит к фрагменту; обычный текст остаётся выделяемым для копирования. Во время воспроизведения можно мягко выделять текущий сегмент, если есть точная разметка. Ручная прокрутка отключает следование за воспроизведением; появляется «К текущему фрагменту». Не прыгать к началу при обновлении статуса или play/pause.

Если timestamps отсутствуют: текст остаётся, кнопки точного перехода нет, краткая подпись «Текст без точных таймкодов». Плеер не закрывает последнюю строку, а экран не превращается в набор bubble-карточек для каждой реплики. Полнотекстовый поиск — в существующих действиях viewer; не создавать отдельную систему поиска аудио.

### U6. Повторное распознавание и конфликт правок

«Распознать заново» — в ⋮ вложения, с доступной текстовой меткой; long press не единственный путь. При прежних ручных правках до старта коротко сообщить: «Ваши исправления сохранятся. Новый текст можно будет сравнить». Не спрашивать заново одни и те же разрешения внутри разрешённого scope.

После результата при конфликте открыть экран «Новый вариант текста». На телефоне использовать переключение «Мой текст» / «Новый результат», а не две узкие колонки. Оба текста полные и читаемые; изменения можно выделить только при корректном diff. Наверху пояснить, что именно заменяется. Внизу одна основная «Применить новый», вторичная «Оставить мой текст». Back ничего не применяет. Если версия изменилась, показать «Текст уже изменён. Откройте актуальную версию» вместо перезаписи.

Отмена/ошибка не уничтожает текущий текст. Комментарий пользователя к материалу не является объектом замены. Если гарантированный Undo отсутствует, не рисовать его; история и возможность возврата должны соответствовать реализованному контракту.

### U7. Вложения чата

Существующая строка вложений находится над composer. Фото — миниатюра; документ/аудио — компактная карточка с иконкой, коротким именем, размером и статусом. Для длинного набора видим первые два элемента и «Ещё N»; раскрытие показывает весь список с удалением каждого файла. Не растягивать ленту вложений на большую часть переписки. Точное расположение согласовать с текущим AttachmentChip, не вводить конкурирующую галерею.

Удаление — видимый крестик с 48 dp зоной, озвучиваемый «Убрать [имя] из сообщения»; это не удаление оригинала из памяти. Тап по телу открывает preview, не отправляет файл. При неготовом вложении Send объясняет проблему в контексте: «1 файл ещё обрабатывается»; доступны «Дождаться» и явное «Отправить без него» с перечислением исключаемого. Неподдерживаемый файл можно убрать/заменить, но нельзя молча проигнорировать.

Предупреждение о доступном только тексте: «Будет отправлен извлечённый текст PDF» рядом с вложением. После отправки история отражает фактически отправленные материалы. Отмена/повтор не дублирует уже отправленное сообщение. Статус шага 8 не меняет текущее решение по голосу: Google открывает системное окно, кнопка улучшения только для Whisper; название модели в шапку не возвращать.

### Визуальная приёмка, которую Sol не заменяет зелёным TypeScript

До UI-кода конкретного пакета сверить текущий экран и библиотеку компонентов; эта спецификация не утверждает, что названные компоновки уже реализованы. Для нового составного экрана подготовить эталон в существующем языке Nebula, затем сравнить с реализацией. Обязательные состояния эталонов: preview-ready, link-only error, processing/partial, PDF text/original, audio transcript, retry conflict, mixed chat attachments. Это состояния одного решения, не три новых художественных концепции.
