# PersAI: аудит поисковых полей (08.11.2026)

Единый контур: SQLCipher memory_entities/memory_observations/memory_attachments, memory_search_fts, memory_index_terms, memory_aliases, memory_chunks и локальный векторный/фотоиндекс. Второй индекс, база, фоновый агент или классификатор не создаются.

## Матрица полей и точек заполнения

| Поле | Исходный путь | Автообогащение и гарантия |
|---|---|---|
| Заголовок | Ручной, подтверждённый draft из чата, имя исходного файла | LLM предлагает только альтернативный titleHint для поиска; исходный заголовок не переписывает |
| Основной текст | Пользователь, Android Share/Telegram/MAX, подтверждённый ответ ИИ | Остаётся исходным текстом, не дополняется догадками модели |
| OCR/ASR/PDF | Уже существующие извлечения и сегменты | Доступный прочитанный текст передаётся обработчику; непрочитанный файл не выдаётся за прочитанный |
| Теги | payload.tags, UI импорта #441 | Фоновая LLM генерирует до пяти тегов, совмещает с авторскими и пересчитывает свои; пользователь может полностью запретить автоизменение тегов |
| Тема, описание, альтернативное название | Ранее отдельные поля для заметок не заполнялись | model_search.topic, summary, titleHint с origin=model:auto. В поиске — только FTS terms, не исходные цитируемые chunks |
| Синонимы/формы слова | memory_index_terms model:auto/user | Прежний обработчик расширен темами, тегами, датами и местами без второй системы |
| Люди и имена | Названия, aliases, исходный текст, подтверждённые отношения | LLM предлагает search.people; relation link только к одному однозначному доступному существующему person ID; не угадывать родство и новые личности |
| Даты и места | Авторские payload.date/city/location и verified source metadata | model_search.dates/places — отдельные поисковые подсказки. Не изменять valid_from, GPS, source_publication_date, author |
| Вид записи kind | UI карточки / подтверждённый draft | Не менять в фоне: неправильный person/event изменит семантику и права |
| Раздел | User UI, import LLM #441, подтверждаемый move | Не перемещать без подтверждения. Иерархия — отдельный открытый PR #439 |
| Источник, URL, вложения, receipt | Канонический importer, provenance, SHA/dedup | LLM не создаёт и не подтверждает источник или версию поста; filename входит в FTS |
| Фото | Локальный photo embeddings и OCR | Без реально сохранённого описания/OCR не угадывать предметы снимка и не отправлять оригинал на внешнюю модель |
| Наблюдения/события | MemoryRepository.createObservation и reviseObservation | Разрешённые текстовые события участвуют в LLM подсказках; их изменения делают прежние model terms устаревшими |
| История разговоров | Сохранённый SQLCipher conversation snapshot | Её topic/section ведутся LLM через действующий set_conversation_context; это не note entity, новый индекс не вводится |

## Момент обработки

На сохранении заметки, импорте, подтверждённом draft и запуске приложения используется существующий scheduleIndexTerms -> enrichPending -> applyIndexEnrichment. При добавлении вложений и событий — повторное расписание. Старые стандартные записи с отсутствующим model_search.schema получают постепенный backfill через тот же источник model:auto.

Только active ordinary (standard/inherit) записи и доступные обычные разделы; Documents, personal/secret/unclassified, архив и корзина никогда не передаются внешнему провайдеру. Явное «Сохранить без ИИ» записывает index_enrichment_opt_out и исключает запись также из дальнейшей фоновой отправки. AppLock/отмена и изменения recordVersion/ACL отменяют коммит.

В одной SQLCipher транзакции сохраняются модельные tags и model_search с пометкой происхождения, CAS-версия и revision, старые model terms/links заменяются, FTS и векторы актуализируются. Авторские теги сохраняются; если пользователь редактировал теги, auto-tag override становится истинным.

Поисковые подсказки — не доказательства автора, даты, источника, родства или содержания нераспознанного оригинала. Нельзя показывать model_search.summary как прочитанный исходник.
