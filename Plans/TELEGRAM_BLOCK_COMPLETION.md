## TG-1 — `telegram/auth-robustness`

**Цель:** вход понятен и из любого состояния есть выход (T1, T2, T3, T9, T10, T15, T19).

**Файлы:** `mobile/modules/persai-tdlib/android/src/main/java/expo/modules/persaitdlib/PersaiTelegramTdlibModule.kt`, `mobile/src/telegram/account.ts`, `settings.ts`, `TelegramAccountCard.tsx`, `TelegramAutoSync.tsx`, `mobile/src/telegram/account-errors.ts` (уже существует), тесты в `mobile/src/telegram/__tests__/`.

**Шаги — нативный модуль:**

1. **Уже сделано в #477 — не повторять.** Коды ошибок уже различаются (`tdlib_flood_wait_<секунды>`, `tdlib_flood_limited`, `tdlib_phone_invalid`, `tdlib_code_invalid`, `tdlib_password_invalid`, `tdlib_api_invalid`). Текст ниже оставлен как справка: если для шагов 2–5 нужен новый код ошибки, добавляй его в существующую функцию разбора в модуле, а не создавай вторую. Исходный вариант: в `sendRequest` вместо единственного `tdlib_operation_rejected` выбрасывай код из закрытого списка. Добавь функцию:
   ```kotlin
   private fun safeErrorCode(reply: JSONObject): String {
     val code = reply.optInt("code", 0)
     val message = reply.optString("message", "")
     val wait = Regex("(?:FLOOD_WAIT_|retry after )(\\d{1,6})").find(message)?.groupValues?.get(1)?.toIntOrNull()
     return when {
       wait != null || code == 429 -> "tdlib_flood_wait:" + (wait ?: 60).coerceIn(1, 86400)
       message.contains("PHONE_NUMBER_INVALID") -> "tdlib_phone_invalid"
       message.contains("PHONE_NUMBER_BANNED") -> "tdlib_phone_banned"
       message.contains("PHONE_CODE_INVALID") || message.contains("PHONE_CODE_EMPTY") -> "tdlib_code_invalid"
       message.contains("PHONE_CODE_EXPIRED") -> "tdlib_code_expired"
       message.contains("PASSWORD_HASH_INVALID") -> "tdlib_password_invalid"
       message.contains("EMAIL") && message.contains("INVALID") -> "tdlib_email_invalid"
       message.contains("API_ID_INVALID") || message.contains("API_ID_PUBLISHED_FLOOD") -> "tdlib_app_credentials_invalid"
       else -> "tdlib_operation_rejected"
     }
   }
   ```
   Исходный текст ошибки TDLib в исключение, события и журнал не передавать. Точные тексты ошибок сверить с документацией TDLib; неизвестное остаётся `tdlib_operation_rejected`.
2. Добавь метод `cancelAuthorization`. Разрешён в состояниях `authorizationStateWaitPhoneNumber`, `…WaitCode`, `…WaitPassword`, `…WaitEmailAddress`, `…WaitEmailCode`, `…WaitRegistration`, `…WaitOtherDeviceConfirmation`. 3. Восстановление после ошибки запуска. В `initialize`, в ветке `if (clientId != 0)`: если `authState == "tdlib_runtime_error"`, то отправь `close` (через `sendNoReply`), дождись завершения потока приёма (`worker?.join(5000)`), и если после ожидания `clientId == 0`, продолжай создание нового клиента как при первом запуске; иначе брось `tdlib_restarting_after_close`. 5. `application_version`: принимай версию пятым параметром `initialize(profile, id, hash, key, appVersion)`; в JS передавай версию из `expo-constants` (`Constants.expoConfig?.version`, запасное значение `"0"`), ограничь 32 символами и шаблоном `^[0-9A-Za-z.\-]{1,32}$`.

**Шаги:**

1. Замени одиночный запрос истории циклом:
   ```
   collected = пустой список; from = cursor; попытки = 0
   пока collected.size < limit и попытки < 5:
       history = sendRequest(запрос как сейчас, но from_message_id = from, limit = limit - collected.size)
   ```
