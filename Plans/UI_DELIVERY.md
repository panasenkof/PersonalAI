# PersAI: критерии завершения интерфейса

26.10.2026 · ред. 75. Очередь — только [PLAN.md](../PLAN.md#2-что-делаем-дальше--единственная-рабочая-очередь). Основные экраны и PR #101–128 в main; это не означает новой физической приёмки. [История](UI_DELIVERY_HISTORY_2026-10-26.md) сохраняет прежние видео, PR, результаты и этапы.

**Решение владельца:** отдельный ручной U5 sign-off не блокирует функции и публикацию PR. Владелец пользуется приложением и присылает ошибки. Автотесты/CI выполняет разработчик; новый Android результат не выводится из старого PASS. U5 — [матрица наблюдений](UI_U5_ACCEPTANCE.md), остаётся OPEN без фактической проверки, а работа продолжается.

## 1. Состояние пакетов и конкретные остатки

| Пакет | Состояние кода | Что проверять/дорабатывать |
| --- | --- | --- |
| U0: Home/viewport/клавиатура/скролл | Исправления в main | Регрессии Send/Stop/Clear, чтение вверх и «К последнему», поздний stream и IME; новая видеозапись — отдельное воспроизведение |
| U1: оболочка и чат | B+C/иконка/история/компактный ввод и базовые вложения в main | Доступность, длинные сообщения, текущие форматы/провайдеры; полная Figma не условие работы |
| U2: Память и редактор | Библиотека/карточки, голос/LLM-правка, контекстные действия и режим выбора в main | ⋮ отдельно от выбора; Отмена/Back/последняя галочка; нет «Выбрать все»; ошибки/CAS/несохранённые изменения, голос/AppLock |
| U3: импорт и просмотр | Группы файлов, encrypted originals, #125 append, #128 Share chooser в main | MIME/лимиты/Cancel/partial errors, transient URI, новый HTML/PDF/ASR по функциональным пакетам; не повторять многовложенность |
| U4: настройки | Основные группы и формы переработаны | Два подключения, выбор медиа/голоса, сохранение, маскировка ключей, ошибки/выход без сохранения |

Не открывать новый глобальный редизайн ради каждого остатка. Новая функция получает короткую спецификацию состояний и использует существующую систему. Конкретные источники: [аудит по устройству 25.10](../docs/design/UX_REVIEW_FROM_DEVICE_2026-10-25.md), [память/импорт](../docs/design/MEMORY_SELECTION_IMPORT_2026-10-25.md), [follow-up памяти](../docs/design/MEMORY_AUDIT_FOLLOWUP_2026-10-25.md).

## 2. Непрерывный визуальный контракт

- Сохранять утверждённые REF-ICON-A/REF-ORB-B, Nebula B+C, прозрачную согласованную подложку, состояния и текущую художественную форму. [Визуальный контракт](../docs/design/NEBULA_VISUAL_CONTRACT.md), [reference hashes](../docs/design/references/README.md). Не запускать выбор шести новых иконок после утверждения.
- Три вкладки: Главная/Память/Настройки; не раздувать главный экран каждым будущим инструментом. В списках приоритет содержимому и действиям; цвет/анимация не единственный сигнал статуса.
- 320–430 dp, длинный русский текст, font scaling, Gboard, жесты/трёхкнопочная навигация, Back, safe areas, TalkBack/контраст и реальные touch targets. Примерная web-ширина не равна доказанному Android поведению.
- Данные/ключи/SQLCipher/AppLock и `com.persai.app` сохраняются. Пакет оформления не меняет разрешения/LLM транспорт/схему без отдельной функциональной причины.
- «В чат», «Отправить модели», «Сохранить в память» и «Добавить к заметке» различимы. Внешний Share предлагает назначение; внутренняя скрепка идёт прямо в чат.

## 3. Аудит дублей внутри изменяемого сценария

Перед изменением найти точки входа и общий обработчик, состояния/настройки и конкурирующие пути. Похожие кнопки могут иметь разные полезные цели; общий компонент не является лишней функцией. Удалять лишь необоснованный дубль, сохраняя доступность нужного действия и данные.

В спецификации пакета краткая таблица: действие → точки входа → каноническое состояние/обработчик → решение → тест. Проверять две формы одной настройки, двойной save/LLM-запрос, двойные модальные окна, наследование черновика при Back. Отмена меню не равна отмене выбора; незавершённый draft не исчезает из-за аналитики/индексации.

Новые temporal/relational предложения используют один компактный список/карточку с preview/confirm/reject/defer/undo, а не новую вкладку и N модальных окон. Сохранение источника не блокируется анализом. Дизайн этих новых сценариев уточняется в функциональном PR по [плану памяти](MEMORY_RELIABILITY.md).

## 4. Выход из одного пакета

1. Описать конкретный дефект/новый сценарий, состояния и успешный результат; изучить релевантные референсы при изменении взаимодействия. Существующий утверждённый стиль достаточен, лимит Figma не блокер.
2. Внести законченное изменение; на гонки/lifecycle поведенческий тест, а не только поиск строк в исходнике. Проверять отмену/ошибку и прежний соседний путь.
3. Запустить проверки, применимые к изменению: typecheck/Jest, browser для UI, минимальный required native smoke. Не расширять весь Maestro suite на каждом PR; целевой сценарий добавлять по мере доработки функции.
4. Указать PR, конечный SHA, реальные CI/artifact URLs и native/device результат. APK проверяется по своему SHA; новый коммит требует применимых повторных проверок, не наследует старое зелёное состояние.
5. P0/P1 исправлять по воспроизведению, P2 фиксировать с конкретным следующим пакетом. Не требовать от владельца повторить весь чек-лист для независимой работы; не чистить его данные, не требовать сейчас ручного restore.
6. Обновить строку [реестра](ROADMAP_STATUS.md) и активный PLAN; история отдельно. Нет неопределённого этапа «ещё полировать всё».

## 5. Производительность и исследование моделей

[ANDROID_PERFORMANCE.md](ANDROID_PERFORMANCE.md) — поздняя автоматизация измерений. Наблюдаемое зависание/утечка исправляется сейчас; минимальный замер нового native runtime для №83/59 нужен при его внедрении и не ждёт общего стенда. FPS, температура батареи и энергия — разные величины; browser/эмулятор их не доказывают.

Критерии состояния U5: проверенные основные пути, нет нерешённых воспроизводимых P0/P1, оставшиеся P2 имеют план, фактические APK/устройство известны. До проверки статус OPEN, без остановки разрешённых функциональных PR. Слияние PR — только по отдельному поручению владельца, это не ручной UX-gate.
