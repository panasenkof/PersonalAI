# Android release / JNI class guard and crash reports (15 Nov 2026)

## Scope and architecture
Source: the Android R8/JNI postmortem supplied by the owner. PersAI uses
ExecuTorch (on-device Whisper), Tesseract4Android, SQLCipher/React Native,
and an optional vision engine and TDLib. It **does not bundle ONNX Runtime**
today; no ONNX rule is necessary. The release project is generated by Expo.

C0-A / C3-B: REUSE. Expo build-properties extraProguardRules is the **single**
writer of native keep rules from mobile/scripts/persai-jni-keep.pro for all
prebuilds. The release preparation step validates these rules, it does not
rewrite them. Existing DiagnosticLogsScreen is the only diagnostic UI.
Android ApplicationExitInfo is system-owned exit history, not another app
database or diagnostic log store. No background upload, user tracking, new
permission, storage migration or changes to SQLCipher/ACL.

## Gates
1. Unit: node --test mobile/scripts/prepare-android-release.test.cjs
2. Unit: python3 -m unittest mobile/scripts/test_check_apk_jni.py
3. CI: Expo prebuild -> verify keep rules -> assembleRelease -> inspect exact
   APK DEX class definitions and verify pinned Java/JNI classes. Both PR
   native CI and signed publication use check-apk-jni.py.
4. Required rules: ExecuTorch Java API, Tesseract Java JNI, app-owned PDF and
   crash-report modules, optional vision packages. TDLib retains its
   dedicated consumer-rules.pro. ONNX check is conditional if the native
   runtime is introduced.
5. Native .so string scan is **advisory** and may have both false positives
   and false negatives. A green static check does not prove native inference.
   Compare exact APK sizes and check actual model loading on device.
6. R8 enablement is not changed by this PR. The build keeps its existing
   optimization setting. A separately verified minified APK is required to
   claim complete R8 runtime acceptance.

## Android device acceptance (not yet executed)
- Install release PersAI over the existing app, keep backup and signing ID.
- Open Settings -> Diagnostics, verify the Android crashes section and the
  distinction between chat JSONL and system crashes.
- Use a real on-device Whisper inference and PDF OCR; check Google ASR,
  photo search and local embedding model on real device if installed.
- Reproduce a controlled **non-production** native crash in a disposable
  test build, restart, and confirm ApplicationExitInfo metadata appears.
  Never induce a crash against valuable user data.
- Tap Share only when intentionally sending a report. Check the receiver,
  verify no automatic uploads and that cache report is removed after share.
- Android 12+ native tombstones are protobuf binary, exported in Base64.
  Android may purge traces from its global buffer: report metadata is still
  useful, and an unavailable trace must not be described as decoded text.
- Verify Android 11 fallback (no binary tombstone guarantee), empty history,
  unavailable native bridge, repeated refresh and device privacy controls.
