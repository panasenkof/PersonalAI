# Автоматические проверки интерфейса PersAI

## Расширенные Maestro-регрессии U2/U3/U4 — необязательный набор (23.10.2026)

По решению владельца проекта в PR #111 **обязательный эмуляторный CI запускает только `minimal.yaml`**: настоящий PIN, ввод черновика, переключение вкладок и возврат. Дополнительные `memory-note.yaml`, `settings.yaml`, `import-url.yaml`, `import-photo.yaml` **сохранены в репозитории**, но пока запускаются отдельно через `mobile/scripts/android-native-flows.sh` на уже запущенном тестовом эмуляторе и установленном QA APK. Они не входят в required gate и не должны выдаваться за успешно прошедшие.

Новые нативные потоки нестабильны: в CI #40010027592 тест заметки упал на повторной прокрутке/закрытии клавиатуры. Проверка сценария исправлена, но полный набор пока не подтверждён; не блокировать им поставку остальных UI-исправлений. Их включение в required CI — только отдельным решением после надёжного выполнения и проверки артефактов. Быстрые статические тесты `maestro-flows.test.cjs` сверяют контракт селекторов, не заменяя нативное выполнение. Сфера, безопасность и SQLCipher не изменяются.

## Короткий обязательный CI smoke (23.10.2026)

Обязательный нативный тест теперь `mobile/.maestro/flows/minimal.yaml`: настоящий PIN, ввод черновика, вкладки Память/Настройки и возвращение к черновику. Тяжёлый сквозной сценарий `smoke.yaml` сохранён отдельно для последующей доработки, **не запускается в обязательном CI**, и не выдаётся за пройденный. Нативная сборка, SQLCipher, TypeScript и Jest остаются обязательными. Добавлять проверки новых функций как изолированные тесты рядом с функцией; расширенный Maestro включать только после подтверждённой стабильности, не подменяя этим базовую проверку.


## Что выполняется

На PR и push main общий **CI required** требует два результата для изменений приложения:

- Быстрый JS job: TypeScript, Jest, release guards, Expo compatibility, SkSL и браузерные
  сценарии реальных экранов на 320/390/768px. Нативные API в браузере подменены адаптерами.
- Native job: standalone release APK x86_64 с SQLCipher/ExecuTorch → Android 35
  AOSP **default** без Google Pixel Launcher (профиль Pixel 2, RAM 2048M) →
  Maestro CLI 2.0.10. APK содержит JS bundle, Metro и облачный Maestro не нужны.

Минимальный обязательный smoke: настоящий PIN → ввод черновика → переходы по вкладкам → сохранение черновика. Расширенный сценарий сохранён в `.maestro/flows/smoke.yaml` как необязательный до стабилизации.
Используются существующие accessibility labels. Тестовые данные латиницей обходят ограничения
ввода Unicode в Android automation; русские надписи проверяются селекторами.

На Android 35 AOSP поле системного PIN имеет resource-id `com.android.systemui:id/lockPassword` (подтверждено `window.xml` CI #384). Maestro проверяет настоящий PIN, а регрессионный тест сверяет оба селектора с этим идентификатором. Ошибки селектора исправляются коммитом, а не автоматическим повтором.\n\n**Без настоящих ключей LLM, запросов к провайдерам и обхода AppLock.** PIN 2468 относится только
к чистому одноразовому эмулятору. Нативные разрешения выдаются стандартным launchApp Maestro;
сценарии отказа в доступе к камере/микрофону в этот smoke не входят.

## Диагностика и запуск

В GitHub Actions открыть CI → `native / native-sqlcipher`. Артефакты:
`android-ui-evidence-<SHA>` (JUnit, скриншоты, logcat, UI hierarchy),
`android-ui-apk-<SHA>` (эмуляторный APK с временной подписью, не для установки поверх APK телефона),
`browser-ui-<SHA>` (браузерные снимки). Retention: evidence 7 дней, APK 3 дня.
При ошибке открывать первый упавший шаг и каталог `attempt-1/`. Если экран и UI hierarchy
показывают ANR системного Launcher/System UI либо эмулятор не дошёл до запуска smoke-скрипта,
CI создаёт **новый AVD** и делает ровно один повтор (каталог `attempt-2/`). Оба прогона
сохраняют независимые screenshots, hierarchy, logcat и JUnit; успешным считается только
полностью прошедший настоящий smoke. Если smoke-скрипт уже начат, но приложение/тест упал без доказанного системного ANR
(включая случаи без JUnit), **повтора нет**, PR остаётся красным.
Тест классификации `classify-emulator-failure.test.cjs` входит в обязательный быстрый CI.
Нельзя «лечить» ANR выключением проверки PIN/AppLock.

Локально нужны JDK 17, Android SDK/KVM, чистый Android 35 x86_64 AOSP (target `default`)
AVD и Maestro 2.0.10.
Сборка повторяет `.github/workflows/mobile-native-sqlcipher.yml`, включая переменные ABI,
`PIA_ANDROID_PACKAGE=com.paigent.app`, prebuild и временную подпись. После сборки из корня:

```sh
bash mobile/scripts/android-ui-smoke.sh
```

Скрипт **только для одноразового эмулятора**: устанавливает APK, задаёт PIN, очищает данные
приложения через Maestro. На физическом телефоне выполнение запрещено проверкой `ro.kernel.qemu`.
Для повторного локального прогона создать чистый AVD (старый PIN уже установлен).

## Быстрый CI без потери обязательных проверок

- Известные документационные изменения: только roadmap/source-artwork integrity и тест классификации.
- Любые изменения mobile, workflow, бинарных референсов и неизвестных путей: полный набор.
- При отсутствии baseline выполняется полный набор; отмена/ошибка обязательного job не считается успехом.
  Единичный retry применяется **только к Android infrastructure failure**, не к упавшим
  тестам функций приложения; повторная сборка APK не выполняется.
- Общий executorch.jar поставляется upstream только в ARM64-архиве: installer скачивает его,
  затем x86_64 runtime; компилируется только x86_64. Архивы кешируются, upstream проверяет SHA-256.
- npm и Gradle cache; PR читает Gradle cache, main может обновить. Один ABI, один эмулятор,
  один native build вместо прежнего отдельного PR workflow. ARM64 проверяется подписанной сборкой выпуска.
- Headless Chromium без лишнего полного браузера; системные зависимости устанавливаются только
  при ошибке загрузки библиотек в пробном запуске (в первом CI apt занял более 6 минут).
- JS и native идут параллельно; отдельного дублирующего Expo Android export нет.
- Новые коммиты отменяют устаревшие прогоны. Установка release APK пользователю остаётся отдельной процедурой.

`CI required` готов для branch protection, но обязательность слияния надо включить в настройках
репозитория (на момент реализации main не защищён). Красный CI сам по себе не запрещает GitHub merge.

## Границы приёмки

Зелёный smoke не доказывает художественное качество, все размеры экранов, Gboard конкретного телефона,
TalkBack, камеру/микрофон, полный LLM/network сценарий или отсутствие всех дефектов. Это не screenshot-diff:
скриншоты — доказательства для разбора. Расширять сценарии при каждом новом поведении UI, не добавляя
хрупких координатных кликов. Визуальная приёмка владельца остаётся отдельной.
Производительность/нагрев отложены в [Plans/ANDROID_PERFORMANCE.md](../Plans/ANDROID_PERFORMANCE.md).
