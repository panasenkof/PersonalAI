# Локальный пилот PIA Agent

Начните с веб-версии на вашем компьютере. Для Windows нужны Python 3 и запущенный Docker Desktop с Docker Compose. Команды выполняются в PowerShell из корня репозитория. Пилот не включает публикацию в магазины или открытие сервиса в интернете.

## Первый запуск

```powershell
python scripts/configure-local-pilot.py
docker compose up -d --build --wait
curl.exe --fail http://localhost:8000/ready
```

Скрипт создаёт `.env` со случайными ключами приложения, БД и резервных копий, не выводит их и отказывается менять существующий `.env`. Если установка уже есть, сохраните прежние ключи и пароль БД; проверьте `PUBLIC_LAUNCH=false`, `REQUIRE_VERIFIED_EMAIL=false`. Не запускайте генератор для замены ключей работающей установки. `.env` исключён из Git; сохраните его отдельно для восстановления.

Откройте http://localhost:8000/app/start.html, перейдите в приложение, зарегистрируйтесь. В настройках задайте OpenAI-совместимый сервер, ключ и модель, затем нажмите «Проверить модель и поиск». Для общей модели всех пилотных аккаунтов оператор может заполнить в `.env` `DEFAULT_LLM_BASE_URL`, `DEFAULT_LLM_API_KEY`, `DEFAULT_LLM_MODEL`, `DEFAULT_EMBEDDING_MODEL` и `LLM_ALLOWED_BASE_URLS`, затем повторить `docker compose up -d --wait`. Адрес модели должен быть доступен из контейнера; `localhost` внутри него означает сам контейнер. Установите бюджет у провайдера перед передачей общего ключа через сервер.

SMTP можно подключить позже. Пока он не настроен, подтверждение email и самостоятельное восстановление пароля не проверены; участникам заранее сообщите это ограничение. Экспорт, удаление аккаунта и смена известного пароля доступны. Для восстановления забытого пароля нужен действующий SMTP, а не ручная правка БД.

Порт веба по умолчанию доступен только на вашем компьютере. Не меняйте его на общедоступный адрес ради приглашения людей. Первую приёмку можно провести на этом же компьютере с отдельными аккаунтами участников. Для удалённой группы потребуется отдельно настроенный защищённый доступ и рабочая почта.

## Проверка телефона

Сначала откройте инструменты разработчика браузера и проверьте веб на узком экране. Физический телефон не сможет подключиться к `localhost` вашего компьютера. Для проверки нативного клиента разработчиком нужен доступный телефону сервер и development build Expo SDK 54; инструкции конфигурации и сборок — в [LAUNCH_RUNBOOK.md](LAUNCH_RUNBOOK.md). Expo Go не считайте установленным продуктом. Установку PWA, камеру, фон и системное меню экспорта проверяйте на устройстве через HTTPS.

## Приёмка с двумя участниками

1. Каждый регистрируется и отправляет первое сообщение без подсказок. История второго аккаунта недоступна первому.
2. Участник прикрепляет файл, получает ответ, отменяет генерацию и повторно открывает чат после перезапуска сервиса.
3. Проверяет настройки модели, смену пароля, экспорт ZIP и отсутствие ключей/паролей в нём.
4. На отдельном тестовом аккаунте проверяет удаление после остановки заданий: старый вход и файлы становятся недоступны.
5. Оператор фиксирует проблемы и делает копию перед обновлением. Зашифрованная копия и отдельный журнал удалений описаны в [LAUNCH_RUNBOOK.md](LAUNCH_RUNBOOK.md); Linux-скрипт `deploy/backup.sh` выполняйте из WSL с доступом к Docker. Не удаляйте volumes: `docker compose down -v` удалит данные.

Остановить сервис без удаления данных: `docker compose stop`. Возобновить: `docker compose up -d --wait`. Данные сохраняются в Docker volumes; `.env` содержит необходимые для их чтения ключи. Перед обновлением сохраните копию и проверьте восстановление в отдельной установке.


## Закрытая регистрация и ngrok

Генератор нового `.env` выключает регистрацию (`REGISTRATION_ENABLED=false`). Перед созданием первого аккаунта укажите `REGISTRATION_ENABLED=true` и `REGISTRATION_ALLOWED_EMAILS=ваш@email.ru` (при необходимости добавьте адреса участников через запятую). После создания аккаунтов можно снова выключить регистрацию: вход существующих пользователей сохраняется. `PUBLIC_LAUNCH=false` управляет проверками готовности выпуска, а не доступом из интернета.

Для ngrok используйте отдельный вариант прокси:

```powershell
docker compose -f docker-compose.yml -f deploy/compose.ngrok.yml up -d --wait
ngrok http http://127.0.0.1:8000
```

Добавьте HTTPS-адрес туннеля в `PUBLIC_BASE_URL` и `CORS_ORIGINS`, затем повторите команду Compose. Во всех последующих командах для этой установки используйте оба файла Compose. Вариант сохраняет `X-Forwarded-For`, добавляет адрес локального ngrok и выбирает второй адрес справа: добавленный самим ngrok реальный адрес клиента. Значения, присланные клиентом слева, игнорируются. Основание: [официальное описание заголовков ngrok](https://ngrok.com/docs/gateway/endpoints/http).

Этот вариант рассчитан строго на цепочку «клиент → ngrok → локальный nginx → API». Порт 8000 должен оставаться привязанным к `127.0.0.1`; не включайте профиль `public` одновременно и не публикуйте API напрямую. Для обычного nginx используйте основной Compose и один доверенный переход. При изменении цепочки прокси пересмотрите `TRUSTED_PROXY_HOPS`.

Перед приглашением участников проверьте с двух внешних устройств вход, stream/Stop, PDF, изоляцию аккаунтов, SMTP и восстановление копии. Автоматические тесты не заменяют эту приёмку. Встроенная зашифрованная копия ограничена 1 GiB исходных данных: для больших установок используйте отдельную процедуру резервирования PostgreSQL и файлов с шифрованием и проверкой восстановления.


## Ограничения запросов модели

В `.env` доступны `LLM_MAX_OUTPUT_TOKENS=4096`, `MAX_ACTIVE_JOBS_PER_USER=4` и `LLM_REQUESTS_PER_DAY=200`. Это максимум токенов каждого ответа модели, число одновременно принятых/исполняемых заданий пользователя и общая суточная квота принятых запросов через API, каналы, MCP и проверку модели. Квота хранится в БД и сбрасывается в полночь UTC; ошибка после принятия или отмена не возвращает расходованный запрос. Для активных заданий и суточной квоты значение 0 отключает ограничение.

После изменения `.env` пересоздайте сервисы командой Compose из раздела запуска; при обновлении должна примениться миграция `j0f5c1d3e004`. Ответ 429 с `active_jobs_limit` означает, что нужно дождаться завершения или отменить задание; `daily_request_limit` — дождаться времени `Retry-After` или изменить квоту оператором. Эти настройки не являются денежным бюджетом: итерации агента, embeddings и STT могут увеличивать стоимость одного запроса. Сохраните отдельный бюджет и оповещения у провайдера.

При временной ошибке refresh мобильная сессия сохраняется, поэтому после восстановления сети можно повторить запрос. Отказ refresh с 401/403 потребует нового входа.
