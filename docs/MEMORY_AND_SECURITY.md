# Память, шифрование и резервные копии

Вся память PersAI — записи, наблюдения, связи, история правок, полнотекстовый индекс и диалоги — хранится в одной базе SQLCipher на телефоне. Своего сервера у приложения нет; к провайдеру модели уходят только фрагменты из разделов с уровнем доступа «обычный» и только в момент запроса.

## Шифрование

- Используется `expo-sqlite` с плагином `useSQLCipher: true`. В Expo Go это не работает: нужна собственная нативная сборка (APK из CI, `expo prebuild` или EAS).
- Перед любой записью приложение проверяет `PRAGMA cipher_version` и не открывает обычную незашифрованную SQLite. Запасного режима без шифрования нет, в том числе для разработки.
- Ключ — 256 бит из `expo-crypto`, хранится в `expo-secure-store` с `WHEN_UNLOCKED_THIS_DEVICE_ONLY`. Ключ никуда не передаётся и не входит в резервные копии.
- Индекс FTS5, журнал WAL и история правок находятся внутри зашифрованной базы.
- Ключ не привязан к биометрии на уровне отдельных чтений: биометрия защищает вход в приложение, а не каждый запрос к базе. Это контроль доступа приложения поверх защищённого хранилища ОС, а не аппаратная проверка на каждый запрос.

## Вход в приложение

`AppLock` разблокирует приложение один раз при запуске и после пяти минут в фоне. Подходит любая блокировка экрана телефона: биометрия, PIN-код, пароль или графический ключ. На телефоне без блокировки экрана приложение не открывается и просит её включить. Переходы между вкладками, системный выбор файла и меню «Поделиться» не требуют повторного входа; содержимое закрывается заставкой, пока приложение не на переднем плане. Без авторизованной сессии слой хранения отклоняет любые операции, в том числе через уже открытое соединение.

## Профиль

На телефоне один профиль, он выбирается один раз при первом запуске новой версии:

- новая установка или прежний режим «на телефоне» — профиль `guest`, база `pia-personal-memory-v1.db`;
- прежний вход в серверный аккаунт — идентификатор этого аккаунта, чтобы сохранились записи, сделанные под ним. Идентификатор берётся из сохранённого токена только как подсказка, где лежит база.

После выбора профиль записывается в `pia.profile.v1`, а старые серверные токены и адрес сервера удаляются. Если на телефоне были обе базы, используется та, с которой человек работал последней; вторая остаётся на устройстве нетронутой.

## Обновление без потери данных

- Старые ключи v2, защищённые биометрией, читаются на экране входа — это чтение и есть единственная биометрическая проверка — и переносятся в хранилище v3. Сам ключ SQLCipher не меняется.
- Незащищённый ключ самой первой гостевой версии переносится без копирования открытых данных.
- Если файл базы непустой, а ключа нет, данные не перезаписываются: приложение сообщает о блокировке. Не удаляйте установленную базу, чтобы обойти эту ошибку.
- Схема базы версионируется (`PRAGMA user_version`, сейчас 5); обновление схемы проходит в транзакции и откатывается при ошибке.

## Резервная копия и восстановление

- Копия создаётся через `ATTACH DATABASE ? AS pia_export KEY ?` и `sqlcipher_export`: получается новая, отдельно зашифрованная база с записями, индексом, связями, историей правок и диалогами. Открытый JSON или незашифрованный файл не создаются.
- Для копии генерируется отдельный код восстановления — 64 шестнадцатеричных символа. Его нужно хранить отдельно от файла.
- Файл сохраняется через системное меню «Поделиться»; временная копия удаляется из кэша, в том числе при ошибке.
- Восстановление возможно только в пустой профиль. Формат, таблицы и версия схемы проверяются до копирования; все таблицы вставляются в одной транзакции с проверкой внешних ключей. При ошибке изменения откатываются, существующие данные не перезаписываются.
- Потеря и телефона, и кода восстановления означает необратимую потерю данных. Копии создаются вручную, автоматического резервирования нет.

## Транзакции SQLCipher

`withExclusiveTransactionAsync()` в `expo-sqlite` (выяснено на SDK 54, поведение сохраняется) открывает новое соединение, а `PRAGMA key` разблокирует только исходное. Поэтому PersAI выполняет `BEGIN IMMEDIATE` / `COMMIT` / `ROLLBACK` на одном разблокированном соединении с последовательной очередью транзакций. Закрытие базы ждёт завершения активных записей.

## Что не доказывают автоматические тесты

Jest и браузерные проверки имитируют SQLCipher, биометрию и системные окна. Шифрование во время работы, экспорт и восстановление, неверный код и повреждённый файл нужно проверить на реальном телефоне по [DEVICE_QA.md](DEVICE_QA.md).
