# Готовность PIA Agent к первым пользователям

Проверка 1 октября 2026. Это технический отчёт по коду и план выпуска, а не утверждение о готовности опубликованного сервиса. PersonalAI — имя репозитория, PIA Agent — отображаемое имя продукта.

## Результат проверки

До этой доработки мобильная конфигурация не содержала иконки, adaptive icon и splash screen. Веб имел только тёмную тему и постоянную панель 240 px без мобильной навигации. Вход показывал часть серверных ошибок без перевода; не было инструкции установки, подсказок первого чата, PWA-манифеста, веб-вложений и интерфейса смены пароля.

Теперь добавлены:

- Оригинальный векторный знак PIA: буква P в форме диалога, небольшой акцент ИИ. Растровая иконка 1024×1024 без прозрачности для основного значка, отдельный прозрачный adaptive foreground, splash, favicon, Apple touch icon, PWA 192/512. Знак помещается в центральную безопасную область adaptive/maskable иконок. Исходник `brand/icon.svg`; экспорт `scripts/generate-brand.cjs` с sharp.
- Светлая и тёмная веб-темы, переключаемый список чатов на телефоне, динамическая высота экрана, safe area, видимый фокус клавиатуры, ограничения движения, диалоги с удержанием фокуса.
- Подсказки первого чата и примеры, которые заполняют черновик, а не отправляются без выбора пользователя.
- Веб-загрузка документа/фото через существующий защищённый API. Повторная отправка после отказа API сохраняет черновик и вложение без дублирования пользовательского сообщения. В процессе загрузки отправка заблокирована.
- Установка веб-приложения: манифест, предложение установки в поддерживающем браузере, инструкция Safari. Service worker кэширует только публичную страницу отсутствия соединения. Данные аккаунта, API и скрипты приложения не кэшируются им.
- Мобильный вход со скроллом при клавиатуре, показом пароля, текстовой клавиатурой для резервных кодов 2FA, проверкой адреса сервера и объяснением localhost. При повреждённой сохранённой сессии приложение не зависает на загрузке.
- Мобильные кнопки вложений и отправки не меньше 44×44, нижний safe area, запрос камеры в момент использования, повтор загрузки чатов и первый явный CTA.
- Смена известного пароля в обеих версиях; новые токены сохраняются, старые устройства отзываются сервером. Неверный текущий пароль/код не завершает имеющуюся сессию клиента автоматически.
- EAS-профили preview/production и отказ release-конфигурации без HTTPS-адреса и собственных идентификаторов приложения. Это шаблоны сборки, а не готовые APK/IPA.
- Пользовательская справка `/app/help.html`: начало работы, установка, провайдер модели, данные, 2FA, ошибки, обращение за помощью.

## Что препятствует широкому самостоятельному запуску

| Приоритет | Пробел | Критерий завершения |
|---|---|---|
| P0 | Нет подтверждённого рабочего публичного сервера и домена | HTTPS, миграции, worker/Redis/Postgres, реальные модель и эмбеддинги, лимиты, `/ready`, внешний мониторинг; первый чат нового пользователя даёт ответ |
| P0 | Старый Expo SDK 51 / React Native 0.74 | Последовательная миграция SDK и зависимостей, expo-doctor, сборки Android/iOS под действующие требования, проверка на устройствах. Expo рекомендует минимум SDK 54 для актуальной совместимости Xcode 26; SDK 51 не считать готовым к App Store |
| P0 | Нет проверенных подписанных мобильных сборок | Owned package/bundle ID, EAS project ID и аккаунты магазинов, подпись, Android APK для пилота/AAB для магазина, iOS TestFlight; запуск вне Expo Go |
| P0 | Нет восстановления забытого пароля и подтверждения email | SMTP/провайдер, одноразовые ограниченные по времени токены, защита перебора и повторного использования, одинаковый ответ для существующего/несуществующего email, UX обеих версий |
| P0 | Нет самостоятельного экспорта и удаления аккаунта со всеми файлами | Защищённые серверные операции, повторная аутентификация, согласованные правила хранения/резервных копий, UI обеих версий, проверка изоляции пользователей и удаления данных |
| P0 | Не определены правила работы с пользовательскими данными и канал поддержки | Владелец сервиса, контакты, список обработчиков/провайдеров, сроки хранения, удаление, условия использования и опубликованная политика. Справка объясняет текущую обработку, но не заменяет политику оператора |
| P0 | Резервное копирование не проверено восстановлением | Автоматическое копирование БД, blob-хранилища, ключей отдельно; успешное восстановление тестовой установки и документированные RPO/RTO |
| P1 | Новый пользователь должен разбираться в LLM-конфигурации | Владелец заранее настраивает рабочую модель или мастер подключения с проверкой доступности, понятными расходами и состояниями настройки |
| P1 | Нет подтверждённого контроля качества на устройствах | Android + iPhone + планшет, крупный шрифт, TalkBack/VoiceOver, экранная клавиатура, safe area, смена сети, уход приложения в фон, длительная генерация |
| P1 | Поддержка и эксплуатация требуют ручной диагностики | Версия в интерфейсе, контакт поддержки, безопасный диагностический отчёт без секретов, политика обновлений, наблюдение ошибок, ограничение затрат провайдера |
| P1 | Напоминания не приходят в нативные push | Либо явно описать доставку через Telegram, либо реализовать push-токены, отзыв и пользовательские разрешения. Не обещать push в текущем приложении |
| P2 | Нет простой публичной страницы предложения продукта | Реальные скриншоты, 2–3 подтверждённых сценария, понятные границы функциональности/стоимости, ссылка установки/поддержки; без обещаний ещё не реализованных функций |

Нельзя решить настройки домена, SMTP, контактов оператора, оплаты модели и аккаунтов магазинов вымышленными значениями. Их должен определить владелец продукта. Изменение SDK нужно проверять отдельными последовательными шагами, а не считать замену версии достаточной проверкой.

## Порядок выхода

1. **Закрытый пилот в вебе/PWA:** развернуть HTTPS, настроить модель, опубликовать контакт поддержки и описание данных, проверить восстановление резервной копии. Пригласить небольшую группу, заранее объяснив ограничения восстановления и удаления аккаунта. Пилот не объявлять массовым самостоятельным сервисом.
2. **Нативный пилот:** обновить SDK, собрать подписанные приложения, пройти проверку на Android/iPhone. Раздать APK/TestFlight; проверить установку, новый аккаунт, первый ответ и обновление версии.
3. **Открытый выпуск:** завершить P0, подготовить описания и скриншоты магазинов, форму обратной связи, понятные лимиты и стоимость. Провести приёмку с людьми, которые не видели проект, наблюдая без подсказок.

## Подготовка сборки мобильного приложения

После обновления SDK и проверки зависимостей:

```bash
cd mobile
npm ci
export EXPO_PUBLIC_API_BASE=https://your-real-pia-domain.example
export PIA_IOS_BUNDLE_ID=your.owned.identifier
export PIA_ANDROID_PACKAGE=your.owned.identifier
# Авторизация и привязка существующего/нового проекта выполняются владельцем Expo.
npx eas-cli build:configure
npx eas-cli build --profile preview --platform android
npx eas-cli build --profile production --platform all
```

Указанные домен/ID — примеры; использовать свои значения и переменные EAS для удалённой сборки. Preview Android создаёт APK; production Android — обычный AAB. iOS internal distribution требует provisioning устройств, а публичный пилот обычно удобнее через TestFlight production-сборки. Не публиковать release с localhost. Не обещать доступность SDK 51 в актуальном Expo Go.

## Проверки этой доработки

- TypeScript: успешно.
- Jest: 38 тестов, включая веб-вход, защиту повторной отправки, черновик при отказе, multipart-вложения, первый чат, меню, очистку при выходе, смену пароля, фильтрацию service worker, проверку серверов и release-конфигурации.
- Backend: 120 успешно, 1 пропущен; тест встроенного реального Postgres/pgvector не запускает сервер, потому что среда запрещает создание системного пользователя. Серверная логика этой доработкой не менялась.
- JS syntax и git whitespace: успешно.
- Комплект иконок просмотрен. PNG-размеры и прозрачность проверены.
- Визуальная проверка браузера **не завершена**: в среде нет установленного Chromium, а управляемый браузер блокирует локальный адрес. `scripts/verify-web.cjs` подготовлен для проверки ширин 320/390/768/1440 на локальном статическом сервере с тестовыми API; его прохождение ещё не подтверждено.
- Установка PWA, Android/iOS binary, камера на устройстве, фоновые переходы и реальная LLM **не проверены**. Успешные unit-тесты не заменяют эти проверки.

## Ручная приёмка перед приглашением пользователей

- Человек без подсказок понимает назначение продукта, находит установку, создаёт аккаунт и получает первый полезный ответ.
- Chrome/Edge desktop, Safari iPhone, Chrome Android: нет обрезанного текста и горизонтальной прокрутки на 320 px; открытие чатов и настроек доступно с клавиатуры.
- Светлая/тёмная тема, увеличенный системный шрифт, чтение полей и кнопок screen reader.
- Регистрация занятого email, неверный пароль, 2FA и резервный код, смена пароля, выход со всех устройств.
- Обрыв сети при отправке: черновик остаётся, повтор не создаёт визуальный дубликат; не принимать сообщение «нет чатов» за успешную загрузку при ошибке сети.
- Камера без разрешения, выбор файла и отмена, превышение размера, распознанные факты и подтверждение/отказ.
- Отмена генерации, возврат из фона, истечение сессии, смена сервера без пересылки старых токенов.
- Установка и обновление PWA/нативного приложения, круглая иконка Android, отсутствие сети, повтор подключения.
- Изоляция двух аккаунтов, завершение сессий, удаление/экспорт по реализованному процессу, восстановление резервной копии.
