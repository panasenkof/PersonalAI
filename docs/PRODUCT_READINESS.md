# Готовность PIA Agent к первым пользователям

Проверка 1 октября 2026. PersonalAI — имя репозитория, PIA Agent — имя продукта. Иконка и основные интерфейсы подготовлены; программные механизмы для самостоятельного начала работы добавлены. **Работающая публичная установка и подписанные мобильные приложения пока не подтверждены.**

## Что теперь реализовано

- Комплект иконок: оригинальный SVG-знак, основная 1024×1024 без прозрачности, прозрачный adaptive foreground, splash, favicon, Apple touch icon и PWA 192/512. Исходник `brand/icon.svg`, экспорт `scripts/generate-brand.cjs`.
- Светлая/тёмная веб-тема, мобильная навигация, safe area, видимый фокус, адаптация к 320 px, доступные диалоги; установка PWA и страница отсутствия сети без кэширования аккаунтных данных.
- Вход и первый чат с примерами, вложения, сохранение черновика при ошибке, отмена генерации, понятные ошибки. Мобильные настройки прокручиваются с клавиатурой; действия с данными защищены от повторного запуска.
- Восстановление пароля и подтверждение email в вебе и приложении. Случайные одноразовые токены: 30 минут для сброса, 24 часа для email; в таблице токенов только SHA256, очередь писем шифруется ключом установки. SMTP с TLS, долговечная повторная доставка, частотные лимиты, одинаковый ответ для известных/неизвестных адресов. Сброс сохраняет 2FA и отзывает старые сессии. Письмо не выполняет действие при одном открытии ссылки.
- Экспорт ZIP с историей/фактами/исходными файлами, без паролей/API-ключей/секретов 2FA. Удаление аккаунта после пароля, 2FA и точного email; явное предупреждение. Изоляция аккаунтов, повтор удаления файлов при ошибке, отдельный журнал для аварийного восстановления. Незавершённые задания сначала нужно остановить. Экспорт ограничен 100 MiB по умолчанию; для большей базы — контакт поддержки.
- Модель оператора для новых аккаунтов, кнопка проверки модели/эмбеддингов и объяснение расходов. Ключ оператора не копируется в аккаунты; с ним доступны только заданные оператором модели. Иные модели требуют собственного ключа. Частотные лимиты не заменяют денежный бюджет провайдера.
- Версия, сведения об операторе, ссылки правил и поддержка; диагностический JSON по строгому списку полей, без идентификаторов, переписки и секретов. На телефоне экспорт/диагностика открывают системное меню, временный файл удаляется после его закрытия.
- Последовательная миграция Expo 51 → 52 → 53 → 54, React Native 0.81, React 19.1, Navigation 7. EAS-профили требуют HTTPS и собственных package/bundle ID. Это подготовка сборок, а не готовые APK/IPA.
- HTTPS-профиль Caddy, закрытый прямой порт nginx, обязательная проверка конфигурации PUBLIC_LAUNCH, зашифрованные офлайн-копии БД и файлов, безопасное восстановление в новый каталог, отдельное повторное применение удалений.
- `/app/start.html`: страница предложения продукта с реальным снимком веб-интерфейса на демонстрационных данных. `/app/help.html`: установка и начало работы. `/app/service.html`: данные, поддержка и ограничения; напоминания через Telegram, push не обещается.

## Проверки

- TypeScript и Jest: успешно; 42 теста, включая восстановление доступа и удаление временных приватных файлов после системного меню.
- Expo Doctor: 18/18. `npm ci` без legacy-peer-deps и `expo install --check`: успешно.
- Android и iOS: Metro/Hermes export успешно. Подпись и нативная установка не проверены.
- Ruff и mypy: успешно. Backend после исправлений обзора: 156 тестов успешно, 1 пропущен (отдельная Postgres upgrade-БД не предоставлена), 1 исключён (встроенный Postgres требует разрешённого системного пользователя). Есть предупреждение deprecated httpx в Starlette TestClient; в отдельных прогонах Redis-теста наблюдались предупреждения закрытого SQLite event loop.
- Проверены новая миграция и обновление существующей SQLite-базы с сохранением заданий; строгая схема FK включена для SQLite.
- Chromium: ширины 320/390/768/1440, светлая/тёмная схема; вход, навигация, настройки, ZIP download, проверка модели, сброс из email-фрагмента, страницы сервиса/продукта; без JS-ошибок и горизонтального overflow. API в браузерной проверке тестовые; серверные действия отдельно проверены pytest.
- Резервная копия: реальный SQLite snapshot, шифрование, восстановление записей и файлов; отказ при неверном ключе, небезопасном пути и контрольной сумме. Повторное удаление восстановленного аккаунта по отдельному журналу проверено. GitHub CI подтвердил отдельный Compose/Postgres restore drill, запуск двух API-реплик, PostgreSQL/pgvector/Redis и обновление существующей Postgres-базы (run `36855899805`). Это не подтверждение восстановления реальной производственной установки.
- Исправлен запуск браузерной приёмки в CI: тест сам поднимает сервер с тем же `/app/` mount, что и FastAPI, и закрывает его по окончании. Порт выделяется автоматически, готовность сервера ожидается до открытия браузера. Отдельный регрессионный тест проверяет страницу входа, ресурсы, MIME-типы и отказ при выходе из каталога. `BASE_URL` позволяет отдельно проверить уже запущенную установку.
- Детерминированные evals агента: 6/6. Настоящие LLM/SMTP, Docker production, подписанные native binaries и устройства требуют внешней проверки.

## Приёмка перед приглашением пользователей

1. Незнакомый с проектом человек открывает страницу продукта, устанавливает приложение, регистрируется, подтверждает email и получает полезный первый ответ без подсказок автора.
2. Два аккаунта проверяют изоляцию файлов/истории; смену и восстановление пароля, 2FA/резервный код, экспорт и удаление. Неверный пароль для экспорта не завершает текущую сессию.
3. Проверяются файл/камера и отмена разрешения, подтверждение фактов, отсутствие сети, Stop, возврат из фона, истечение сессии, смена сервера и обновление приложения.
4. Оператор восстанавливает копию в изолированную среду, применяет текущие удаления, читает старый диалог/файл и фиксирует реальные RPO/RTO. Секреты и ключи не хранятся вместе с копиями.
5. Работают поддержка, опубликованные правила, мониторинг и контроль расходов. Только после этого разрешается открытый выпуск.

## Исправления обзора репозитория (2 октября 2026)

- Результат задания и запись о доставке мессенджеру фиксируются одной транзакцией. Отдельная outbox-доставка переживает падение процесса и повторяет отправку с задержкой; агент повторно не запускается. В `/v1/admin/stats` виден размер недоставленной очереди. Гарантия — как минимум одна доставка: если процесс упал после принятия сообщения каналом, но до фиксации успеха, возможен повтор. Discord interaction token может истечь при долгой недоступности: очередь сохраняет ошибку, но это не продлевает токен канала.
- Новые пароли хешируются версионированной схемой bcrypt с SHA-256 prehash: окончания длинных UTF-8 паролей учитываются. Старые bcrypt-хеши обновляются после успешного входа с подтверждённым вторым фактором. Для уже существовавших длинных паролей первоначальный суффикс восстановить нельзя; рекомендуется смена/сброс пароля.
- Отчёт анализов свыше 12 000 символов отклоняется до вызова модели и сохранения показателей с предложением разделить документ. PDF ограничен 200 страницами и 200 000 извлечёнными символами; повреждённые страницы и превышение бюджета дают ошибку вместо частичного сохранения. Разбор выполняется вне event loop. Это не sandbox для враждебного PDF: предельное время/память разбора одной сложной страницы ещё требуют отдельного процесса.
- Утверждение регламента ТО заменяет индекс сущности в транзакции. Параметр `ENABLED_DOMAINS` управляет инструментами агента, промптом, подсказками вложений и MCP; пустое значение отключает оба домена.
- API ограничивает сообщение 20 000 символами и 10 вложениями; контекст каждой итерации LLM имеет бюджет `AGENT_CONTEXT_MAX_CHARS`. Списки сущностей получают SQL-пагинацию.
- Добавлены выключение регистрации и allowlist участников, вариант локального прокси для ngrok и защита от подставленного префикса `X-Forwarded-For`. Генератор нового пилота оставляет регистрацию закрытой до настройки оператором.
- Ручной live-eval теперь завершается ошибкой при отсутствии ключа; автоматический запуск записывает явный статус NOT VERIFIED в summary.
