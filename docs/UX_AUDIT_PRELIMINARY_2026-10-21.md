# PersAI — предварительный UX/UI-аудит (source + existing tests)

**Дата:** 21.10.2026. **База:** `panasenkof/PersonalAI`, основная ветка `main` на момент анализа; нормативная целевая спецификация оформлена в [PR #72](https://github.com/panasenkof/PersonalAI/pull/72), включая `docs/design/NEBULA_VISUAL_CONTRACT.md`. **Статус:** предварительный read-only аудит исходников и существующих UI-тестов, **НЕ полный аудит реального Android APK**. Исправлений кода в этой работе нет.

## Короткий итог

Текущее приложение имеет работоспособную основу: `React Navigation` с тремя вкладками, `FlatList` для истории и заметок, `SafeArea`/keyboard handling, сохранение диалога при переключении вкладок, модальные панели с безопасными областями, локальные диктовка/Whisper и вспомогательные тесты Playwright. Но компоновка и художественное исполнение **не соответствуют** согласованному Nebula: много управляющих блоков до контента, отдельный экран импорта вместо вложений в сообщения, размноженные настройки, анимированное статичное изображение вместо органического `NebulaCore`.

Поиск по документам (`docs/`, `PLAN.md`, OpenSpec) и текущим тестам не выявил уже **завершённого UX-аудита, отвечающего п. 87**. Существуют предыдущие замечания, частные проверки и браузерный acceptance harness, которые необходимо переиспользовать. Поскольку полная Figma v0.3 ограничена доступом и нет свежего нативного прогона APK, этот отчёт **не закрывает пункт 87**.

## Матрица недостающих проверок на реальном APK (для завершения п.87)

1. **Контрольная версия APK, устройство/Android, параметры:** модель телефона, размер и DPI, версия ОС, масштаб шрифта, 3-button/gesture; экспорт скриншота каждого этапа.
2. **Chat:** пустой/обычный/длинный (50+ сообщений) диалог; длинный markdown; ручная прокрутка против потоковой автопрокрутки; открытие history и новой беседы; переключение вкладок посреди ответа.
3. **Composer/voice:** короткий и длинный текст; клавиатура Google/Gboard, свайп/кнопки Android, голос через системное распознавание и Whisper, разрешение микрофона, нормализация/откат; кнопки не скрываются.
4. **Media:** camera, Share из галереи, выбор одного/нескольких файлов, большие изображения, PDF, MP3, URL HTML; отдельно статусы недоступного MIME/таймаута/HTTP/отказа модели; для пока не реализованных функций — отсутствие фальшивого успеха.
5. **Memory:** 0, 1, 20, 200+ заметок, длинные заголовки, разделы, фильтры, multi-select, undo, экран заметки, фото с OCR, восстановление только в безопасной тестовой базе после отдельного разрешения.
6. **Settings:** категория/вложенная форма, хранение двух API-коннекторов, возврат после Save, переключение системной/Whisper, выбор поискового провайдера, бюджет и логи; секреты не появляются на скриншотах.
7. **Адаптивность:** 320/360/390/430dp, высоты 470/580/900dp, шрифт ×1/×1.3/×1.5, тёмная/светлая/контрастная тема; TalkBack; insets 0/24/48 для браузера и реальные Android system bars.
8. **Анимации и энергия:** оба графических референса side-by-side, idle/listening/thinking/response/error, Reduce Motion, background/foreground, 10–15 минут обычного диалога с замером кадров/памяти/нагрева/батареи.

## Рекомендуемая последовательность после PR #72

1. Привязать исходники REF-ICON-A и REF-ORB-B к репозиторию (без снижения качества) и добиться утверждения компоновки Nebula v0.3 в полном интерактивном макете; при лимите Figma можно отдельно доработать HTML для UX-проверки, не подменяя им редактируемый исходник.
2. Закрыть пункт 87 реальными скриншотами/устройством. Первичные P1 замечания выше — вход для этого аудита, а не автоматический verdict native.
3. Дизайн-система 88: `NebulaCore`, `NebulaBackground`, `ChatComposer`, `AttachmentChip`, `MemoryList`, `SettingsSections`, tokens, antiloss policies; UI-скилл для ИИ.
4. Контракт мультимодального агента отдельно от UI: image/PDF capabilities, consent, storage, source and errors.
5. PR 89 маленькими частями с визуальными регрессиями 90: shell → чат → память → импорт → настройки. На каждом этапе сохранять прежний функционал, SQLCipher, биометрию, историю, локальную приватность.

**Итог:** прежние acceptance-тесты полезны, но **полный UX-аудит ранее не выполнен**; текущий документ закрывает только *этап предварительного анализа исходников* и служит основой для завершающей нативной проверки. Вердикт полного UX-аудита: **ОТКРЫТ / НЕ ПРИНЯТ**.
