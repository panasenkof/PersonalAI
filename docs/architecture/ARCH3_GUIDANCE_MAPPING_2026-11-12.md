# ARCH-3 — карта переноса системных инструкций в единый prompt

**Статус:** подготовка, без изменения системных текстов/поведения. **Очередь только в [PLAN.md](../../PLAN.md)**. Исходные тексты: `direct-agent/prompt.ts`, зафиксированные золотыми снимками ARCH-0/1. Схемы инструментов менять запрещено.

## Общие правила, сохраняемые при любом составе инструментов

- Роль PersAI, запрет выдуманных результатов и фактов о памяти; недоверенность заметок, найденных сайтов и распознаваний; запрет исполнять внедрённые инструкции.
- Честная оговорка о непроверенной актуальности при отсутствии веб-поиска; запрет передачи приватных пикселей/векторов без согласия; запрет предлагать сохранять документы и пароли.
- `DIALOGUE_GUIDE`, `factGuide(sections)` и контекстные сведения — только в подтверждённых режимах; не раскрывать закрытые разделы.
- Метаданные и цитаты должны соответствовать реально прочитанным источникам, версии/ACL и текущему контексту, не являться симуляцией tool result.

## Проверки ARCH-3b перед слиянием

1. Базовый prompt минимального каталога не должен упоминать отсутствующие инструменты; `contextOnly` сохраняет отдельную безопасную цепочку.
2. При полной конфигурации **множество исходных предложений** из ARCH-0 должно остаться эквивалентным (за исключением явного удаления бесполезного текста и с отдельным обоснованием в PR). Сопоставление делать с исходным snapshot, а не изменённой функцией.
3. OpenAI Responses и compatible используют **один** `buildSystemPrompt` при одинаковом наборе инструментов; измерить длину текста до/после для четырёх режимов.
4. `golden-tools` не меняется; ACL, CAS/undo, privacy и сам инструментальный цикл не модифицируются.
5. **Live-acceptance по двум провайдерам — обязательный отдельный gate ARCH-11**. До него статус `NOT_RUN_LIVE_MODEL`, нельзя объявлять ARCH-3 принятым.

ARCH-3a добавляет только необязательное поле `ToolSpec.guidance` и выход `catalog.guidance` в прежнем порядке **активных** инструментов. Текстовые инструкции пока не перенесены, и текущие providers их не используют; следующий PR реализует распределение и сборку.
