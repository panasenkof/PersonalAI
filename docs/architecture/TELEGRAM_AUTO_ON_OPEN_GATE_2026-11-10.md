# Telegram PR2.B6 — режим on_open для аккаунта TDLib и резервного бота

Дата 10.11.2026. До required CI — CODE_CANDIDATE, до физического Vivo/live Telegram — C2_PENDING.

## Preflight C0-A/C3-B

- Режим \`manual | on_open\` уже хранится в профильном device-only SecureStore, default manual, UI «Настройки → Telegram».
- TDLib авторизация только через нативное состояние \`authorizationStateReady\`, AppLock и устройство, без бессрочных background services.
- \`importSavedTextPage\` использует единственный \`saveMediaNote\`, ту же SQLCipher память, FTS, дедуп и штатное индексирование.
- Резервный Bot API остаётся независимым с собственным chat_id и getUpdates.

## Поведение

- При открытии/запуске процесса PersAI **после разблокировки AppLock** и только при явном \`on_open\` приложение проверяет существование локального device-only TDLib database key. Новый аккаунт не создаётся автоматически.
- Если нативная TDLib действительно доступна, клиент инициализируется, и **только после реального \`authorizationStateReady\`** разрешён импорт.
- За запуск: **не более одной страницы из 20 последних** сообщений «Избранного», только текст, пропущенные медиа не считаются импортированными. Полную историю пользователь импортирует вручную.
- Бот получает независимый шанс проверить свою очередь, даже если TDLib недоступна/не авторизована/ошиблась, и наоборот.
- Нет таймера, фоновой службы, обхода LLM loop в чате, нового SQL индекса, новых Android permissions.
- Прекращение доступности AppLock закрывает TDLib клиент и абортирует дальнейшие операции; \`once per JS process/profile\` не означает повтор каждую смену вкладки.

## Негативные проверки

- Manual не вызывает ни один канал.
- Без ранее созданной базы TDLib не запускает авторизацию.
- SMS-код / пароль / email состояния не приводят к чтению личных сообщений.
- Только один импорт после готовности; перерисовка и повторное событие ready не умножают работу.
- Сбой бота не препятствует аккаунту; сбой аккаунта не препятствует боту.
- Переключение профиля, закрытие приложения и блокировка приводят к отмене/закрытию.

## Чего пока нет

- **Полного** автоматического backfill. Это лимитированный инкрементальный срез; если накопилось более 20 новых сообщений, старые можно импортировать вручную, но не обещать полноту.
- Saved Messages Topics, оригиналы фото/файлов, bot media/edits, TDLib binary distribution и реальная авторизация на устройстве.
- Полное пользовательское подтверждение внешней LLM обработки сохраняется в прежних настройках фонового обогащения памяти; этот пакет не вызывает модель напрямую.
- Обязательная физическая проверка Vivo X200 Pro + настоящий Telegram: NOT_RUN_PHYSICAL.

## Postflight C0-A/C3-B
