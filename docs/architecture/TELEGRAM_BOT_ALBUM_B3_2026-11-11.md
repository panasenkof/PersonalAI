# Telegram BOT-B3 — групповой импорт альбомов без потери оригиналов

Дата: 11.11.2026. Статус: CODE_CANDIDATE / CI_PENDING / NOT_RUN_PHYSICAL.

## Задача и существующие механизмы

Резервный личный бот принимает `getUpdates`, привязан к одному подтверждённому частному чату и сохраняет текст/одиночные оригиналы через единственный `saveMediaNote` в SQLCipher. BOT-B3 **не создаёт второй writer, индекс, таблицу, очередь, фоновую службу или сервер**.

У Bot API нет поля `total_album_items` или официального сигнала окончания альбома. Каждая часть приходит отдельным `message` с общим `media_group_id`. Нельзя объявить финальный файл последним просто потому, что он оказался концом текущего `getUpdates`.

## Поведение и гарантия ACK

1. Только сообщения подтверждённого личного чата с одинаковым валидным `media_group_id` собираются в ограниченную группу (2–10 оригиналов); сторонние чаты не закрывают группу.
2. Граница: следующее **другое** сообщение владельца либо 10-й элемент. Для короткого альбома в хвосте выборки результат — `pendingAlbum`: **ни один** элемент группы не скачивается, не записывается и не ACK-ается. В UI предлагается отправить боту отдельное текстовое сообщение либо `/done` и повторить импорт.
3. Для каждого файла применяется прежняя проверка Telegram `getFile`, 20 МБ на исходный файл, контролируемое скачивание в уже существующий `persai-incoming` и удаление временного файла после операции; суммарный лимит 80 МиБ действующего writer проверяется до транзакции и затем самим writer.
4. Одна `saveMediaNote(files)` создаёт запись с оригиналами, подписями и метаданными каждого `message_id` в штатном `source_bot_message`; уникальный receipt включает список ID. Предшествующие одиночные receipts не меняются. Повтор того же набора возвращает имеющуюся запись; массовых LLM-вызовов или молчаливого merge нет.
5. Только **после успешного подтверждения SQLite-транзакции или доказанного replay** защищённый курсор продвигается сразу до последнего обработанного update группы. При ошибках сети, AppLock, размера, отмены, SQLCipher, повреждённом списке — нет ACK группы.
6. Чистка временных оригиналов осуществляется даже после отказа при скачивании середины группы.

## Известные границы

- **Конец альбома не может быть криптографически подтверждён Bot API.** При очень поздних элементах уже закрытой группы возможны дополнительные фрагменты; оригиналы не должны теряться, их объединение будет отдельной подтверждаемой операцией. Нельзя писать пользователю «все элементы Telegram уже импортированы» на основании одного запроса.
- У Telegram серверные `getUpdates` имеют ограниченный срок хранения; это не безусловная долговременная синхронизация. Отправка `/done` делает закрытие группы явным без ожидания следующего содержательного сообщения.
- Сервисные данные, изменения и удаления сообщений требуют отдельных сценариев; невозвратные или неподдержанные объекты остаются fail-closed.
- Оригиналы «Избранного» из TDLib — **другой транспорт** и не входят в BOT-B3.
- QA на Vivo/живом аккаунте отложена решением владельца; до неё физический статус `NOT_RUN_PHYSICAL`.

## Автоматические сценарии

Группа из двух оригиналов + `/done`; хвост незавершённой группы без ACK; чужие чаты между частями; 10 элементов; повтор/replay; сбой второго оригинала; переполнение 80 МиБ; изменение источника/ID; неправильный `groupId`; AppLock и поздняя отмена. Проверки должны пройти на exact SHA, затем main CI.
