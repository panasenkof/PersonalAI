# Telegram PR2.B5 — перенос текста «Избранного» в память

Дата: 10.11.2026. Статус до CI и реального Android: CODE_CANDIDATE / C2_PENDING.

## Preflight C0-A/C3-B

- PR2.B2 — узкий TDLib native bridge; PR2.B3 — авторизация и AppLock; PR2.B4 — ограниченный read-only список self chat.
- Единственный writer заметок: \`mobile/src/media/attachments.ts::saveMediaNote\` в SQLCipher. Штатные receipts: \`memory_received_shares\`; штатный FTS и фоновое обогащение полей записи остаются прежними.
- Не создавать отдельную таблицу Telegram, свой репозиторий памяти, поиск, классификатор, автоматическую LLM-сессию или дополнительные Android permissions.

## UX

После подтверждённого \`authorizationStateReady\` в Настройки → Telegram отображается «Импорт Избранного».
- «Импортировать последние 20 сообщений»: читает страницу строго своего чата через native bridge, сохраняет **только** непустые текстовые сообщения и ссылки в «Входящие».
- «Продолжить историю (до 20)»: переходит к старым сообщениям в пределах текущего открытия экрана; повторение исходной страницы не создаёт новые заметки.
- «Начать с новых сообщений»: снова проверяет последние сообщения без дублирования.
- Отчёт об импорте показывает созданные, уже сохранённые, пропущенные медиа и пустые сообщения. Скрытого фонового запуска и новых внешних LLM-запросов в этой вертикали нет.

## Канонический receipt и источник

- Для каждого \`(selfChatId,messageId)\` вычисляется неизменный SHA-256 receipt \`telegram-saved-source-v1\`, **независимый** от названия, текста, тегов и будущих LLM-подсказок.
- Повтор после редактирования исходного сообщения **не перезаписывает** авторскую заметку; обновление таких источников требует отдельного пользовательского сценария.
- \`source_telegram_saved\` в штатном payload фиксирует \`chatId,messageId,date,kind\`, \`source_ref=telegram-saved\`; в отдельных таблицах Telegram данные не дублируются.
- Родительская транзакция создания entity + receipt атомарна; недоступная или заблокированная память не приводит к успешному импорту.
- Native \`getSavedMessagesPage(profile,cursor,limit)\` проверяет совпадение локального профиля с активной TDLib-сессией **до и после** сетевого запроса.

## Не входит, следующие шаги

1. **Реальная TDLib на устройстве:** официальный проверенный бинарник, инструкции установки, ARM64/16 KiB/SSL compatibility, logout и полная очистка.
2. **Saved Messages Topics:** отдельно подтверждённый TDLib API и разрешённый topic ID, topic-aware provenance; новые записи из тематических подборок не терять.
3. **Медиа:** скачивание настоящих оригиналов фото, документа, видео, аудио с пофайловой проверкой и записью в уже существующие attachment parts; альбомы/group captions — отдельные cases.
4. **Автоматическая синхронизация «Избранного»:** ранее выбранный режим manual/on_open должен безопасно инициировать TDLib после AppLock и сохранять только новое с durable checkpoints; данный PR — **только явный ручной импорт**.
5. Сквозная LLM-разметка использовать только действующие инструменты и фоновые механизмы обогащения, по настройкам согласия.
6. Реальный Telegram с разнообразными «Избранными», сообщения после edit/delete/forward, и Vivo X200 Pro физически — NOT_RUN_PHYSICAL.

## Postflight gate

- TS/Jest, тесты реальной SQLite-дедупликации, Native Android emulator release + UI smoke, required CI на exact SHA — проверить до слияния.
- Профильные ACL, SQLCipher, backup/restore и существующий Bot API не ломать.
- Не писать «Telegram синхронизирован», «Все фото импортированы» или DONE/C2, пока остальные этапы не пройдены.
