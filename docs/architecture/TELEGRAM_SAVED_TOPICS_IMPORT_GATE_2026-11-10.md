# Telegram B8 — выбор подборки «Избранного» и канонический импорт текста

Дата решения 10.11.2026. Базовый PR #467 B7 только чтение тем; B8 поверх него, не сливать прежде B7 и required CI.

## Preflight C0-A / C3-B
- Единственный writer `saveMediaNote` в SQLCipher: receipt для Saved Messages вычисляется из **self-chat ID + message ID**, без влияния topic ID. Повторное чтение через список «все» или конкретную подборку не должно создать второй объект.
- Нативные темы и IDs — только из TDLib `updateSavedMessagesTopic`, JS не может выбрать произвольный чат, вызов AppLock обязателен.
- Android Share, бот, LLM инструменты и классификатор не модифицируются.

## Реализованное поведение
1. Настройки → Telegram → существующий блок «Импорт Избранного».
2. Пользователь нажимает «Обновить подборки» (сеть только по явному действию, без автоподгрузки). Отображается только краткий вид тем с типом и ID; Telegram темы группируют по источнику пересылки, **это не разделы PersAI**.
3. Выбор конкретной темы сбрасывает позицию страницы и вызывает `readSavedTopicPage`; выбор «Все сообщения» возвращает прежний `readSavedMessagesPage`.
4. Каждый полученный текст сохраняется только через текущий `saveMediaNote`, с прежним source receipt; к source provenance необязательно добавляется проверенный topic ID. Существующие заметки по тому же сообщению не изменяются и не перезаписываются.
5. Фото/видео/документы, если даже содержат подпись, пропускаются и показываются в отчёте; текст не подменяет оригинал. Успешно сохранённые записи остаются во «Входящих». Нет независимого хранилища/курсор-таблицы.

## Негативные тесты и C2
- Повторный импорт через «Все»/тему, malformed topic IDs, AppLock, сетевые сбои, retry после прерывания, неподдержанные вложения.
- Нет регистрации произвольной группы/чата; IDs проверяет нативный мост.
- На телефонном APK с реальным TDLib SHA/бинарником: **NOT_RUN_PHYSICAL**, UI/CI не доказывают работу настоящего Telegram.
