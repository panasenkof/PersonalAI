# Telegram TDLib B14B — групповой импорт оригиналов «Избранного»

Дата: 11.11.2026. Статус CODE_CANDIDATE / CI_PENDING / NOT_RUN_PHYSICAL.

## Инварианты (C0-A / C3-B)

1. Используются существующие TDLib native bridge, Saved page reader, SQLCipher `saveMediaNote`, AppLock и receipts. Нет нового writer, хранилища, очереди, сервера, поиска или неограниченного TDLib API для LLM.
2. `media_album_id` приходит из собственного чата как неизменённая десятичная строка int64. Нативный `downloadSavedAlbumOriginal` для **каждого** сообщения повторно сверяет selfChat, message_id и albumId. Метод `releaseSavedAlbumOriginal` делает ту же проверку перед очисткой локального кеша.
3. Импорт альбома выполняется одной SQLCipher-транзакцией `saveMediaNote(files)`: от 2 до 10 оригиналов, не более штатного общего лимита 80 МиБ, подписи членов группы сохраняются по порядку. Receipt зависит от selfChat, albumId и упорядоченного списка ID. Повтор импорта/пересечение истории с подборками не создаёт дубликаты.
4. Любой отказ загрузки одного оригинала, неверный файл, превышение лимита или AppLock не даёт неполной заметки. В `finally` делается best-effort очистка только ранее полученных TDLib-файлов.
5. Обычные текстовые и одиночные сообщения работают прежним путём. Автоматическая синхронизация при запуске остаётся **текстовой**, без скрытых загрузок.

## Граница страницы

Из истории считываются до 20 сообщений и, если группа обрывается ровно на нижней границе, не более одной дополнительной страницы. Дочитывается только группа плюс первое старшее сообщение, подтверждающее границу. Это не беспредельное сканирование истории.

Группа становится готовой лишь при обнаружении более старого сообщения другого типа/альбома или при 10 элементах; если групповой хвост не закрыт даже после дочитывания, он возвращается как `pendingAlbum`, не записывается и **не пролистывается** — курсор остаётся до начала группы. Пользователь может повторить запрос позднее. Если альбом — самые старые сообщения в истории, такой хвост требует будущего явного подтверждения и не должен импортироваться как заведомо полный автоматически.

## Не входит в пакет

- Редактирование и удаление сообщений Telegram, согласование с заметками (не допускается удаление пользовательских заметок вслед за Telegram).
- Автоматическая очистка осиротевших кеш-файлов после внезапной остановки процесса. Основной cleanup B13 действует по нормальному `finally`.
- Физическая проверка аккаунта на Vivo, официально помеченная `NOT_RUN_PHYSICAL`.

## Проверка

Jest: источник чужого альбома, int64 ID, ограниченная дочитка, pending вместо потери, порядок файлов/подписей, ошибка второго оригинала, 80 МиБ, SQLCipher отказ, replay и AppLock. Kotlin build + Android smoke на точном SHA до merge. Нативный live-TDLib download отдельно проверяется при финальной ручной приёмке.
