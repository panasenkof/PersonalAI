# Telegram TDLib B12 — оригиналы одиночных сообщений «Избранного»

Дата: 11.11.2026. Статус: CODE_CANDIDATE / CI_PENDING / NOT_RUN_PHYSICAL.

## Архитектурная сверка C0-A

- Existing Android native `PersaiTelegramTdlib` — единственный мост к TDLib; вызов оригинала принимает только профиль, подтверждённый selfChatId и messageId. Произвольные файловые ID, URL и чужие chat_id не доступны JS.
- Existing `saveMediaNote` / SQLCipher / attachments / receipts — единственная запись, индексация и дедупликация. Ни сервер, ни новый writer, ни база, ни polling не создаются.
- AppLock — до/после native запроса и до SQLCipher транзакции; при блокировке импорт прекращается без ложного успеха.
- Привязка: native **каждый раз** перепроверяет `getMe` и `createPrivateChat(self)`, `getMessage`, возвращает оригинал только если он принадлежит self chat. JS повторно валидирует источник, время, вид, текст/подпись и путь в `persai-tdlib-<profile>/files`.
- Оригинал загружается официальной TDLib `downloadFile` (без сетевого URL для JS). Применяются штатный лимит 80 МиБ и native request timeout 25 с; отсутствие завершённой загрузки не трактуется как успех.
- Для одиночных `messagePhoto`, `messageDocument`, `messageVideo`, `messageAudio`, `messageVoiceNote`, `messageAnimation`, `messageVideoNote` сохраняются **реальные байты** и подпись; receipt `telegram-saved:<chat>:<message>` остаётся совместимым с историческими текстовыми записями.
- Пользовательский **ручной** импорт выбирает originals; режим «при запуске» пока **только текстовый**, чтобы не расходовать мобильный интернет и 80 МиБ автоматически.

## Неподдерживаемое и осторожное поведение

- `media_album_id != 0` явно отмечается в чтении как альбом и пока пропускается: нельзя разбить группу на несколько случайных записей и назвать это полным импортом. Групповой импорт TDLib — отдельный PR, не путать с Bot album.
- Форматы вне действующего `mediaKind` не принимаются; не создавать «фальшивые» текстовые заметки с одной подписью.
- Изменённое между preview и загрузкой сообщение отклоняется по несовпадению идентификатора/даты/подписи/вида, а не молча перезаписывается.
- TDLib хранит скачанные файлы в собственном app-private каталоге (вместе с SQLCipher-копией). Управление размером кеша, безопасное удаление и корректная повторная загрузка — отдельная обязательная задача до объявления полного Telegram-медиа READY.
- В прежней схеме источника нет ID альбома и статуса редактирования: удаление/редактирование и согласование изменений пока не поддерживаются, нельзя обещать двустороннюю синхронизацию.

## Автоматические критерии

1. Нативный APK компилируется при отсутствии TDLib (непривилегированный default build), а официально поставленная библиотека по-прежнему проходит отдельный manual signed gate.
2. Нет произвольного Telegram chat/file method ни в JS, ни в LLM tools. Неправильная локальная папка/профиль/сообщение/путь и изменение подписи отклоняются.
3. Сохранение фото с оригиналом и provenance в canonical SQLCipher, replay без дубля.
4. Провал загрузки или блокировка не создают caption-only заметок и не отмечаются как успешный импорт.
5. Медиагруппы не дробятся; в автоматическом режиме originales не скачиваются.
6. Полный CI и Android UI smoke на exact SHA до merge; Vivo физическая проверка отложена владельцем.

## Postflight C3-B

После CI сверить со старым `saveMediaNote`, `TelegramAutoSync`, AppLock и архивами SQLite: нет дублирования механизма записи/поиска/очереди. Для полноценного этапа требуются TDLib альбомы, обработка изменений и управление кешем. Физический статус до живой проверки остаётся `NOT_RUN_PHYSICAL`.
