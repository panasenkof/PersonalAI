# PersAI · сверка UX памяти с утверждённым дизайном и мировыми референсами (29.10.2026)

**Статус:** аудит реального `main` после #213, исходников React Native и сохранённых проектных контрактов; небольшой исправляющий UX-срез в связанном PR. **Не** финальная пиксельная оценка установленного Android APK, не новый дизайн и не новая очередь работ. Физический U5/TalkBack/320–430dp остаётся НЕ ПРОВЕРЕН до фактических тестов. Наличие зелёного Android эмулятора не равно физическому C2.

2. [Оригинальные изображения и контроль целостности](references/README.md), [UX redesign](../UI_UX_REDESIGN.md), [манифест визуальной библиотеки](MEMORY_VISUAL_LIBRARY_2026-10-24.md): утверждены REF-ICON-A/ORB-B/UI-C, карточки «коллекции + недавние», сетка или список, фото/оригиналы, лёгкое редактирование без анкеты, контекстные действия и явные ИИ-подтверждения. Исходные PNG/JFIF есть в GitHub ZIP; **в рамках этой сверки побайтовая/визуальная ревизия бинарных изображений не производилась**. Не выдавать список референсов за сравнение реальных скриншотов.

[M4-UX](../../Plans/MEMORY_ENGINE_UI.md), [U5](../../Plans/UI_U5_ACCEPTANCE.md), [UI delivery](../../Plans/UI_DELIVERY.md) и [базовые инженерные гейты](../DEVELOPMENT_GATES.md): существующая архитектура, однотипные подтверждения temporal+relation, объяснение фактов/источников, без дополнительных вкладок/экранов, доступность, ручная отмена и канонические ACL/CAS writers.

| Приложение / проверяемая возможность | Полезный паттерн | Что делаем в PersAI | Что намеренно НЕ копируем |
| --- | --- | --- | --- |
| [Apple Photos · Duplicates](https://support.apple.com/guide/iphone/merge-duplicate-photos-and-videos-iph1978d9c23/26/ios/26) | Группы похожих материалов отдельно от общего потока; отдельное подтверждение действия с набором | Предложения exact URL/read-later → явный просмотр каждой записи/исключения → архив/корзина и undo | Не называем одинаковую ссылку доказанным дубликатом, не сливаем разные аннотации, не делаем auto-purge |
| [Google Photos · Archive / Locked Folder](https://support.google.com/photos/answer/10694388?co=GENIE.Platform%3DAndroid&hl=en) | Архив — не удаление и не уровень секретности; защищённые материалы нельзя раскрывать через обычный список/поиск | Различать активное/архив/корзину и приватность; ACL проверяется *до* показа заголовков/после открытия/перед применением | Не воспроизводим отдельный Google locked-folder продукт и другой security-контур внутри PersAI |

| [Notion · same content, multiple views](https://www.notion.com/help/views-filters-and-sorts) | Представления галереи, списка, времени — виды одной коллекции | Одни SQLCipher записи и читатель; виды и history не создают второе хранилище | Не копируем сложные таблицы, доски, десятки свойств на мобильном экране |
| [mymind · visual saved media](https://mymind.com/mobile) | Настоящие превью статей/фото, удобный поиск по внешним ссылкам, быстрый Android Share | Сохраняем утверждённую визуальную библиотеку и оригиналы; отметка источника и тип медиа | Не вводим обязательный AI auto-tagging или облачный индекс |
| [Capacities · mobile capture/find](https://capacities.io/mobile-app) | На телефоне важнее быстро сохранить и найти; сложную организацию прятать | Ручной preview и короткие обзорные списки вместо сырого графа | Не переносим desktop-плотность и сложные схемы объектов на 320dp |
| [Android Material 3 · bottom sheets](https://developer.android.com/develop/ui/compose/components/bottom-sheets) | Вторичные действия в модальной панели, не новой вкладке | Используем существующий `BottomSheet` с Android Back/insets | Не встраиваем второй navigation flow на каждый подпроцесс |
| [Android accessibility](https://developer.android.com/guide/topics/ui/accessibility/apps) | Каждая интерактивная зона >=48dp, краткая семантическая метка, читабельный текст при масштабе | `nebulaTouch.minimum`, `accessibilityRole`, `accessibilityLabel`, понятная обратимая кнопка | Не экономим место за счёт невидимых/крошечных элементов |

**Важное различие:** Apple Photos умеет настоящее image-dedup; PersAI №79б сегодня распознаёт *только* точный URL и явную пользовательскую пометку. UI не должен говорить «найдены дубли» или «этот контент устарел». Признак потери интереса не выводится из срока хранения.

## C0-A и C3-B

**До:** `LocalMemoryScreen` → `hygiene().discoverGroups()` → `previewWithExclusions()` → `changeNotes()/undoNotes()`; `MemoryTemporalTimeline` → `repository.temporalKnowledgeHistory()` → `repository.entity()` для guarded source navigation. Источник истины — текущий SQLCipher, правила retention и source/version+ACL; библиотека — `MemoryNoteCard`/Nebula; `BottomSheet` — существующий. 

**После (должно быть доказано CI):** меняются **только текст/иерархия показа** в двух существующих компонентах, без SQL-миграций, новых writer, модели, индекса, таблиц, tab/sidebar, автоматики, изменений Home/сферы. Тесты должны доказать typed candidate uncertainty, distinct valid vs recorded date, no leaked technical labels, reason-coded suggestions, partial coverage и no-auto-apply. Существующие guarded-privacy/native CI — обязательны.

**Stop gate:** если exact-SHA CI успешен, завершить этот UX-срез. Следом вернуться к **обязательным временным ответам/полноте доказательств и 96 C1** по PLAN §2; не запускать общую косметическую ревизию всех экранов. Референсы служат критерием качества по реальным сценариям, а не причиной бесконечно менять дизайн.
