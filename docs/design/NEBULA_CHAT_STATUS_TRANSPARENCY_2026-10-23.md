# PersAI Nebula: статус, прозрачная сфера, читаемая переписка

23.10.2026 — отдельный UX-пакет после слитого #99, по Android-видео `1000038810.mp4`.

## Принятое поведение

- Название модели/подключения убирается из Home: все подключения остаются в Настройках. Вместо селектора — компактный текстовый статус рядом с орбом. Список нейтральных этапов: Готов, Загружаю, Подключаюсь, Думаю, Ищу в памяти, Ищу в интернете, Пишу ответ, Слушаю, Распознаю речь, Нет сети, Ошибка. Показываем `(N/M)` только для реально полученного `progress`. Отдельный formatter в `homePhase.ts` — точка будущей интеграции с характером агента №82.
- `homeCanvas` рисуется SkSL с premultiplied alpha для настоящей прозрачности: фон наследуется из текущей темы, орб и мягкий ореол сохраняют B+C плазму/струну. Сцена лаборатории (`homeCanvas=false`) сохраняет оригинальный непрозрачный фон. PNG fallback на устройствах без совместимого native shader пока остаётся отдельным крайним режимом.
- Переписка следует распространённым правилам нейросетевых чатов: короткое содержимое располагается около поля ввода; после Send виден пузырь вопроса и первые строки ответа непосредственно под ним. Пока ответ короткий, включён bottom-follow; при длинном ответе (от max(140dp, 38% viewport)) прокрутка перестаёт вытеснять начало ответа. Ручной жест имеет приоритет. Плавающая кнопка «К последнему» возвращает следование. Изменения клавиатуры **не** отключают Android `KeyboardAvoidingView height` (#99).
- Без fake reasoning, выдуманных процентов, изменения LLM/API, SQLCipher, AppLock/биометрии и сохранённых записей.

## Критерии проверки

- TypeScript/Jest/browser checks; Android 35 Maestro: настоящий PIN, открытая IME и видимая очистка черновика, переходы между вкладками.
- Физический Android: быстрый и длинный ответ, Send при Gboard, свайп вверх и возврат к последнему, смена вкладки в ходе ответа, длинные списки и первый пустой чат.
- Размеры 320/360/390/430dp, большой системный шрифт; статичная и живая сфера, а также отсутствие квадратного фона на **реальном устройстве**. Скриншотные source guards не заменяют эту визуальную приёмку.
