# PersAI Nebula — A/B переключатель производительности (Home live / static)

**Дата:** 22 октября 2026. **План:** шаг 90 из [NEBULA_PRODUCTION_ROLLOUT.md](NEBULA_PRODUCTION_ROLLOUT.md) и [NEBULA_PERFORMANCE_GATE.md](NEBULA_PERFORMANCE_GATE.md).

## Зачем

После нативной интеграции B+C в Home и исправления обрезания сферы Gboard требуется сравнить **тот же визуальный объект с анимацией и без неё**. Без функции переключения нельзя получить чистую A/B-разницу FPS/нагрузки/battery на *одном* телефоне и сравнимых условиях. Это первый инструмент к измерению, а не заявление об оптимизации или реальном тесте.

## Пользовательский контракт

- **Путь:** Настройки → Диагностика диалогов → Для разработчика → **Анимация Nebula на главной** (переключатель). В текущем главном экране дополнительных кнопок и обязательных вкладок не возникает.
- **ON (по умолчанию):** утверждённая B+C (основа ×5, нить ×1) с семью реальными фазами голос/LLM, full-res исходная текстура, исходный фон. Переключатель применяется при возвращении на Home.
- **OFF:** та же **качественная нативная статичная Skia B+C**, с текущим статусным цветом/нитью, без `useClock`, без лишнего скрытого GPU цикла. **Не заменять на плоский PNG или generic gradient**, если native shader доступен.
- **Reduce Motion, background, закрытый экран:** автоматически отключают движение независимо от ON. Настройка ON не может снять системные ограничения.
- **Профиль безопасности:** значение — *несекретная настройка графики* в локальном `expo-sqlite/kv-store`, **не** в SQLCipher/личной памяти; не хранит текст, файлы, секреты, журналы и не отправляется в сеть. Текущая SQLCipher-память/история/ключи и биометрия не затрагиваются. Android native implementation, browser QA fallback без реального GPU.
- **Отказоустойчивость:** при ошибке чтения настройки Home использует ON (с уже действующими системными Reduce Motion), экран диагностики сообщает об ошибке. Писать изменение только после успешного сохранения. Возврат на Home обновляет состояние.
- **Назад:** отключение тестового режима возможно в любой момент через тот же переключатель; удаление/очистка приложения для возврата не требуется.

## Двухуровневая архитектура

1. `visualMode.ts` — pure `NebulaVisualMode = "live"|"static"`, parse unknown/null to default `live`.
2. `visualPreference.native.ts` — persist с `expo-sqlite/kv-store`; `visualPreference.ts` — web QA-compatible in-memory surrogate, **не аналог нативного исполнения**.
3. `DiagnosticLogsScreen` читает и записывает `NebulaVisualMode`, подписывает switch и выводит краткую инструкцию повторного A/B.
4. `NebulaHomeArtwork.native.tsx` на `useFocusEffect` читает persisted mode, передаёт `pauseAnimation` в `NebulaSkiaExperiment`; не изменяет выбранную LLM, фазу, позицию сферы, диалоги, микрофон или экран «Защищено».
5. `NebulaSkiaExperiment` при `pauseAnimation` монтирует `StaticSkiaOrb` с настоящей текстурой, шейдером и цветной нитью; animated clock и его наблюдатели не монтируются. Добавить читаемую диагностическую причину **«Ручной A/B: статичная Nebula»**, чтобы не выдавать её за ошибку SkSL.
6. **Запрещено:** менять REF-ORB-B, семантику фаз и её время, глобальный Skia speed, настройки профиля, рабочую навигацию, внешний вид AppLock/«Защищено».

## Приёмочные сценарии

| ID | WHEN | THEN |
| --- | --- | --- |
| AB-01 | Новый пользователь / ключ не создан | Home отображает approved live B+C по умолчанию |
| AB-02 | Диагностика → выключить анимацию, вернуться на Home | Тот же B+C Skia shader статичен, цветная нить фаз сохранена, **useClock отсутствует** |
| AB-03 | Диагностика → включить анимацию и вернуться | Live B+C без потери истории, черновика, LLM, навигации |
| AB-04 | В OFF вызвать listening/thinking/responding | Фаза текстом/нитью меняется, движение не начинается |
| AB-05 | В ON свернуть приложение, Reduce Motion | Android accessibility/background имеют приоритет |
| AB-06 | В OFF долго печатать с Gboard | Orb соответствует [keyboard layout](NEBULA_HOME_KEYBOARD_LAYOUT.md), не перекрывает composer |
| AB-07 | Отрицательный сценарий хранения | Сбой локального хранения не ломает Home/SQLCipher, ошибка видна в диагностике |
| AB-08 | CI и Native Android | TS/Jest/SkSL/Android и browser UI PASS. Реальные FPS/GC/thermal/battery отдельно, с **NOT RUN** для непроверенного устройства |

## Реальная процедура замера после APK

Записать: APK build SHA, Android/телефон, яркость %, refresh Hz, сеть и список сторонних фоновых задач. Для каждой пары *live → static* измерить одинаковые сценарии: пустой Home 5–10 мин, длинный чат 5–10 мин и активный потоковый ответ + ввод с Gboard. Выписать frame times p50/p95, jank%, CPU/GPU, память, расход батареи/температуру, субъективную отзывчивость. Затем поменять порядок (*static → live*) для уменьшения погрешности по прогреву. Если perf profiler недоступен — отметить конкретные значения **NOT RUN**. Не объявлять «экономию N%» без физических измерений.

**Готовность:** спецификация определяет ожидаемое поведение; CI и real-device QA отмечать только по результатам, а не по наличию исходников.
