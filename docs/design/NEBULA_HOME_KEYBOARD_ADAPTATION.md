# PersAI Nebula · клавиатура и свободное пространство Home

**22.10.2026 · исправление после проверки на Android**. Основание: пользователь прислал скриншот Home с открытой русской клавиатурой и черновиком «При»: большая живая сфера B+C обрезается панелью ввода. Скриншот подтверждает UX-дефект, но не доказывает поломку GPU или компонента Skia.

## Причина

В `HomeScreen.tsx` размер декоративной сферы фиксируется **по ширине** `Math.min(320, Math.max(200, width - 48))`, а `ListEmptyComponent` остаётся центрированным с `flex:1` даже в сжатой Android области `adjustResize`. Состояние открытой клавиатуры не учитывается. Скриншот показывает обрезанную сферу; при каждом наборе текста это портит композицию.

## Нормативное решение и инварианты

1. **Chat-first keyboard policy:** при получении фокуса `PromptInput` на Home **немедленно размонтировать декоративную большую сферу**. Это устраняет конфликт ещё до того, как Android закончит анимацию клавиатуры.
2. Отслеживать реальные события `Keyboard.keyboardDidShow / keyboardDidHide` с очисткой обработчиков при размонтировании Home. `keyboardDidHide` возвращает обычную сцену **даже если Android оставил фокус TextInput** (например, системная кнопка «Назад»), а `keyboardDidShow` скрывает сферу, если клавиатура была открыта другим способом.
3. Пока клавиатура видна, **не отображать также маленький декоративный status orb в нижнем блоке чата**. Это уменьшает GPU-нагрузку и исключает визуальное перекрытие текста; текстовый статус генерации/диктовки и кнопки остаются.
4. При закрытии клавиатуры и пустом диалоге восстановить большую анимированную B+C-сферу **без потери исходного REF-ORB-B, пяти мембран, фазовой нити и скоростей ядра/нити**. Нельзя заменить её плоским градиентным кругом.
5. **Ввод, отправка, нормализация, диктовка, текст черновика, история диалогов, переключение вкладок, SQLCipher и биометрия не меняются.** Экран «PersAI · Защищено» явно исключён из scope.
6. Уважать Android системные insets, 3-кнопочную/жестовую навигацию и клавиатуры с разной высотой. Не задавать фиксированную высоту клавиатуры и не навешивать новый абсолютный layout поверх composer.
7. По окончании, кроме Jest/TypeScript/SkSL/Native Android, прогнать Playwright/browser UI при ширине **320, 390, 768** и реальный APK на Android с Gboard/другой IME.

## Приёмочные критерии

| Сценарий | Действие | Ожидаемое |
| --- | --- | --- |
| KB-01 | Пустой чат, клавиатура закрыта | Большая B+C в полном размере, живой Skia, без чёрного диска |
| KB-02 | Тапнуть «Спросить у ИИ…», Android открывает клавиатуру | Не показывается большая/малая декоративная сфера, поле и кнопки доступны, черновик не сброшен |
| KB-03 | Нажать системное «Назад» (только закрыть IME, Home остаётся) | Сфера вернулась; повторное открытие IME снова скрывает её |
| KB-04 | Отправить сообщение, пока IME открыта | Черновик/отправка работают, LLM не отменяется, генерация не перекрыта сферой |
| KB-05 | Открывать историю и переходить Home ↔ Memory ↔ Settings | Никаких остаточных слушателей keyboard, CPU/GPU не работают в скрытых вкладках |
| KB-06 | Переключить язык/тип IME, повернуть экран, изменить высоту клавиатуры | Нет фиксированной пиксельной зависимости, composer не уходит под системную клавиатуру |
| KB-07 | Android Reduce Motion и background | Отсутствует фоновый shader clock, исходный качественный статичный кадр доступен вне режима редактирования |

## Результат / ограничения

Код и тесты должны быть в отдельном PR; **проход CI не означает подтверждённую native IME приёмку**. Сценарий KB-06 обязательно проверять физическим устройством. Не менять AppLock и независимые экраны приложения.
