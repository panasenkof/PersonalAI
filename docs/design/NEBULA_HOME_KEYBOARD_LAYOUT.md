# Nebula Home — адаптация сферы к клавиатуре и доступной высоте

**22.10.2026.** Репродукция: скриншот реального Android PersAI на тёмной главной с Gboard и введённым «При». Большая B+C сфера обрезана верхней кромкой composer (виден лишь верх объекта). Это нарушение HOME-04 в [сценарии интеграции](NEBULA_HOME_NATIVE_INTEGRATION.md), а не недостаток художественного Skia.

## Причина в коде

- `artworkSize = min(320, max(200, width - 48))` не зависит от высоты списка, клавиатуры или фокуса ввода.
- `ListEmptyComponent` с `flex:1` продолжает размещать крупную сферу, когда `KeyboardAvoidingView` сократил высоту `FlatList`.
- `onContentSizeChange → scrollToEnd` выполняется даже при пустом списке и может сдвинуть приветственный рисунок за границу viewport.
- Большая сфера не обязана быть видна при наборе текста: **приоритет у содержимого чата и composer**.

## Принятые правила

1. Когда клавиатура открывается **или** поле `PromptInput` получает фокус, большая сфера переключается на компактный размер `≤96 dp`. В частности при узком/маленьком viewport и `size<96` пропускается вовсе, чтобы не закрывать историю/ввод; после закрытия клавиатуры возвращается исходная B+C сфера.
2. В расслабленном пустом чате большая сфера подбирается по ширине **и измеренной высоте списка** с безопасными внешними отступами: верхнее ограничение 320dp, нижний адаптивный минимум не должен перекрывать composer. `onLayout` списка измеряется без дополнительных native permissions и без навязывания global keyboard handling.
3. `onContentSizeChange` прокручивает к последнему сообщению **только при наличии настоящих строк/потока ответа**; на пустом чате прокрутки быть не должно.
4. При активном чате в режиме ввода декоративный status orb показывается лишь при реальном состоянии `thinking/responding/listening/transcribing` и лишь когда список имеет достаточный viewport. Прячем в первую очередь декоративный GPU-слой, не состояние приложения и не работу агента. Кнопки «Файл», «Камера», «Голос», «Улучшить», «Отправить» сохраняют прежнее действие.
5. `PromptInput` получает *необязательный* `onFocusChange`; это UI-сигнал, не отправка текста в LLM и не изменение работы микрофона. Android событие `keyboardDidShow/Hide` страхует случаи переключения полей и аппаратной клавиатуры.
6. Подписи фаз/статус отвечают реальным событиям, тёмный Home, исконная B+C текстура и нити сохраняются. **Не менять экран защищённого доступа**, Memory/Settings, биометрию, LLM, сохранение заметок.

## Приёмочные сценарии

- **IME-01:** Android, пустой чат, Gboard закрыта: большая B+C сфера целиком в доступной области над composer; экран не скроллится самопроизвольно.
- **IME-02:** тап «Спросить у ИИ…», Gboard открыта: переход на компактную сферу ≤96dp, она не перекрывает шапку/клавиатуру/ввод. При недостатке высоты сферы вообще нет. Фокус и черновик остаются.
- **IME-03:** тап «Назад» для скрытия Gboard: когда поле ещё в фокусе, интерфейс сохраняет компактность до следующего корректного события; при явном `keyboardDidHide` после открытия восстанавливается обычная композиция без рывка.
- **IME-04:** одна-две строки сообщений или потоковый ответ + открытая Gboard: нет большой сферы, сообщения скроллятся, кнопка «Стоп» не перекрыта, рендер переписки продолжается при смене вкладок.
- **IME-05:** размеры 320/390/430 dp, трёхкнопочная навигация и gestures, системный Reduce Motion, светлая системная тема — никакого выхода элементов за видимую область.
- **IME-06:** unit/contract guard, Playwright браузерный UX, TS/Jest, SkSL и Android SQLCipher release workflow; **реальную IME-геометрию устройства проверить после сборки APK**, CI без устройства не является окончательной приёмкой.
