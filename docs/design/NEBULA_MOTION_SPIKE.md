# NebulaCore — технический spike и план нативной проверки

**Статус на 22.10.2026:** историческая спецификация исследования; Skia B+C и живой Home уже реализованы (#77–93), стабилизация #96 проходит отдельную приёмку. Не повторять spike как обязательный следующий шаг. Не завершены измерения Android FPS/battery и финальная визуальная приёмка. Актуальная очередь: [PLAN](../../PLAN.md), [U0–U5](../../Plans/UI_DELIVERY.md). Ниже сохраняются исходные альтернативы и критерии исследования.

## Задача

Показать **объёмную органическую переливающуюся сферу**, похожую на REF-ORB-B: 3–5 слоёв-мембран, сложный блик/рефракция, внутреннее перемещение энергии, морфология границы и реакция на фазу LLM/голоса. Простое увеличение масштаба PNG или один круговой градиент — **не принимаются**.

Изолированный **HTML Canvas2D motion-study**: [nebula-core-spike.html](../prototypes/nebula-core-spike.html). Он исследует рисунок/morph/фон и предоставляет статичные fallback-кадры. **Это браузерный прототип, не доказательство совместимости с React Native, производительности Android или качества финального шейдера.** Его нельзя использовать как скриншот-фальшивку вместо компонента.

## Состояния и контроллер

Уже добавлено (задача 88 foundation): `mobile/src/design/nebula/motion.ts` с `NebulaPhase`, `NebulaEnvironment`, `resolveNebulaScene` и таймингами. Микрофон/LLM истинный источник состояния, `reduceMotion`, `appActive` и питание управляют quality. `starFlight` — только явный `requestedStarFlight` в foreground idle, не перезапускается при каждом запросе.

## Оценка вариантов для Android (не выдавать предположения за замеры)

| Путь | Визуальное качество | Технический риск | Обязательная проверка |
| --- | --- | --- | --- |
| A. Skia runtime shader/paths | Потенциально лучший динамический морф и цвет; близок референсу при хорошем материале | Дополнительный native пакет, GPU/thermal, версионирование Expo, shader support | Отдельная native release-сборка, Android GLES/Vulkan/драйверы, 48dp и 120dp orb, 60fps, thermal/battery |
| B. Экспорт качественных подготовленных кадров/видеосегментов | Результат можно художественно довести до REF-ORB-B; высокая предсказуемость | Размер ассетов, синхронизация фаз, memory pressure, seamless loop, альфа-канал | FPS при списке сообщений, seek/loop, reduced-motion static кадр, pause on background |
| C. Комбинация B + Reanimated transitions/UI | Сохраняет художественное ядро из кадров, контролирует мягкие переходы | Пакет Reanimated и Worklets, запуск новой native версии, reset состояния | Только SDK-совместимые версии, устройства ниже среднего, возврат из background |

**Критичный факт о SDK 57:** Expo 57 основан на RN 0.86.3 и Worklets 0.10.1; Reanimated SDK-рекомендация 4.5.x, не менять Worklets на 0.12 без отдельного апгрейда. Expo SDK 57 рекомендует Skia 2.6.2. В [expo/expo#50733](https://github.com/expo/expo/issues/50733) воспроизведена несовместимость **метода `makeImageFromView`** с React Native 0.86 из-за устаревшего вызова `dispatchOverflowDraw`; автор сообщает о фиксе в Skia >=2.11.1 / SDK 58. Это **не доказывает**, что любой shader Skia 2.6.2 не работает, но является основанием для изолированного теста и отказа от широкого upgrade в этом PR. [Expo Skia SDK57](https://docs.expo.dev/versions/v57.0.0/sdk/skia/) · [Expo 57 changelog](https://expo.dev/changelog/sdk-57) · [Reanimated Expo](https://docs.expo.dev/versions/latest/sdk/reanimated/).

**Текущий уточнённый художественный выбор:** [B (детализация и объём) + C (мембраны/движение)](NEBULA_HYBRID_BC_DECISION.md). Подготовлен [QA-контракт для Skia-кандидата](NEBULA_SKIA_LAB_QA.md). Изолированный нативный код исследования НЕ заменяет требование Android release-проверки. Видео B остаётся альтернативой. При появлении версии Skia подтверждать GPU-совместимость и компиляцию SkSL реальным тестом.

## Spike 1 — исследование реального устройства

1. Подтвердить оригиналы SHA-256 и неизменность пикселей базовых ассетов.
2. Создать изолированный `NebulaCoreNativeExperiment` в **отдельном PR**, без подключения к `HomeScreen`; по `__DEV__` route или отдельной тестовой APK сборке.
3. Проверить как минимум 2 пути: A (Skia 2.6.2 *без* `makeImageFromView`, либо оправданное обновление после native compatibility) и B (высококачественный pre-render loop). Для каждой альтернативы сохранить 5–10 секунд записи на устройстве в одинаковой яркости/размере.
4. Измерить среднюю и p95 frame time / пропуски кадров, потребление памяти и энергозатраты при `idle` 5 минут и в активном чате, масштаб 44dp и 154dp, 1x/1.5x font, два типовых Android профиля (реальный телефон + более слабый профайл при наличии).
5. Проверить быстрый вход/выход, hardware back, OS remove animations, low power, работу речи/VAD, переключение вкладок и одновременно потоковый ответ.
6. Сравнить визуально REF-ORB-B с обеими анимациями **side-by-side**. Нельзя считать победой только FPS при радикально упрощённом рисунке.
7. Выбрать вариант **по подтверждённому качеству + стабильности**, затем открыть отдельный внедренческий PR с ограниченным rollout. При невозможности выполнить требования — оформить explicit user decision, не скрывать упрощение.

## Визуальные пороги и честные ограничения

- **Цель** — преимущественно около 60 FPS на целевом Android в foreground, без деградации печати, списка сообщений и распознавания; числовое измерение обязательно до «готово».
- Не создавать непрерывные `requestAnimationFrame` фонового WebView в production; браузерный canvas — **только исследование**.
- Предусмотреть полный статичный REF-ORB-B fallback (не банальный кружок); статичное изображение не должно мешать ответам агента.
- В `thinking` показывать реальный краткий статус без ложного прогресса; `listening` только с реальным audio permit.
- Star flight только старт/новый чат/согласованное событие, до 2500мс, корректное отключение при reduce motion.

### Обязательная диагностика зависшего рендера (22.10.2026)

Нельзя молча показывать fallback как будто он и есть рабочая анимация. Если пользователь видит неподвижную сферу, показывать причину: Reduce Motion, background, экономия, shader disabled, compile failed, image pending или special offline/error. При полноценном рендере выводить clock ticks Skia и экспериментальный ускоренный режим для распознавания движения. В CI компилировать SkSL через CanvasKit/WASM, затем всё равно проверять реальный Android GPU. Владелец сообщил о статичной лаборатории; root cause **не подтверждён**, поэтому проблема остаётся открытой до APK.
