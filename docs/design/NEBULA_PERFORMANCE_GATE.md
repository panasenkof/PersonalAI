# Nebula Android · Performance и battery gate

**Решение владельца (22.10.2026):** полноценные замеры CPU/GPU/энергопотребления **после внедрения основных компонентов**, которые создают нагрузку: native Skia core B+C, космический фон, диалог с виртуализированной историей, потоковая генерация, ввод/клавиатура и голосовые состояния. **Не требуется ждать** полной переделки Memory/Settings/всего бэклога.

## Проверки по этапам

### До интеграции — эталон baseline (коротко, не блокировать Home-макет)
- Записать commit SHA/APK, устройство/Android, разрешение и refresh rate, brightness, power saver, foreground/background, Wi-Fi/мобильную сеть.
- Замерить baseline на текущем Home: startup, idle 5 min и прокрутка длинного диалога. Без этого нельзя корректно говорить, что Skia стала расходовать на 30% больше/меньше.
- Не считать измерения из браузера или отдельной SkiaLab окончательными.

### Каждый PR с новыми GPU/анимационными элементами — короткий guard
- Запуск/закрытие приложения, возврат из background; без crash, бесконечного shader clock в фоне, утечек и разрывов связи с mic/LLM.
- Проверка одного слабого Android-профиля при возможности, иначе явно пометка NOT RUN.
- Проверка reduced-motion, low-power, большой/малой сферы и keyboard scrolling, базовые frame-time log и thermal.
- CI: SkSL CanvasKit compilation, TypeScript/Jest, Android native release build и UI smoke. Эти проверки **не заменяют** реальные показатели батареи.

### Сразу после объединения основных нагружающих компонентов Home — **основной gate перед rollout**
Проверить на том же телефоне, brightness, сети и средней тепловой точке:
1. 10–15 минут Home idle с большой сферой и фоном.
2. 10–15 минут активного чата: длинная история, скролл, streaming ответа, typing/keyboard, удаление/добавление preview вложений.
3. Голосовой ввод и транскрипция во время работы сферы, возвращение из background, пауза.
4. Reduced-motion, low-power и статичный REF-ORB-B fallback (контур состояния если shader доступен).
5. A/B `feature flag`: **новый Home Nebula ON vs baseline/OFF** без очистки данных, одинаковый сценарий.

Снять **FPS распределение, frame time p50/p95 и jank, CPU/GPU, память/GC, батарейный разряд (нормализованный по времени), нагрев/thermal throttling**, загрузку старта и scroll latency. Отчёт: реальные значения с единицами и устройством, разность baseline↔ON; необнаруженные показатели честно отмечать NOT RUN.

## Решения при регрессии

- Цель плавности: ~60 FPS там, где устройство позволяет; ориентир времени кадра **16.7 мс для 60 Гц**, но для дисплея 90/120 Гц пересчитать отдельно; важны p95 и jank.
- **Никаких придуманных процентов батареи:** допустимый порог выбрать из измеренного baseline и пользовательских ожиданий до публичного rollout.
- Если анимация влияет на диалог, VAD/голос или батарею: замерить вклад **core / фон / нить** отдельно через profile toggles, убрать непреднамеренные скрытые циклы; оставить качественный статичный fallback без визуального упрощения эталона.
- Не понижать молча детализацию сложной плазменной сферы, не заменять её градиентным кругом ради FPS. Варианты — частота кадров, pause background, ограничение размеров/частоты, video fallback **только после замеров и согласования**.
- Выход из этапа: таблица baseline vs ON, видео с устройства, результаты и решение о rollout. Зафиксировать в `docs/design/` и следовать через PR.

**Важно:** этап запуска измерений привязан к реально **соединённому Home + GPU core + звёздный фон + потоковый чат**, а не к номеру PR и не к окончанию всех функций PersAI.
