# PersAI Nebula — утверждение сферы и переход к рабочему интерфейсу

**Решение владельца, 22.10.2026:** «отлично, оставляем такой дизайн сферы». **Художественный вид текущей Nebula B+C утверждён**, включая формат неоновой фазовой нити. **Дальнейшие эксперименты с внешностью сферы не должны блокировать UI-миграцию.**

## 1. Зафиксированный художественный образец

Источник: [NEBULA_DUAL_SPEED_THINKING.md](NEBULA_DUAL_SPEED_THINKING.md) и [NEBULA_HYBRID_BC_DECISION.md](NEBULA_HYBRID_BC_DECISION.md); графика — неизменяемый `REF-ORB-B` из [ZIP](references/README.md), launcher icon — отдельный `REF-ICON-A`.

- **Сфера B+C**: насыщенный объёмный стеклянно-плазменный объект, не сводить к одномерному gradient/circle/scale PNG; сохранить многослойность, блики, сложные мембраны, деликатно изменяемый силуэт.
- **Основная скорость сферы ×5**, фазовая тонкая неоновая нить движется **на отдельных часах ×1**, повторяя фактическую деформируемую границу.
- В `idle` нити нет. `listening`, `transcribing`, `thinking`, `responding`, `offline`, `error` используют профили из `phaseFilament.ts`; `offline/error` статичны.
- `thinking`: усиленная примерно на 20% деформация, едва заметное радиальное дыхание, более выраженный, но не ускоренный пульс струны. Сохранять комфортную частоту — не превращать в вспышки.
- **Фон**: сложная космическая глубина и умеренная динамика со звёздами, без постоянного «варпа» за читаемым текстом. Референс касается художественного оформления, не оправдывает постоянный GPU background animation.
- Утверждены **внешность, характер движения и различие состояний**, но **не** FPS/энергопотребление, все размеры, работу в длительном чате, фоновые сценарии и доступность — их нужно измерить.

**Change control:** запрещено по инициативе ИИ менять форму, палитру или скорость, искать новые варианты сферы, «упрощать для ускорения» или заменять проверенные ассеты. Необходимое изменение допускается только как отдельное предложение с side-by-side сравнением, замерами и явным согласованием с владельцем.

## 3. Очередность следующего этапа (86 → 87 → 88/89 → 90)

### Шаг 1 — P0: закончить композицию главной (86, **без переделки сферы**)

На базе утверждённого **Nebula v0.3** подготовить полный интерактивный макет главной с состояниями:
- **Основной чат** занимает максимум пространства; нет плакатных фраз «Чем помочь сегодня?», «Чего хочет пользователь» и перечня технических возможностей.
- Компактная шапка (история, новый чат, модель/подключение) и **закреплённый composer** (ввод, очистка, голос, «Улучшить/Исходный», плюс/вложения, отправить). Кнопки соответствуют реально доступным операциям.
- Сфера **не занимает значительную площадь над сообщениями**: в пустом чате — качественный фирменный объект; во время диалога — компактный статусный элемент, который не мешает чтению, доступности или набору.
- Реальные состояния: нет подключения, новый чат, активный диалог, LLM thinking/responding/error, listening/transcribing, ввод/клавиатура, длинная история, файлы (только как сценарий до функциональной спецификации), восстановление после background.
- Макет учитывает будущие automations, память, поиск по изображениям, локальные/облачные LLM, медиа и расширяемые tools **без новых обязательных нижних вкладок**.
- Сделать редактируемый Figma v0.3 при доступном лимите и/или честный нативный/интерактивный прототип с обязательной сверкой с утверждённым макетом. **Наличие Figma не выдавать за готовую Android реализацию.**

**Критерий:** владелец принимает компоновку основного экрана отдельно от уже принятой сферы.

### Шаг 2 — P0: целевой UX-аудит (87)

После компоновки сравнить текущие Home, Memory, Settings, import, media и настройки с новым стандартом. Отдельно:
- 320/360/390/430 dp, увеличенный текст 1.3×/1.5×, жестовая и трёхкнопочная навигация, `SafeAreaInsets`, клавиатура и нижняя панель Android.
- Обнаружимость главных действий, преждевременная прокрутка, обрезка, накладывающиеся кнопки, лишние статусы и дублированные формы настроек.
- Нет потери истории при смене вкладок, локальная память/шифрование доступны как раньше; задержки voice/LLM при анимации.
- Итог: screenshots + перечень дефектов P0/P1/P2 и таблица «исправлять в каком PR». Предварительный аудит исходников 21.10 — **не замена нативному Android QA**.

### Шаг 3 — P1: завершить дизайн-систему (88, отдельный PR)

Токены из `mobile/src/design/nebula/tokens.ts`, базовые `components.tsx` и motion contract использовать для:
- Шапки, composer, кнопок, текстовых ролей, аватаров, лент сообщений, состояний loading/empty/error, карточек и модальных sheets.
- Light/Dark/Reduce Motion, TalkBack/labels, клик-область ≥48dp, dynamic font, `KeyboardAvoidingView`/insets, lazy asset-loading и управление аппаратным back.
- Подключать `NebulaSkiaExperiment` в production только после адаптации для Home и измерений на устройстве; убрать diagnostic info/debug counters и lab controls из основного UI. Никаких случайных background shader loops.
- `AGENTS.md` и UI-скилл применять как обязательный gate к каждому UI PR.

### Шаг 4 — P1: последовательно переносить экраны (89)

1. **Home/чат:** сначала header+composer+диалог; затем неброская сфера в пустом чате/статусе, связанная с истинными mic/LLM состояниями; использовать feature flag/rollback для Skia.
2. **Память:** понятное дерево/список, поиск, вложения, batch действия. Не менять структуры хранения/SQLCipher под видом UI.
3. **Настройки:** компактное меню разделов, вложенные формы; сохранить текущие подключение моделей/ключи, лимиты, поиск, голос, журналы.
4. **Импорт/мультимедиа:** UI системных окон и превью; мультимодальная передача — отдельная проверенная OpenSpec, с явными согласиями и пределами приватности.

Каждый этап отдельный PR, только с реально работающими действиями, без заглушек, которые выглядят рабочими.

### Шаг 5 — обязательный QA gate (90, параллельно каждому PR)

- GitHub TypeScript/Jest/SkSL/Android build + Playwright screenshots и нативный APK smoke; старые сценарии диалога/памяти/настроек не регрессируют.
- Реальная система Android: Android software keyboard, вырез/навигация, portrait/landscape где допустимо, длинная русская строка, заполненные сообщения и высокий DPI.
- Контролируемая анимация: FPS p50/p95, терморежим/энергия, AppState, уменьшение движения. Основной чат остаётся отзывчивым на бюджетном телефоне, анимация не должна мешать микрофону и streaming.
- Отчёт PASS / FAIL / NOT RUN; зелёный CI без visual QA нельзя объявлять финальной приёмкой.

**Первым исполнить пункт 86:** `feat/nebula-home-composition`, спецификация и полнофункциональный макет Home с согласованной сферой; после принятия макета — короткий targeted аудит (87), затем перенос Home с feature flag (88/89) и regression QA (90).
