# Skia B+C lab — техническая спецификация и матрица проверки

**Цель:** исследовательская нативная реализация утверждённого [решения B+C](NEBULA_HYBRID_BC_DECISION.md) на Expo 57. **Не является** финальным брендовым шейдером, не подключена к рабочему чату.

## Исходные ограничения

- Исполнение через `@shopify/react-native-skia@2.6.2` + `react-native-reanimated@4.5.1`, `react-native-worklets@0.10.1` уже используется в проекте.
- Не использовать `makeImageFromView` / snapshot API: в `expo/expo#50733` зафиксирована несовместимость с RN 0.86, не относящаяся непосредственно к SkSL RuntimeEffect.
- В оригинальном ZIP `REF-ORB-B.jfif` сохраняется побайтово; из него **только производным этапом** создаётся `nebula-orb-ref-b.png`, исходный SHA-256 строго контролируется. Не помещать исходник внутрь шейдерного текста и не менять его исходную палитру.
- В `hybridShader.ts` исходная текстура остаётся источником насыщенности и объёма; пять световых слоёв, рефракция, caustics, specular rim и сложный органический силуэт генерируются SkSL отдельно. Плоский круг как замена недопустим.
- В `NebulaSkiaExperiment.tsx` реальный phase получает извне, `resolveNebulaScene` запрещает фоновые / reduce-motion / power-constrained эффекты; в static mode показывается производный **качественный оригинал**, а не декоративный плоский круг.
- Большая сфера показывается в лабе; основной экран, ввод, память, многомедийные вложения не меняются.

## Порядок визуальной оценки владельцем

1. Скачать канонические REF-ORB-B и REF-UI-C из ZIP.
2. Подготовить одинаковые Android-записи B(video) и C(Skia) при phase idle и thinking; отправить side-by-side, без компрессии главных деталей, по возможности одинаковый цветовой профиль.
3. По каждой записи оценить шкалой 1–5: **объём и детализация**, **насыщенность**, **живость мембран**, **сходство с референсом**, **ненавязчивость фона**. Три обязательных первых параметра не должны проигрывать исходному B.
4. Если детали B пропадают, не подменять решение фразой «шэйдер работает» — доработать материалы, отрисовку/исходники или оставить видео-кандидат.
5. После решения пользователя — отдельный внедренческий PR с ограниченным rollout.

```bash
npx expo install --check

npx jest --ci --runInBand
# Нужны Android SDK, установленный release APK, реальная тестовая сборка.
```

`NebulaSkiaExperiment` доступен в лаборатории через вложенный маршрут `NebulaLab` только **после установки APK, содержащего соответствующий навигационный PR**; пользовательский Home и три вкладки не меняются. **Публикация кода в репозитории не является подтверждением работающей анимации.**

**Важный нюанс:** поддержку shader uniforms и точный результат компиляции SkSL можно подтвердить только рендером в нативной среде; Jest не является компилятором SkSL.

### Диагностика отсутствующей анимации (22.10.2026)

После сообщения пользователя «в лаборатории нет анимации» выявлена проблема наблюдаемости: прежняя реализация **молча показывала статичный REF-ORB-B**, если SkSL не скомпилировался, изображение не успело загрузиться, Android сообщил `AppState.currentState=null`, Reduce Motion активен или выбран режим offline/error. Это **возможные причины**, ни одна из них ещё не подтверждена на конкретном телефоне.

В лабораторном корректирующем PR добавляются: явная метка причины статичного режима, счётчик фактического Skia `useClock` (шаг 750 мс), ускоренная демонстрация движения ×2,5 и CI-компиляция SkSL в CanvasKit WASM. Принцип сохраняется: high-fidelity исходный постер используется как fallback, а не заменяется примитивным кругом. При получении нового APK сначала выбрать `idle`, отключить лабораторную «Экономию» и «Reduce Motion», проверить системное **Уменьшение анимации**, затем сравнить текстовый статус и счётчик. Если написано «SkSL не скомпилировался», приложить экран и системные логи (без приватных данных).

**Ограничение:** CanvasKit в CI проверяет синтаксис SkSL, а не реальное GPU-исполнение Android. Переход статуса в «animated» и рост времени подтверждают запуск часов/компиляцию, но не доказывают художественную приёмку и видимую деформацию. Если при росте времени картинка неподвижна, исправить работу uniform/Skia GPU и проверить кадры до принятия результата.



## Утверждено 22.10.2026: контурная нить и режим ×5

[Подробная спецификация](NEBULA_STATE_FILAMENT_SPEC.md) теперь заменяет предыдущий диагностический ×2,5: базовая скорость ×1, лабораторный ускоритель ×5 **только по времени**, без повышения амплитуды/яркости. В `idle` нити нет; в listening, transcribing, thinking, responding, offline, error нить следует динамической границе сферы; `offline/error` остаются статичными, но окрашенными. После обновления APK дополнительно проверить положение, свечение, 44/168dp, шесть цветов, выключение анимации и восстановление после фонового режима. Реальная Android-проверка и пользовательская оценка обязательны.


## 22.10.2026 · проверка независимых скоростей ×5 / ×1

Нормативная спецификация: [NEBULA_DUAL_SPEED_THINKING.md](NEBULA_DUAL_SPEED_THINKING.md). В новой APK по умолчанию сфера B+C должна двигаться с ×5, но фазовая струна — со своим ×1. Проверить на listening, transcribing, thinking и responding, что пульс нити **не ускоряется вместе со сферой** и повторяет её быстрый контур. Для сравнения «Сфера ×1 — сравнить» временно замедляет лишь сферу; нить не меняется. В thinking деформация сферы +~20% и отчётливее пульсирование нити. При offline/error/Reduce Motion — обе временные координаты статичны. Нить остаётся тонкой, но различимой на насыщенной плазме. Проверка в Android APK обязательна до художественной приёмки.
