# PersAI Nebula — утверждённый визуальный контракт v1.0

**Статус:** утверждено пользователем 21.10.2026 как целевой **визуальный язык и UX-поведение**. Это **нормативные ограничения для проектирования и реализации**, но НЕ заявление, что интерфейс, анимации или мультимодальный LLM-чат уже реализованы. Поддерживать в одном репозитории совместно с [PLAN.md](../../PLAN.md), [UI_UX_REDESIGN.md](../UI_UX_REDESIGN.md) и OpenSpec.

**Область:** React Native / Expo 57, Android в первую очередь. Не менять стек, архитектуру хранилища, биометрию или доступ LLM под видом редизайна. Вносить UI поэтапно. **Никакой самостоятельной подмены дизайна на «простой кружок», минималистичный логотип, статическую заглушку или стандартный экран с плитками.**

## 1. Общая художественная система

**Концепция:** *living cosmic glass / Nebula*. Серьёзный премиальный ИИ-помощник, одновременно футуристичный и удобный для продолжительных разговоров. Ощущение глубины, энергии и движения, без «игровой» перегруженности.

| Свойство | Обязательно (SHALL) | Запрещено (SHALL NOT) |
| --- | --- | --- |
| Тематика | Тёмный космический фон, слоистые полупрозрачные подложки, глубокие синевато-фиолетовые тени, умеренный неон | Плоский белый редизайн как первичная версия, монохромные серые карточки |
| Фокус | Разговор и вложения; эффектная сфера появляется лишь там, где не вытесняет сообщения | Постоянный центральный «шар» поверх чата, тёмные непроницаемые панели над текстом |
| Графика | Глянцевые объёмные сферы, внутренний градиент, блики, вихревые/мембранные структуры, мягкие частицы | «Круг с градиентом», один border/glow, псевдо-анимация вращения плоской картинки как окончательный результат |
| Цвет | Indigo / violet / cyan / electric blue на navy/black; красный/янтарный/зелёный только по смыслу состояния | Красочность в каждой карточке, нечитабельный красный на фиолетовом, кислотный постоянный glow |
| Материалы | Glass-like карточки с контрастным текстом, тонкой кромкой и локальной глубиной | Вездесущий blur на весь экран, текст прямо поверх активно движущихся ярких звёзд |
| Типографика | Чёткий, нейтральный гротеск; типовые размеры с масштабированием | «Киберпанк» декоративным шрифтом, мелкие подписи для обязательной информации |

**Стартовые цветовые токены для прототипа** (подлежат проверке контраста и настройке в дизайн-системе, не требуют точного совпадения каждого пикселя): `canvas #070D20`, `surface #14213D`, `elevated #1D2E51`, `text #F6F8FF`, `secondary #ABBAD8`, `violet #795BFF`, `cyan #30CAED`, `electric #376BF2`, `success #2FD3A4`, `warning #FFC074`, `danger #F084A1`. Для всех токенов — semantic aliases, dark/light/high-contrast и роли элементов вместо захардкоженных значений в каждом экране.

Принцип: **богатство визуального объекта и фона не должно превращаться в богатство интерфейсных блоков**. Информационная иерархия — компактная.

## 2. Иконка и фирменная идентичность — REF-ICON-A

### Геометрия и материалы

- Финальный замысел: насыщенная большая космическая сфера **внутри скруглённой квадратной поверхности**, не нейросеть, не буква «P», не чат-пузырь.
- Сфера не меньше ~58–72% визуального диаметра композиции исходной квадратной плитки; светлый энергетический центр, сферические стеклянные слои, периферические голубые/сиреневые отсветы, тонкие орбитальные следы, звёздные точки на глубоким navy фоне.
- Блики и сложность допустимы для **полноразмерной** иконки; на Android launcher должна сохраняться читаемость в 48dp. Отдельный small-size вариант может иметь **меньше микро-звёзд**, но **не менять форму сферы на плоский диск**.
- Не добавлять букву/надпись `PersAI`, корону, псевдо-подписку, чужие логотипы или не предусмотренные пользователем символы.
- Android adaptive icon: подготовить foreground, background, monochrome (Android themed) и `splash`; важные детали — в безопасной зоне по Android mask, проверить круговую/квадратную/скруглённую маски, тёмный/светлый лаунчер, 48/72/108dp. **Monochrome** — системное исключение из цветного бренда, а не замена основной иконки.
- Экран загрузки: крупный отполированный REF-ICON-A/REF-ORB-B, без обещаний работающего интерфейса при ещё не завершённой инициализации. Использовать оптимизированный PNG/WebP/AVIF, исходник сохранять без пересжатия.

### Проверка иконки

1. Side-by-side показать оригинал REF-ICON-A, финальную full-color иконку и её масштаб 48dp.
2. Убедиться, что вне safe zone не обрезаны сфера, блики, орбитальные дуги и важные элементы; фон не даёт белых углов.
3. Проверить качество рендера в настоящем release APK, а не только в IDE превью. Если не хватает качества — **не принимать**.

## 3. «Живой» объект — REF-ORB-B, не примитивная окружность

Компонент `NebulaCore` — собственный высококачественный visual system, а не `AvatarCircle`.

**Видимые части:** ядро с глубиной; 3–5 полупрозрачных плавно переплетающихся органических слоёв/мембран; разные скорости движения внутренних бликов; плавно сдвигающиеся сине-лиловые оттенки; неидеально круглый динамический силуэт без резких скачков; мягкое внешнее сияние, небольшое поле частиц и атмосфера. Это художественная схема; допускаются другие реализации, **если side-by-side визуально приближает REF-ORB-B, а не удешевляет его**.

**Состояния и Motion Contract**

| State | Сигнал | Наблюдаемое поведение | Ориентир по времени |
| --- | --- | --- | --- |
| `idle` | нет работы | Медленное «дыхание» (размер/яркость), органическое изменение формы, внутреннее движение цвета без мельтешения | цикл 6–12 с |
| `listening` | запись микрофона начата | Более выразительная оболочка, мягкая пульсация/волны **по уровню звука**, явная надпись/иконка «Идёт запись», завершение по VAD | волны 200–700 мс, сглаженные |
| `transcribing` | распознавание голоса | Плавный внутренний поток и короткая текстовая метка, запись не показывается как активная | 1–2 с на цикл |
| `thinking` | LLM запрос или инструмент | Усиление завихрения света, частицы/небольшая орбитальная динамика, статусы работы без ложного прогресса | 2–5 с на цикл |
| `responding` | потоковый ответ | Спокойное активное свечение, без смены экрана; текст читается сразу | мягкий переход ≤350 мс |
| `offline` | сеть/модель недоступна | Приглушение яркости + понятный текст ошибки; **не только цвет** | явное устойчивое состояние |
| `error` | операция не удалась | Короткий световой акцент + доступный текст с причиной и retry | анимация ≤400 мс |

События и состояния задаёт контроллер фактического состояния операции, **не сама случайная анимация**. Нельзя показывать `listening`, когда у Android нет разрешения на микрофон, или `thinking`, когда вызов уже завершился. `idle` на маленьком аватаре не обязан постоянно анимироваться: под основными сообщениями важнее батарея и читаемость.

**Motion accessibility:** `reduceMotion` / Android Remove animations → без бесконечных morph/parallax/star-flight, стабильная **качественная** иллюстрация финального кадра + статусы словами/иконками. Предусмотреть `lowMotion` для энергосбережения, фонового режима и медленного устройства. При сворачивании приложения таймеры, рендер и аудио-индикаторы не должны работать бесконечно без пользовательского согласия.

**Реализация — spike, не жёсткий приказ на библиотеку:** сравнить React Native Skia (динамические shader/path/gradients), Reanimated (состояние/жесты/motion), готовые последовательности качественно отрендеренных кадров как fallback. **Нельзя выбирать «простой gradient+scale круг» без отдельного одобрения.** GPU/энергопотребление измерить на реальном устройстве. Предварительная цель плавности: близко к 60 fps на целевом аппарате при открытом чате; допустимое снижение и компромиссы документировать до изменения качества изображения. Анимация никогда не должна блокировать клавиатуру, ScrollView, VAD или отображение токенов.

## 4. Космический фон и пролёт сквозь звёзды

1. Постоянный фон: глубокий navy → nearly black градиент, тонкие туманности, орбитальные штрихи, 2–3 слоя **редких** звёзд различного размера и глубины; для текстовых областей — затемнение/контрастный scrim.
2. **Idle:** медленный параллакс, слабое мерцание, малые смещения в несколько px, без «дождя из звёзд».
3. **Star flight**: заметный, но кратковременный пролёт (например, при запуске, создании нового чата или специально согласованном событии), примерно 1–2.5 с; не запускать на **каждое** сообщение и не крутить его бесконечно за чатом.
4. При открытой клавиатуре, активном чтении длинного ответа, screen reader, low power/reduce motion фон почти статичен. Разные скорости UI и фона не вызывают вертикального «уезда» экранных элементов.
5. Оптическая сложность находится **позади** содержимого; невзаимодействующие визуальные части должны иметь `pointerEvents="none"` / соответствующий механизм.
6. Не допускать резких вспышек/стробирования, мигания крупных областей, motion sickness. Отключение анимаций не отключает функцию чата.

## 5. Главный экран: максимум места для диалога

### Компоновка (приоритет P0)

- **Шапка:** компактный `PersAI` + выразительный **малый** значок сферы или статус; выбор текущего LLM; история/новый чат. Обычная цель — 52–64dp **без системного inset**; элементы не должны уходить за вырез экрана.
- **Центр:** виртуализированная лента сообщений, адаптирующаяся к системной клавиатуре; без гигантского приветствия «Чем помочь сегодня?», плиток «Попробовать», навязанных вопросов, постоянных справочных блоков, рекламы, больших индикаторов и декоративных заголовков. **Сфера крупным планом только в действительно пустом чате**, без перекрытия инпута, затем уменьшается/исчезает.
- **Сообщения:** компактные контрастные user/assistant bubble или свободный поток с чётким авторством; потоковый текст, markdown, code, таблицы, цитаты, ссылки и источники; по контексту могут идти attachment cards и галереи, но не декоративные карточки вместо простого текста.
- **Инпут (composer):** закреплён над keyboard/system bar. Текстовое поле, **+** (добавить), отдельно **микрофон**, отправить; существующая функция «Улучшить / исходный текст» остаётся доступной как второстепенная компактная action, не удалять из продукта. Ввод auto-grow до 4–6 строк, затем скролл внутри; никаких абсолютных координат кнопок по ширине экрана.
- **Preview перед отправкой:** миниатюры фото (по тапу открыть оригинал), чипы PDF/файлов с названием, MIME, размером и удалением **конкретного** элемента; несколько вложений и прокрутка миниатюр — без обрезания send/voice. Подписи для screen reader.
- **Чат + вложения:** варианты ответа агента — текст, изображение, файл/PDF, коллекция, подтверждаемое действие с кнопкой «Отменить». Изображения/файлы могут быть в истории без автоматического сохранения в память.
- **Навигация:** три назначения «Главная / Память / Настройки» остаются доступными. Разрешается компактная нижняя панель, автоскрытие при клавиатуре либо адаптивная компоновка только после UI-тестов; не подменять три главных назначения несколькими тайными маршрутами.

### Состояния `Composer` и сообщения

`empty`, `draft`, `hasAttachments`, `uploading`, `transcribing`, `sending`, `streaming`, `failedOneAttachment`, `failedEntireRequest`, `cancelled`, `budgetBlocked`, `offline`, `permissionsRequired`. Для каждого обязательны: состояние доступности кнопки Send, сохранение/очистка черновика, повторный запуск, объяснение пользователю, восстановление после возврата из другой вкладки.

Сценарии:
- Пользователь нажал **+** → bottom sheet: камера, галерея, файл/PDF, аудио/видео, URL; picker поддерживает разные файлы и отмену без потери текста. Вызов разрешений только когда нужен конкретный источник.
- Пользователь прикрепил **фото + PDF**, набрал текст → превью обоих вложений, можно удалить одно, отправить с одним запросом. Не требуется создавать заметку в памяти.
- Пользователь запросил «Что на фото?» → если подключённая LLM поддерживает vision, безопасно доставить данные; иначе предложить явно подписанный OCR/описание или объяснить ограничение, **не выдавать распознавание за факт без обработки**.
- Пользователь переключил вкладку во время ответа → история и поток не теряются; при возврате composer без повреждения, overlay не перекрывает системную навигацию.
- Голос: реальные permissions → слушает → VAD → текст → ручная нормализация/возврат исходного текста → отправка. Состояния и анимация синхронизированы с реальным распознаванием.

**Граница UI и функционала:** визуальная возможность добавить файл **НЕ** равна реализованной мультимодальной обработке. Для агента до UI-интеграции требуется отдельная OpenSpec: capabilities OpenAI/Anthropic-compatible и локальных моделей, преобразование вложений, privacy consent, размер/квоты, обработка ошибок, локальное удаление/хранение и аудит. Приватные «Документы» не передавать модели автоматически. `Save to Memory` отдельно от `Attach to Chat` и отдельно от п.84 `Multiple attachments in one note`. **Нельзя подменять обработку LLM только сохранением в заметку.**

## 6. Память, настройки, расширение будущих возможностей

**Память:** поисковая строка сверху; фильтры и разные типы содержимого; recent/relevant и разделы; компактные превью медиа. Доступ к нескольким оригиналам в одной заметке, транскрипту и OCR, нескольким версиям факта, галерее, undo и корзине. Без огромного «информационного баннера» в начале. Варианты `empty`, `importing`, `searching`, `permissionDenied`, `offline`, `corruptedAttachment`, `restoreInProgress`. Предстоящие: CLIP/OCR (83), файлы в записи (84), HTML/MP3 (85), структура (56/66), транскрипты (75), временные факты (72/73).

**Настройки:** краткий список категорий `Подключения`, `Голос`, `Поиск/инструменты`, `Лимиты`, `Память/копии`, `Персонализация`, `Приватность`, `Диагностика`; вложенные формы и второстепенные опции внутри. Никаких фальшивых `Plus/Pro`, маркетинговых иконок и подмены названий подключений. Не показывать реальные ключи, токены и чувствительные данные. Существующие настройки подключения нескольких моделей и поисковых провайдеров сохранить.

**Будущие UX-маршруты:** automations и расписания (57), бюджеты (54), инструменты и внешние подключения (62–64, 76), уведомления/сводка дня (71), напоминания по месту (81), характер (82) интегрировать через вложенный экран, contextual action и bottom sheet без новых обязательных вкладок. Если повседневные сценарии подтвердят пользу отдельной вкладки — отдельно согласовать новое решение. Не превращать Home в панель мониторинга.

**Медиа-результаты:** галереи и PDF показывать настоящими превью и типизированными карточками, но не выдумывать тестовые факты в рабочем APK. Демонстрационный текст/фото только в прототипах и проверочных фикстурах.

## 7. Адаптивность, визуальная доступность и защита качества

| Проверка | Минимальное требование к приёмке |
| --- | --- |
| Экран | 320/360/390/430dp + большие устройства; **нет** обрезания важных элементов, горизонтальной прокрутки всего экрана или съехавших кнопок |
| Клавиатура | нижняя строка composer, отправка, «+» и голос остаются доступны; заметен и доступен текущий черновик; Android 3-button и gesture nav |
| Размер текста | системные множители 1.0/1.3/1.5; длинные русские названия провайдеров и файлов, длинные ошибки и markdown без наложений |
| Контраст | текст обычного размера по возможности WCAG AA 4.5:1, важные нетекстовые affordance ≥3:1; не полагаться на glow вместо читаемой границы |
| Тач | основное интерактивное поле касания Android не менее 48×48dp при сохранении визуального компактного стиля |
| Тема | первичная dark Nebula; светлая и высококонтрастная — полноценно в дизайн-системе, не пустая белая форма |
| Screen reader | TalkBack для добавления вложений, удаления отдельного файла, микрофона (в т.ч. состояния), отправки, загрузки, ошибок и отмены |
| Motion | Reduce animations, low battery/thermal, сворачивание приложения, отсутствие запуска аудиопотока при декоративной анимации |
| Перфоманс | измерить p50/p95 FPS/потребление памяти/энергии на реальном Android; анимация не должна ухудшать ввод и стриминг |
| Архитектура | токены, централизованные компоненты, runtime flags для motion quality и fallback; no screenshot as fake UI |
| Регрессия | screenshot snapshots разных размеров + реальные Android сценарии; эталоны обновлять только после ревью, не просто для зелёного CI |

### Категорические запреты для ИИ-разработчика

1. **MUST NOT:** заменить референсные сферы на однократный CSS-like radial-gradient circle, одно SVG-кольцо, плоскую букву или нейросетку под предлогом «MVP».
2. **MUST NOT:** вшить изображение целого скриншота вместо редактируемых компонентов и работающих действий.
3. **MUST NOT:** уплотнять экран за счёт нечитабельного текста, убирания доступности или сокрытия кнопок системной клавиатурой.
4. **MUST NOT:** добавить незапланированные платные планы, короны, подсказки «что спросить», бесконечную карусель, обязательные предложения или четвёртую вкладку.
5. **MUST NOT:** сломать защищённую память, хранение истории, биометрию, локальные документы или отправлять вложения неизвестному LLM/серверу без правила доступа.
6. **MUST NOT:** выдавать неподдерживаемый провайдером image/PDF/audio input за успешный, подменять ошибки заглушками или тихо отправлять только текст без уведомления.
7. **MUST NOT:** скрывать упрощение, отсутствие оригиналов или непроверенный APK за фразой «всё сделано».
8. **MUST:** перед UI-PR читать этот файл, [UI_UX_REDESIGN.md](../UI_UX_REDESIGN.md), OpenSpec, план; перечислить какие SHALL/WHEN-THEN подтверждены, приложить before/after и Android проверки.

## 8. Приёмка по этапам (не смешивать статусы)

- **V0 · концепция:** одобрена пользователем (текущий статус). Первичный визуальный приоритет — полноформатный чат и два референса пользователя.
- **V1 · дизайн-ресурсы:** оригиналы REF-ICON-A/B доступны агенту в стабильном источнике; финальная Figma v0.3 содержит редактируемую структуру всех трёх экранов, компоненты и минимум 7 состояний orb/composer; явно проверена собственником. **Пока не выполнено**.
- **V2 · технический spike:** есть два сравниваемых образца анимации + измеренные FPS, батарея/память, поведение при Reduce motion; выбранная технология подтверждена. **Пока не выполнено**.
- **V3 · дизайн-система:** оформлены `NebulaCore`, `NebulaBackground`, `ChatComposer`, `AttachmentChip`, `ChatFileCard`, `SettingsRow`, `MemoryItem`, `StatusIndicator`; semantic tokens and Android-safe layouts; единый UI-скилл, обязательный для агентов. **Пока не выполнено**.
- **V4 · экран/настоящий APK:** нет регрессий доступности и работы, сравнение с утверждённым референсом на реальном телефоне, полностью рабочие сохранение/ввод/история. Мультимодальные функции принимаются **отдельно**, не одной галочкой за дизайн. **Пока не выполнено**.
