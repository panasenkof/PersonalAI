# PersAI · Единый UX-контракт импорта, распознавания и улучшения текста (перед этапом I)

**Дата:** 02.11.2026. **Статус:** согласованная постановка по обратной связи с Vivo X200 Pro / APK b592, **не реализовано**. **Очередь:** [PLAN.md §2](../../PLAN.md) → [подплан шага 8](../../Plans/PersAI_Step8_Sol_Medium.md) → этот дизайн-контракт; оба сохраняют единый roadmap. Вновь выявленные дефекты из физической проверки записывать отдельно с реальным результатом.

**Основание:** тест 1 — OCR фотографии распознаёт, экран перегружен и нет быстрого ИИ-улучшения до сохранения; тест 2 — те же замечания к PDF, но качество и покрытие всех PDF-страниц **не подтверждены**; тест 3 — аудио требует такого же компактного UI и выбора между Whisper/доказанным системным/совместимым онлайн-ASR; работоспособность системного ASR файла **не подтверждена**. Тест 4 — пользователь не нашёл повторное распознавание PDF на экране импорта: фактически действие доступно **только после сохранения**, в `MemoryNoteScreen` через ⋮ → «Распознанный текст и оригиналы» → «Текст из файла» → «Распознать заново». Это **DISCOVERABILITY FAIL / FUNCTION NOT TESTED**, а не доказательство ошибки алгоритма повтора.

**Приоритет:** новые решения владельца → [NEBULA_VISUAL_CONTRACT](NEBULA_VISUAL_CONTRACT.md) → [UI_GUIDELINES](../UI_GUIDELINES.md) → этот сценарный контракт → [U3 import](U3_IMPORT_JOURNEY_2026-10-23.md), [U3 multi](U3_MULTI_RECOGNITION_2026-10-23.md), [U2 editor](U2_MEMORY_EDITOR_2026-10-23.md). Сохраняем утверждённый Nebula, текущее количество разделов, локальную зашифрованную память и существующий механизм доступа.

## 1. Единая задача и принцип

**Один предсказуемый путь для фото, PDF и аудио:** выбрать источник → увидеть, что будет обработано и **каким способом** → запустить ровно одно основное действие → проверить текст/полноту → при желании нажать маленькую «Улучшить с ИИ» → **явно** сохранить. Для текста/ссылки действие «Прочитать»/«Загрузить» вместо бессмысленного OCR; для уже готового текста сразу перейти к проверке. Не надо сначала создавать заметку ради коррекции распознавания.

**Структура сверху вниз:**
1. **Компактный заголовок:** «Добавить в память»/«Новая заметка»; Back/отмена с защитой черновика. Никакой второй панели навигации.
2. **Карточка источника:** превью/название, вид (фото/PDF/аудио/текст), длительность аудио или фактическое число страниц PDF если известны; «Изменить» (когда допустимо). Несколько источников: горизонтальный счётчик «2 из 3» и компактный список состояния по файлам, не повторять полные настройки 3 раза.
3. **Карточка обработки:** одна строка **«Способ: На телефоне · OCR/Whisper»** либо **«Онлайн · провайдер / ASR-модель»** с действием «Изменить» (вызывает короткий выбор). При выбранном внешнем способе до запуска видимы получатель, тип отправляемых данных, потенциальная стоимость, согласие; для запрещённых данных недоступно. Ни настройки ключей, ни выбор chat LLM не занимают главный экран.
4. **Главная кнопка:** «Распознать», при работе «Остановить» рядом со статусом; после удачи не оставлять вторую огромную «Распознать» над результатом. «Распознать заново» — контекстная вторичная операция с сохранением прежнего текста до явного принятия.
5. **Результат:** заголовок «Распознанный текст» (для прямого текста «Текст материала»), ясный статус «полностью / частично / не прочитано / неизвестно» на основании данных, текст с редактированием и **единственным общим действием** маленькая иконка ✨/wand + доступная подсказка «Улучшить с ИИ». Длинный результат получает скролл в странице/постраничные блоки без обрезания.
6. **Подпись автора и расположение:** короткое поле комментария (отдельно от OCR/ASR), выбранная коллекция/конфиденциальность. Дополнительные имена, тип, ключевые слова, формат/продвинутые режимы — раскрываемая группа «Дополнительные настройки», **по умолчанию закрыта**. При запрете облака решение остаётся явным и не скрывается в этой группе.
7. **Один нижний закреплённый CTA:** «Сохранить в память» с состояниями disabled/сохранение/готово; учитывает safe area и Gboard, не перекрывает поле текста. Дублированной кнопки Save в теле нет. Отправка в чат — отдельный путь, никогда не синоним сохранения.

### Компактная композиция (не пиксельный макет)

```text
[‹] Добавить в память
┌ Источник ──────────────────────────┐
│ 📄 инструкция.pdf · 8 страниц     ⋯│
└────────────────────────────────────┘
  Способ: На телефоне · OCR     Изменить
[ Распознать ]     (при работе: Остановить)
  Результат · 6 из 8 страниц прочитано
  Распознанный текст            [✨]
  [Текст / исходные страницы / комментарий]
  Раздел: Заметки            Изменить
  Дополнительные настройки           ⌄
══════════════════════════════════════
[          Сохранить в память         ]
```

Тот же каркас для фото (превью + «Русский OCR») и аудио (мини-плеер + длительность + «На телефоне · Whisper» либо «Онлайн · …»). Указывать только подтверждённую длительность/страницы, не показывать искусственные проценты. В контексте чтения уже сохранённой заметки использовать **тот же** маленький ✨ возле конкретного текстового блока вместо повторяющихся больших кнопок.

## 2. Матрица отличий без расхождения экранов

| Материал | Карточка источника | Доступный способ обработки | Контент после обработки | Особое правило |
| --- | --- | --- | --- | --- |
| Фото | Фото, имя, число файлов | Локальный русский OCR; явный внешний document-text при разрешении | Текст, флаг сомнительных символов | Фото не отправлять с командой «Улучшить текст» |
| PDF | Документ, реальное число страниц если известно, просмотр исходных страниц | Text-layer без сети; local OCR только для сканов/непрочитанных страниц | Текст **с номерами страниц, покрытием/пропусками** | Не смешивать источник и ИИ-перефраз; улучшение страницы не теряет локатор |
| Аудио | Плеер, имя, длительность если известна | Явный локальный Whisper / **подтверждённый** онлайн ASR; системный Android **только после Vivo-пруфа** | Транскрипт, исходное аудио, таймкоды только от ASR | Скачанный Whisper не перехватывает явный онлайн-выбор; не выдавать текстовую LLM за аудио ASR |
| TXT/HTML/ссылка | Имя / URL + чистый текст | Локальное чтение/загрузка страницы без «ложного распознавания» | Текст + ✨ | Не навязывать extra LLM; ошибка загрузки не удаляет URL |
| Несколько файлов | Компактный список с ready/failed/progress на **каждом** | «По очереди» по умолчанию, «Сопоставить вместе» — явно и с согласием | Источники и ошибки отдельно; итоговая заметка одна | Не объединять строки без provenance, не скрывать ошибки и частичное покрытие |

## 3. Один компонент действия «Улучшить с ИИ» во всех точках

- Использовать/адаптировать **существующие** `NoteAiEditor`, `editNote`, `IconAction`, `NoteEditorSection`; один и тот же bottom sheet и одинаковый вход из `MemoryImportScreen`, `MemoryNoteScreen` (создание, чтение, редактирование), просмотра сохранённого OCR/ASR текста. Значок визуально компактный, но зона касания минимум **48×48dp**, подпись TalkBack «Улучшить с ИИ: [текст заметки / распознанный текст]»; у соседних блоков различать цели. Не ставить по большой отдельной кнопке под каждым полем.
- **Источник и поле цели обязательны:** `body` (авторский текст) либо `extractedText` (OCR/ASR/извлечение). Выбор текста из нескольких файлов/страниц указывает точный scope и реальную полноту. Результат пишется **только в то поле/источник**, откуда запущен, по действующим разрешениям и версиям. Не переносить `extractedText` в `body` автоматически, не записывать AI edit как оригинальный OCR/ASR evidence.
- В sheet: сначала «Исправить ошибки распознавания» (только когда контекст OCR/ASR), «Орфография и пунктуация», «Разбить на абзацы», «Свой запрос». Показывать получателя/модель и факт внешней передачи **только текста** перед первым запросом; отдельная явная кнопка «Показать результат», не автозапуск.
- Результат: «Исходный / Предложенный» (взаимное переключение или компактное сравнение) + **«Применить» / «Отмена»**. После применения до сохранения — «Отменить правку ИИ». При нечитаемых словах, именах, датах, числах, дозировках, величинах предлагать проверку оригинала вместо догадки. Не «исправлять» речь так, будто было повторное прослушивание.
- Нет подключения/ключа/модели либо внешняя передача запрещена: значок не запускает запрос, показывает понятную причину и доступный обычный ручной редактор. Для private/secret и закрытых разделов — строго действующая ACL. Никакого обхода через выбранную ASR-модель или основную LLM. Lock/профиль/уход/смена источника/редактирование/версия/отмена обрывают или инвалидируют ответ.
- Отдельные действия «Распознать заново» (запуск нового OCR/ASR по оригиналу) и «Улучшить с ИИ» (правка **готового текста**) нельзя объединять; изменения сохраняются только по явному выбору. **Повтор должен быть видимым у результата**, а не спрятанным в меню ⋮ → редактирование → раскрытие «Текст из файла». На первичном импорте после готового OCR/PDF/ASR показать контекстное «Распознать заново» возле результата; в сохранённой заметке показывать это действие у карточки оригинала/транскрипта даже в **режиме чтения**, если оригинал сохранён. Для PDF коротко указать выбранный способ («Текстовый слой» либо «OCR сканов»), реальное покрытие и неизменность оригинала. При нескольких исходниках обязательно выбрать конкретный оригинал. Не допускать большой дублирующей CTA.
- **Общая безопасная модель:** исходный текст остаётся до завершения и до «Применить новый»; после нового распознавания показать предпросмотр и «Оставить текущий / Применить новый». Если в черновике или заметке есть несохранённые правки, не запускать повтор молча: объяснить «Сначала сохраните изменения» или дать безопасный явный выбор без потери данных. Отмена, ошибка, AppLock, смена версии/профиля не заменяют текст пустым. При отсутствии сохранённого оригинала действие недоступно **с понятным объяснением**, без ложного обещания повторной обработки; до первого сохранения можно повторить по текущему выбранному файлу, пока его временная копия доступна.

## 4. Аудио: выбранный способ виден, а не угадывается

- В `Настройки → Мультимедиа → Распознавание аудиофайлов` хранится отдельное предпочтение **для файлов**, не связанное с голосовым вводом с микрофона. Локальная модель остаётся безопасным начальным режимом у существующих пользователей; выбор `speechId`/ASR-модели и capability status отражается на карточке импорта, с возможностью временно изменить способ для конкретного файла. Изменение в импорте не должно неожиданно менять глобальную настройку, и наоборот.
- **На телефоне — Whisper:** без сети; явно показывать состояние модели, скачать — через существующий менеджер (не автоматически), ожидаемые лимиты и корректные ошибки.
- **Онлайн — специализированная модель ASR:** первое внедрение по H-ASR1 (официальный `/audio/transcriptions` и проверенная модель); пользователь видит, что именно исходное аудио будет передано, провайдера, выбранную **ASR-модель**, возможность расходов и кнопку подтверждения. Текстовая LLM может **улучшать уже готовый транскрипт**, но не должна автоматически получать аудио. Не объявлять любую OpenAI-compatible/chat-модель ASR-совместимой.
- **Системное распознавание Android:** не показывать активной третьей опцией до H-ASR2 и фактического PASS инъекции файла через API устройства; доступность Google-микрофона ≠ поддержка файлов. При отказе распознавателя честный «На этом телефоне для файлов недоступно» и оставить два рабочих метода, без включения микрофона через динамик/скрытого сетевого fallback.
- Плеер/транскрипт/✨ работают одинаково независимо от провайдера. Настоящие producer timestamps доступны для seek; если их нет — отображать текст без псевдо-таймкодов. ASR-исходник и ИИ-исправление разделены, возможность повторного распознавания с подтверждением ручных правок не потеряна.
- Сравнение качества русской речи — отдельный измеримый gate H-ASR1 (эталонные записи, шум/фамилии/цифры, стоимость, время/память). Не обещать «лучший» движок без измерения.

## 5. Состояния и взаимодействия: идентичный UX

| Состояние | Что видно | Главное доступное действие | Что недопустимо |
| --- | --- | --- | --- |
| Нет источника | Короткий выбор файл/камера/ссылка | «Выбрать» | Обилие настроек моделей |
| Готов к обработке | Карточка + реально выбранный метод | «Распознать»/«Прочитать» | Скрытая сеть или auto-Save |
| Идёт | Прогресс только доказанный; имя текущего файла, доступная «Остановить» | «Остановить» | Дубли запросов и блокирование Back навсегда |
| Частично | Полученные части и список пропусков/ошибок | «Повторить неудачные», «Сохранить доступное» | Отметка «всё обработано» |
| Ошибка / offline / ключа нет | Прежний текст/оригинал остаётся | «Попробовать снова» / «Изменить способ» | Молчаливое переключение в облако |
| Текст готов | Отдельный извлечённый текст, ✨, контекстное «Распознать заново» при доступном оригинале, комментарий и раздел | «Сохранить в память»; вторично «Распознать заново» | Авто-ИИ и подмена источника |
| Повторная обработка | Старый текст остаётся, явно показаны источник, способ и новый предпросмотр | «Оставить текущий» / «Применить новый» | Скрытая замена правок, запуск повтора при несохранённых изменениях |
| ИИ предложил правку | Сравнение с исходным, Scope и disclosure | «Применить» или «Отмена» | Незаметная подмена авторского поля |
| Нет прав / AppLock | Безопасное ограничение/очистка временных копий | «Назад» или разрешённые ручные действия | Запоздалая запись/утечка в чужой профиль |

**Back/отмена:** сначала закрыть sheet, затем выйти из редактирования/черновика с подтверждением; не показывать одновременно sheet и системный Alert. При отсутствии сохранения черновик не становится записью в SQLCipher. При ошибке не выбрасывать успешные части и вручную исправленный текст. Смена исходника требует явного решения при несохранённой правке. Порядок фокуса TalkBack соответствует расположению элементов, disabled имеет словесное пояснение.

## 6. Реализация по маленьким PR без второй архитектуры

1. **H-UX1 (UI)** — общий верхний каркас, компактный выбор источника/способа, одна главная CTA, одна нижняя Save, свернуть вспомогательные элементы; photo/PDF/audio и mixed, без изменения транспортов или исходных данных.
2. **H-UX2 (текст)** — маленькое общее ✨ для `body`/`extractedText` в новом/импортированном/сохранённом; расширить имеющийся `NoteAiEditor` точечным scope, preview/CAS/undo, без новой системы транскриптов/провайдеров.
3. **H-ASR1 (движок)** — явная настройка локальный/проверенный онлайн, убрать неявный приоритет Whisper при готовой модели, ограничение ASR endpoint/model, consent и provenance; не менять микрофонное распознавание.
4. **H-ASR2 (native feasibility)** — отдельно проверить Android system file input на Vivo; при UNSUPPORTED зафиксировать ограничение и не добавлять недействующее управление. При подтверждённой поддержке — интеграция через прежний `extractMedia` без параллельной очереди.
5. **После каждого UI PR:** C0-A/C3-B, PLAN CONFORMANCE, снимки до/после на **320/360/390/430dp** с 1.0×/1.3×/1.5×, dark/light, Gboard и закрытой клавиатурой, Android gesture/3-button, TalkBack, Reduce Motion, disabled/offline/loading/partial, в т.ч. ложный двойной клик, большие имена/тексты и safe-area. Токены только `mobile/src/design/nebula/tokens.ts` и существующая `useTheme`. Минимальная зона касания 48dp, без фиксированных высот для строк.
6. **CI exact SHA / APK / физический Vivo:** каждая проверка отдельно помечается PASS/FAIL/NOT_RUN; проверить 3 набора (фото OCR, смешанный PDF, аудиофайл), новый/сохранённый текст, разные подключения и запрет внешней отправки, original/edited provenance, индексацию, cancel/lock/фон/сеть/смену профиля. Перед I все затронутые PR слиты, итоговая APK испытана **адресно**; при ручной проверке пункта 4 пользователь находит повтор PDF **без последовательности скрытых меню** как до первого сохранения, так и в сохранённой заметке; тест со своими правками — отдельный фактический PASS/FAIL; без неоправданной повторной полной 96-case кампании.

**Не входит:** новый экран/таб для медиатеки, новый editor/LLM service, второй SQL writer/индекс, платный фон, вторая система доступа, смена бренда Nebula, самостоятельное решение «главная LLM распознаёт любое аудио», обещание системного Google file ASR без пробы, общая переделка раздела Настройки, скрытое копирование оригинала во внешнюю модель.

## 7. Матрица готовности и защита от разъезда дизайна

**Перед слиянием каждого PR ответить:** совпадают ли верхняя карточка и bottom CTA для фото/PDF/аудио? Нет ли дублирующей кнопки/пункта меню? Одинаковы ли ✨ и безопасное подтверждение для нового и сохранённого текста? Видны ли исходник/метод/покрытие/провайдер/приватность именно там, где человек принимает решение? Сохраняются ли исходные номера страниц/таймкоды только при их наличии? Можно ли пройти сценарий целиком на 320dp с Gboard? Вся ли логика использует текущий extractor, `NoteAiEditor`, SQLCipher/source-version/ACL? Есть ли скриншоты до/после и реальные проверки, а не только зелёный Jest?
