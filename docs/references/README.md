# Внешние инженерные руководства для PersAI

**Дата составления и проверки источников: 17.11.2026.** Справочник для разработчиков и ИИ-агентов, работающих над мобильным приложением PersAI (React Native / Expo, Android, локальная память и инструменты LLM).

**Статус:** справочные материалы, **не отдельная очередь работ и не новая спецификация**. Приоритет имеют решения владельца, [PLAN.md](../../PLAN.md) (единственная очередь), [AGENTS.md](../../AGENTS.md), [docs/DEVELOPMENT_GATES.md](../DEVELOPMENT_GATES.md), действующие планы и OpenSpec. Из публикаций нельзя автоматически делать вывод «это уже реализовано», менять архитектуру, приватность, CI, разрешения инструментов или сроки.

## Как применять

1. Читай релевантный **конкретному изменению** источник, а не весь каталог на каждом PR. Перед значимым техническим решением проверяй актуальную редакцию, дату, API и совместимость с Expo/Android.
2. Указывай в техническом решении/PR: первоисточник, конкретный принцип, применимость к **существующему** механизму PersAI и способ проверить его на настоящем коде.
3. Разделяй рекомендации, предложения к внедрению и требования владельца. При противоречии с действующей спецификацией согласуй изменение, не меняй поведение молча.
4. Не создавать параллельные хранилища, обработчики действий, поисковые индексы, телеметрию и маршруты LLM ради соответствия статье.
5. В оценках качества сохраняй границу между `PASS_CI`, `PASS_EMULATOR`, `PASS_PHYSICAL`, `NOT_RUN` и `NOT_PROVEN`. Отдельная зелёная сборка не доказывает работоспособность APK на телефоне.
6. При обновлении ссылок указывай дату перепроверки и сохраняй ссылки на профильные документы; не переписывай целиком статьи в репозитории.

## Верификация и доказательства качества — ключевой источник

**Addy Osmani, Claude Code / claude.dev — [How the Claude Code team thinks about verification](https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/)**, **16.11.2026**. Проверено **17.11.2026**.

В статье разбираются три дополняющих метода — **end-to-end (E2E)**, **property-based** и **differential** — и то, как независимые проверяющие, точная привязка к коммитам и контроль самих тестовых ворот уменьшают ложные успехи. Для PersAI важнейший вывод: `Jest PASS` и сборка APK ещё не равны подтверждённому сценарию на реальном Android. **Подробное прикладное сопоставление: [VERIFICATION_GUIDANCE.md](VERIFICATION_GUIDANCE.md).**

Смежные действующие правила: [гейты разработки](../DEVELOPMENT_GATES.md), [приёмка устройства](../DEVICE_QA.md), [проверка Android UI](../ANDROID_UI_TESTING.md), [выпуск APK](../RELEASE_APK.md), [сценарии агента](../../Plans/AGENT_SCENARIO_ACCEPTANCE.md).
