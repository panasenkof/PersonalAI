# Как применять verification команды Claude Code в PersAI

**Источник:** Addy Osmani, [How the Claude Code team thinks about verification](https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/), 16.11.2026. **Проверено 17.11.2026.** [Вернуться к каталогу](README.md).

**Статус:** аналитический материал. Перечисленное не является уже реализованными тестами и не вводит новые обязательные CI-ворота. Не заменяет [AGENTS.md](../../AGENTS.md), [DEVELOPMENT_GATES.md](../DEVELOPMENT_GATES.md), утверждённые приёмочные сценарии и разделение CI / APK / Android на реальном телефоне.

## Суть статьи

1. **E2E:** нужно исполнять полноценное действие пользователя в работающей системе и сохранять наблюдаемые доказательства (действие, шаг, ошибка, журнал, снимок). Только unit-тест не подтверждает работающий продукт.
2. **Property-based:** проверять неизменные свойства на широком/генерируемом наборе входов (в частности, сериализацию, идемпотентность, инварианты сохранения и доступа).
3. **Differential:** прогонять старую и новую реализации на одинаковом корпусе, отделяя разрешённые изменения поведения от регрессий. Старый дефект сам по себе не становится нормой.
4. **Проверяющий должен быть независим:** нельзя считать надёжным механизм, если код PR незаметно ослабляет собственные проверки. Оценка привязывается к **точному SHA**; сам набор критериев нужно защищать от заинтересованного изменения.
5. **Быстрые и надёжные проверки:** flaky-тесты порождают ложные сигналы; тяжёлые сценарии запускать адресно, а новые ворота оценивать сначала в режиме наблюдения.

## Привязка к нашим сценариям

| Изменение PersAI | Что проверить сквозным E2E | Подходящие property/differential проверки | Какое доказательство сохранить |
| --- | --- | --- | --- |
| **Google/system ASR, микрофон, диктовка** | Главный экран → нажать микрофон → произнести короткий текст → выдержать паузу → получить редактируемый текст без вылета; закрыть/повторить | Многократные старты/остановки, отмена, переход в фон и возвращение; отсутствие дублирования регистрации слушателей и событий | Точный APK/SHA, Android/устройство, ASR-провайдер, лог `logcat`, шаг и результат; для вылета — stacktrace |
| **Telegram/TDLib, сохранённые сообщения** | Авторизация/2FA → импорт именно выбранного источника → создание ожидаемых записей → повтор синхронизации без дублей → выход | Идемпотентность повторного импорта, границы загрузки, отмена, жизненный цикл TDLib; сравнение поведения до/после изменения адаптера | Подписанный APK, точная ревизия, источник импорта, количество уникальных записей (без содержимого), native-логи с маскировкой чувствительного |
| **SQLCipher, память и резервные копии** | Создать запись → закрыть/заблокировать → восстановить доступ → найти → изменить/отменить → резервная копия → восстановление | Round-trip резервной копии и существенных полей; запрет утечки закрытых разделов; CAS/undo; повтор миграции; сравнение с поддерживаемой прежней схемой | До/после ID/версии, проверка целостности и ACL, состояние данных без приватного текста, отметка физического прогона |
| **Фото, поиск и мультимодальные модели** | Импорт фото → индексация → поиск текстом / образцом → открытие именно исходного фото; проверить недоступность модели и отмену | Стабильное ранжирование на размеченном корпусе, одинаковая обработка дублей, сохранение ревизий, отсутствие отправки фото LLM без разрешения; сравнение нового и прежнего retrieval | Репрезентативный **размеченный** корпус, результат top-K и его ошибки, задержка, RAM и батарея при реальном измерении; отдельное `NOT_PROVEN`, если качества не оценивали |
| **R8, JNI, TDLib и сборки** | Старт оптимизированного release APK, работа нативных мостов, авторизация, камера/ASR без `UnsatisfiedLinkError` / `NoClassDefFoundError` | Сравнение debug/release на одних сценариях и ABI; контроль упаковки библиотек и R8 правил; «сборка успешна» не заменяет вызов native API | Точный APK SHA-256, ABI, logs/JNI stacktrace, версия Kotlin/Expo, CI run |
| **Агентные инструменты и промпты** | Запрос → выбор доступного инструмента → подтверждение пользователем → одна каноническая запись → проверка результата → undo | Одинаковый набор правил у разных провайдеров; запрет недоступных инструментов; двойное подтверждение не делает двойную запись; differential при изменении общего prompt builder | Трасса доступных инструментов, события/коды результатов без приватных содержимых, сравнение двух провайдеров только при реально выполненном live-прогоне |

Это **кандидаты для улучшения** имеющихся проверок; перечень не означает, что все перечисленные сценарии прошли или должны выполняться при каждом PR.

## Предложение для будущих PR: минимальная проверка по риску

1. Перед реализацией выбрать **один риск и один проверяемый пользовательский сценарий** из действующих критериев. Внести только необходимые тесты, без новой очереди в `PLAN.md`.
2. Воспроизвести исходный сбой на старой ревизии. Если тест не фиксирует дефект, он не является доказательством его исправления.
3. Для изменений миграций, поиска, сериализации, R8 и агентных маршрутов по возможности добавить одну PBT/differential-проверку с фиксированным seed и известными контрпримерами. Не брать исправленную реализацию как единственный независимый эталон.
4. Запустить необходимые локальные тесты, CI на точном SHA, а при релевантных нативных изменениях — **настоящий оптимизированный APK** и устройство / эмулятор. Указать, что не удалось проверить; не переносить `PASS` между средами.
5. В отчёте разделить `PASS`, `FAIL`, `SKIP`, `NOT_RUN_PHYSICAL`, `NOT_RUN_LIVE_LLM`, `NOT_PROVEN`, baseline/regression и подтверждённую версию APK.
6. При изменении самих gate-скриптов проверить, что новые правила не делают собственный PR заведомо «зелёным». Дополнительные ворота сперва проверять в observe-режиме; подключать как обязательные только отдельным решением.

**Предостережение:** подход Anthropic к `.claude/skills/verify`, числу автоматических попыток и commit-gate — пример их процесса, **не прямое распоряжение** изменять наш `AGENTS.md`, Cursor, CI или Android QA. Пользовательская приватность важнее тестовых логов: никаких ключей, кодов Telegram, содержимого заметок и закрытых фото в отчётах или артефактах.
