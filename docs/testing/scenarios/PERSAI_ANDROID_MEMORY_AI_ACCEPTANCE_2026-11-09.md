# PersAI — сценарий приёмки Android: иерархия памяти, инструменты LLM, автоматические метаданные

**Дата:** 2026-11-09  
**Тип:** исполняемый QA-runbook для ИИ-агента (не отчёт о выполнении).  
**База для сверки:** `main` с #439 (вложенные разделы, backup v19, действия LLM), #441 (LLM-теги/раздел при импорте), #442 (модельные поисковые поля). До запуска записать **фактический** SHA, не подменять его приведёнными номерами PR.  
**Устройство:** приоритет — Android 16, Vivo X200 Pro; автономные проверки — отдельный Android-эмулятор с тестовым профилем.  
**Область:** функции, затронутые #439/#441/#442, и их регрессии. Не объявлять весь этап 9 завершённым.

> **Команда ИИ-агенту:** исполни тесты ниже в указанном порядке. Не ограничивайся анализом исходников или зелёным CI. Запускай приложение и воспроизводи реальные действия; для каждого ID сохрани фактический результат и доказательства. Если нет доступа к устройству, живой модели, ключу, исходной базе v18 или автоматизации экрана — фиксируй `BLOCKED`/`NOT_RUN` с причиной, а не `PASS`. Не изменяй приложение, серверные настройки или реальные данные для того, чтобы «подогнать» результат теста.

Зафиксировать доказательство, прекратить потенциально разрушающий сценарий и продолжать только безопасные независимые тесты.

## 3. Иерархия разделов и навигация: H01–H11

**H01 — Создание вложенных разделов через UI.** Шаги: Память → корень → «Создать раздел» с названием «ИИ» (если нет) → открыть «ИИ» → «Создать подраздел здесь» → «Обучение» → открыть → «Полезные скиллы». Повторно открыть Память. **Ожидается:** цепочка доступна; в корне показываются только корни, в каждом разделе — непосредственные дети; нет исчезнувших или дублированных карточек.

**H02 — Путь и возврат.** Открыть глубочайший раздел, создать F01, открыть запись; затем кнопка «назад» устройства, хлебные крошки/«В родительский раздел» и «Все разделы». **Ожидается:** верный полный путь, сохранность F01, возврат на уровень выше без перехода в чужую ветку; прокрутка и кнопки доступны.

**H03 — Повтор названия в разных ветках.** Создать `Дом/Обучение` и F03, оставить `ИИ/Обучение` с F02. В выборе раздела у записи и в списке разделов проверить полные пути. **Ожидается:** F02 и F03 не смешиваются; одноимённые элементы различаются контекстом; маршрут ведёт в правильную ветку.

**H04 — Поиск внутри вложенного раздела.** В `ИИ/Обучение/Полезные скиллы` искать точную `ORION`; затем в родителе и во всём разделе Память. **Ожидается:** совпадение находится при подходящем scope. Записать, является ли поиск по родителю рекурсивным в текущем контракте, и сверить с фактическим `searchNotes`; **не считать отсутствие рекурсии ошибкой без требований**, но не терять запись в глобальном поиске.

**H05 — Перемещение раздела.** В `Разделы` → `Переместить` перенести пользовательский `Обучение` из `Дом` в другой допустимый обычный раздел, затем вернуть. **Ожидается:** ID раздела, F03, его архив/вложения, поиск и ревизии остаются; путь меняется, тело заметки нет.

**H06 — Запрет цикла.** В одноразовом профиле открыть перемещение `ИИ` внутрь `ИИ/Обучение` или внутрь самого `ИИ`. **Ожидается:** цель отсутствует/запрещена, отсутствуют циклы и зависание UI. Unit-тест обязан покрывать самозацикливание и descendant-циклы.

**H07 — Повтор имени у одного родителя.** Попытаться повторно создать `ИИ/Обучение` с тем же названием. **Ожидается:** отказ или понятное сообщение о конфликте; число разделов не изменилось; создать аналогичное название в `Дом` разрешено.

**H08 — Длина пути.** Создать цепочку из 8–12 пользовательских подразделов с короткими именами (например `Уровень01`…`Уровень12`), внизу заметку с маркером `QA9-20261109-DEEP`. Перезапустить приложение. **Ожидается:** все уровни доступны, поиск и навигация не обрываются, ни одного скрытого лимита в 2–3 уровня. Если реальный UI/провайдер имеет обоснованный предел длины строки — зафиксировать, а не скрывать.

**H09 — Защищённые ветки.** Посмотреть наличие системного `Документы` и защищённых/закрытых разделов в QA-профиле; попытаться переместить обычный `ИИ` в `Документы` и наоборот. **Ожидается:** запрещено ослабление/несовпадение sensitivity, LLM не получает содержимое закрытой ветки, открытие защищённых записей требует соответствующего доступа.

**H10 — Существующая память.** На обновляемом профиле (только с предварительным backup) сверить до/после записи, разделы, IDs, теги, вложения, историю, корзину, архив. **Ожидается:** корневые разделы и данные не исчезли при миграции на schema v19. Если исходная версия не была v18 — указать фактическую.

**H11 — Удобство UI.** На 320/390px и реальном Vivo: кнопки подразделов и вспомогательные действия не перекрываются клавиатурой/нижней панелью; фото-обложки заметок видны в списке и плитке; вход в редактирование требует одного действия; «Текст распознавания» показывается только при наличии результата. **Ожидается:** без обрезания, двойного редактирования и потери фотографий. Зафиксировать отдельные дефекты, если найдены.

## 4. Создание/удаление разделов инструментами LLM: L01–L12

Тестировать **через обычный чат**, поскольку все команды в чате проходят через выбранную LLM и её каталог, а не через regex UI. Для проверки служебных вызовов использовать безопасный диагностический trace/тестовый provider mock; одних ответов модели «готово» недостаточно.

**L01 — Подтверждаемое создание.** В чате написать: «Создай в разделе ИИ → Обучение подраздел “QA9-20261109-ЧатРаздел”». Ожидать карточку «Создать раздел?» с полным родительским путём и причиной. **До нажатия** проверить в Память, что раздела нет. Нажать «Создать раздел», дождаться receipt, открыть Память. **Ожидается:** ровно один новый подраздел, появившийся только после подтверждения.

**L02 — Отмена.** Аналогично запросить `QA9-20261109-CANCEL` и нажать «Отмена». Повторно открыть Память и чат. **Ожидается:** раздел не создан, нет скрытого позднего создания и ложного подтверждённого receipt.

**L03 — Повтор подтверждения / повтор сообщения.** Подтвердить L01 дважды (или воспроизвести повтор UI после перезапуска). **Ожидается:** не более одного раздела, повторная операция отказана/идемпотентна, без гонки или дубля.

**L04 — Вложенный путь с одинаковыми названиями.** Написать «Создай “QA9-20261109-TARGET” именно в ИИ/Обучение, не в Дом/Обучение». **Ожидается:** правильный parent; если LLM не может однозначно выбрать, она уточняет, а не создаёт в произвольной ветке. Проверить trace `propose_create_memory_section` и `parentSlug`.

**L05 — Удаление пустого.** Создать F11 через UI, попросить «Удали пустой раздел QA9-20261109-EMPTY». Проверить карточку «Удалить пустой раздел?», нажать подтверждение. **Ожидается:** только указанный пустой пользовательский обычный раздел исчез; не затронуты другие разделы.

**L06 — Удаление непустого.** Создать `QA9-20261109-NONEMPTY` с F12 **в корзине**. Попросить удалить раздел. **Ожидается:** отказ, потому что запись существует независимо от active/archived/trashed. Раздел и запись сохраняются. Не очищать корзину для «исправления» результата.

**L07 — Удаление родителя с детьми.** Попросить удалить `ИИ/Обучение`, пока в нём есть `Полезные скиллы`, либо другой QA-родитель с детьми. **Ожидается:** отказ с причиной, дочерние разделы/заметки сохранены.

**L08 — Удаление системного/чужого/защищённого.** Попросить удалить «Документы», «Заметки» и недоступный/неизвестный раздел. **Ожидается:** нет предложения опасного удаления; отказ. Никаких обходных попыток через прямые вызовы writer.

## 5. Импорт, автоматическое определение раздела и теги: I01–I12

Вход в тестовый импорт через Память/создание заметки или Android «Поделиться» → PersAI. Кнопки, подтверждённые текущим UI: «Определить раздел с ИИ» (accessibility label), «Добавить теги», «Сохранить в память», диалог выбора «Сохранить без ИИ» / «Разрешить ИИ и сохранить». Перед каждым тестом удостовериться, что выбран **обычный** раздел и нет неявного разрешения провайдеру.

**I01 — Доступность кнопки.** В экране импорта заполнить читаемую русскую подпись «Статья о локальных моделях и русском распознавании речи». При подключённой LLM и доступном стандартном разделе проверить кнопку «Определить раздел с ИИ». **Ожидается:** кнопка активна; после нажатия появляется отдельный запрос разрешения на передачу видимого текста, не «серый» без объяснения.

**I02 — Нет текста.** Импортировать одно фото без подписи и без OCR, посмотреть кнопку и пояснение. **Ожидается:** ИИ не заявляет, что «увидел» оригинал, раздел/теги не выдумывает; UI объясняет необходимость подписи/распознанного текста. Сохранение в память доступно по исходному процессу.

**I03 — Согласие / отказ.** Нажать подбор; в системном диалоге выбрать отказ. Повторно открыть импорт. **Ожидается:** не было egress-запроса, раздел и теги не изменились. Затем разрешить один подбор — виден предложенный раздел, до пяти тегов и возможность исправить результат.

**I04 — Автопредложение при сохранении.** На стандартном импорте с содержательной подписью, без ручных тегов, нажать «Сохранить в память» → «Разрешить ИИ и сохранить». **Ожидается:** теги/раздел предложены в допустимом каталоге и сохранены через прежний writer; не более одного нового объекта для одного подтверждения; модель не создаёт новый раздел автоматически.

**I05 — «Сохранить без ИИ».** Повторить импорт F06 и в диалоге выбрать «Сохранить без ИИ». **Ожидается:** оригинал/текст сохраняется, выставлен opt-out для фонового enrichment, не выполняется скрытый вызов провайдера позже (проверить mock request counter и перезапуск).

**I06 — Приоритет пользователя.** Выбрать вручную `Дом/Обучение` и теги `ручнойтег`, затем сделать разрешённый LLM-подбор для фразы про ИИ. **Ожидается:** ручной раздел не заменяется чужим AI-предложением, авторские теги сохраняются; изменения показываются до сохранения.

**I07 — Повтор Android Share.** Одну и ту же тестовую подпись+ссылку отправить через Share дважды, с разными предложениями тегов от mock LLM. **Ожидается:** отпечаток точного повтора не изменяется из-за случайных модельных тегов; уже существующая запись не размножается молча, есть корректный выбор сохранить отдельную копию, если предусмотрено.

**I08 — URL-only и недоступная страница.** Импортировать F07 без чтения сайта. **Ожидается:** отсутствуют придуманные теги, заголовок содержимого, автор и дата; отображается достоверная «ссылка без прочитанного текста»; сетевые ошибки не ведут к потере исходной ссылки.

**I09 — OCR / PDF / голос.** Импортировать тестовый PDF/изображение с F10. Сначала подтвердить реальный извлечённый текст, затем отдельно разрешить подбор. **Ожидается:** LLM получает только действительно извлечённое, не оригинальный файл; при ошибочном OCR UI позволяет исправить его до сохранения; поиск по исправленным словам работает.

**I10 — Импорт защищённого.** Выбрать личную/защищённую классификацию и повторить I01/I04. **Ожидается:** внешний подбор не предлагается, исходник/текст не отправляется; запись остаётся в разрешённом защищённом разделе.

**I11 — Сбой / отмена модели.** Вызвать отказ/timeout/невалидный ответ провайдера, затем «Сохранить в память». **Ожидается:** пользователь видит причину, может сохранить без автотегов, исходные файлы не теряются, нет дублирования и фонового повторного egress без разрешения.

**I12 — Реальный Telegram/MAX Share.** На Vivo через Android Share отправить 1) текст+ссылку, 2) фото с подписью, 3) альбом нескольких файлов. Проверить URI grants, одно подтверждаемое сохранение, сохранность оригиналов после закрытия мессенджера, поиск. **Ожидается:** корректное действие для каждого типа. Если у агента нет физического доступа/приложений — `NOT_RUN_PHYSICAL`, не симулировать PASS.

## 6. Фоновое LLM-обогащение и поиск: E01–E12

#442 добавляет `payload.tags` (модельные значения), `model_search.topic/summary/titleHint/people/places/dates` и модельные индексные термины в **прежней** SQLCipher/FTS системе; сам исходный title/body/source не должен переписываться. Модельный `summary` — поисковая подсказка, а не цитата. Проверку raw payload выполнять только в одноразовом QA-профиле безопасным repository/test adapter; на пользовательском телефоне ограничиться UI, поиском и зашифрованным backup.

**E01 — Обогащение обычной заметки.** Сохранить F04 и дать приложению выполнить штатное enrichment с разрешённой LLM. Через UI проверить «Теги заметки»/«Поисковые слова ИИ» при наличии, поиском — слова «морфология», «речь», «фотоархив». **Ожидается:** поисковые подсказки появляются только после реального успешного вызова, title/body исходной записи неизменны. Отсутствие внешней LLM не значит FAIL: это `NOT_RUN_LIVE_MODEL`.

**E02 — Русская семантика.** Для F01/F02/F04 задать в чате «Найди сохранённые материалы об офлайн-моделях для русского», «Где инструкция про мобильный ИИ?» и «Найди заметку про морфологию». **Ожидается:** LLM использует существующий `search_local_notes`/reader и возвращает только реальные доступные записи; проверять recall вручную по эталону и ссылкам. Нельзя подменять этот тест локальным regex-поиском от лица чата.

**E03 — Теги: права автора.** Для F04 сохранить ручной `важное`, запустить повторное enrichment. **Ожидается:** ручной тег не удалён, модельных максимум пять на предложение, повторные значения нормализуются; авторский override сохраняется.

**E04 — Ручная правка блокирует перетирание.** Изменить теги F05 руками после появления auto-tags, сохранить, дождаться следующей индексации. **Ожидается:** выбор пользователя сохраняется; пересчёт не заменяет ручные теги без его команды.

**E05 — Устаревание подсказок.** В F04 заменить текст целиком с «морфология» на «акустические фильтры», запустить штатную индексацию. **Ожидается:** устаревшие model:auto terms/теги сняты/пересчитаны по политике override, поиск по старой гипотезе не выдаётся как подтверждённый материал; новый термин находится.

**E06 — Добавление вложения/наблюдения.** К обычной QA-заметке добавить подтверждённый OCR/распознавание или разрешённое текстовое наблюдение, затем проверить поиск. **Ожидается:** запущен текущий scheduler re-enrichment, старая модельная ревизия не приписывается новой версии.

**E07 — Источник vs гипотеза.** В текст F10 поместить вымышленные имя «Мария Северова», дату 2026-12-17 и «Казань». После enrichment проверить, что подсказки `people/dates/places` помогают искать, но **не изменяют** `source_publication_date`, GPS, `valid_from`, author, kind и не создают автоматически нового «Человека» или подтверждённое родство.

**E08 — Ссылка без текста / фото без OCR.** Сохранить F07 и F09 без подписи и реального извлечения. **Ожидается:** LLM не добавляет содержательных тегов/описаний объектов «по воображению»; оригинал не отправляется автоматически, обогащение может пропускаться.

**E09 — Фильтр и FTS.** Поиск точного тега F04 в интерфейсе Память (фильтр тегов) и сочетание «тег + текст + статус», затем убрать фильтр. **Ожидается:** точное совпадение, отсутствие посторонних записей, пагинация не теряет фильтр; реиндексация восстанавливает поиск из payload без смены authoritative store.

**E10 — Разграничение доступа.** Для F08 и архивной/удалённой/закрытой записи создать тестовый контролируемый spy transport. **Ожидается:** их текст не появляется в outgoing model prompt, LLM не видит их в обычном поиске; AppLock прерывает обработку, нет утечки после unlock.

**E11 — Гонка ревизии / rollback.** Детерминированным mock зависнуть перед ответом LLM; изменить текст, переместить раздел, заблокировать приложение или сменить профиль и затем вернуть ответ. **Ожидается:** старый ответ не коммитится на новую ревизию, нет частичного изменения tags/model_search/terms/links, нет ошибки индекса или cross-profile записи.

## 10. Критерии приёмки

**ACCEPT по проверенному пакету допускается, только если одновременно:**

- все затронутые обязательные автоматические тесты и required CI на **том же тестируемом коде** прошли; APK идентифицирована;
- создана/открывается неограниченная в рамках сценария иерархия, перемещения не нарушают ссылки, нет циклов или потери заметок;
- LLM **не выполняет** создание/удаление без UI подтверждения и не удаляет системный, защищённый, непустой или содержащий детей раздел;
- ИИ-теги и поисковые подсказки основаны на разрешённом реально доступном тексте; ручные поля и подтверждённые факты не перезаписаны; `Сохранить без ИИ` действительно запрещает последующую фоновую отправку;
- раздел/тег не назначаются «угадыванием» для пустого фото/недоступного URL, ACL/AppLock/profile/CAS защищают от гонок;
- backup v19/restore и соответствующие миграции проверены **в тестовой среде** без утраты данных;
- все обязательные для запрошенного уровня проверки имеют фактические доказательства; не осталось P0/P1 без решения.

Если технический пакет готов по CI, но отсутствуют live LLM/Vivo/restore доказательства, честный вывод — **ACCEPT_WITH_GAPS** или **INSUFFICIENT_EVIDENCE**, а **не** «прошло всё». Физические проверки допускается завершить отдельным отчётом на ту же APK. Возникший дефект не исправлять самовольно в этом сценарии: оформить точное воспроизведение, причину/предположение отдельно, PR по утверждённому процессу.

## 11. Источники реализации для диагностики

- `mobile/src/screens/LocalMemoryScreen.tsx` — дерево, переход вверх, перенос, фильтры, архив и корзина.
- `mobile/src/screens/HomeScreen.tsx` — предложение создания/удаления, кнопки подтверждения/отмены и receipts.
- `mobile/src/screens/MemoryImportScreen.tsx` — отдельное согласие на подбор, ручные теги, сохранение без ИИ.
- `mobile/src/screens/MemoryNoteScreen.tsx` — редактор, ручные теги, просмотр и извлечённый текст.
- `mobile/src/local-memory/sections.ts`, `repository.ts`, `storage.ts` и `backup.ts` — parent graph, транзакции, миграции, backup.
- `mobile/src/direct-agent/section-actions.ts`, `tool-catalog.ts`, `engine.ts` — разрешения и инструменты LLM `propose_create_memory_section` / `propose_delete_memory_section`.
- `mobile/src/media/import-llm-classifier.ts`, `mobile/src/direct-agent/enrich.ts`, `mobile/src/local-memory/enrichment-policy.ts` — классификация/обогащение и privacy-gates.
- `docs/ANDROID_UI_TESTING.md`, `docs/RELEASE_APK.md`, `docs/DEVICE_QA.md` — реальные границы сборки и испытаний.
