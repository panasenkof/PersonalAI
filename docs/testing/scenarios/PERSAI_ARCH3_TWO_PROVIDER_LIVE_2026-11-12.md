# PersAI ARCH-3 / ARCH-11 — адресная приёмка на двух LLM-провайдерах

**Статус:** подготовленный сценарий, **не выполнен**. Запускать **только после** реализации `buildSystemPrompt`, получения точного SHA и подписанного APK. Это **не повторная приёмка этапа 9**. Telegram/TG-11 и импорт истории Telegram сюда не входят.

## Цель

Проверить, что OpenAI Responses и другой провайдер (Anthropic либо DeepSeek с совместимым протоколом) получают **единые правила поведения по доступным инструментам**; при этом не выдумывают результаты недоступных инструментов и сохраняют пользовательские подтверждения/ACL. Публичные и приватные сведения не должны передаваться веб-поиску/моделям вопреки разрешениям.

## Обязательная идентификация среды

Зафиксировать в отчёте `docs/testing/reports/`: коммит `main`, SHA APK и точную версию приложения, телефон/Android, два *названия провайдера и модели* (без API-ключей), время/дату, включённые разрешения на интернет и фото. Сначала выполнить по одной операции без инструментов и с инструментом, убедиться, что оба подключения работоспособны. Не публиковать полные промпты с личными данными.

Использовать **тестовые заметки**, например `QA-ARCH3-ALPHA` с текстом «На полке стоят яблоки, груши и три книги» и `QA-ARCH3-BETA` с другим текстом; пустой тестовый подраздел `QA-ARCH3`. Для операций удаления/переноса — только эти записи. Нельзя очищать рабочие данные, работать с личными документами, выполнять внешнюю отправку писем или команд умного дома.

## Раздельные уровни результата

- **C1/автотесты:** `golden-tools` без изменений, `golden-prompt` обновлён только для утверждённого общего билдера; typecheck, Jest, browser smoke, native+emulator; ссылка на точный SHA.
- **LIVE_MODEL:** для каждого сценария отдельно `PASS / FAIL / NOT_RUN` на **каждом** провайдере; фиксировать *имя вызванного инструмента, проверяемые параметры, результат и наличие подтверждения*, без секретов и персональных данных.
- **C2/Android:** при проверке карточек и доступа на реальном телефоне — отдельный статус `PASS_PHYSICAL / FAIL_PHYSICAL / NOT_RUN_PHYSICAL`. Проверка API в CI не подменяет телефонный результат.
- **Критерий ARCH-3:** оба провайдера дают функционально эквивалентное поведение по активным инструментам (не обязательно дословный ответ). Ни одного выполнения мутации без подтверждения и ни одной утечки в выключенный канал. Если провайдер не поддерживает tool calling, фиксировать `NOT_SUPPORTED`, а не PASS.

**При FAIL:** записать воспроизведение, версия модели, SHA и минимально допустимые обезличенные доказательства; исправлять отдельным маленьким PR. Не обновлять эталонные снимки ради маскировки разницы и не закрывать ARCH-3 до реального двухпровайдерного подтверждения владельцем.
