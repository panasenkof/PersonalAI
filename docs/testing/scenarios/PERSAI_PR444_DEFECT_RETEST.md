# PersAI — повторная проверка дефектов PR #444 (агент)

**Источник:** `docs/testing/reports/PERSAI_MEMORY_AI_2026-11-09_f16f9298.md`, PR #444.  
**Исправления:** PR #445. Это отдельный исполняемый чек-лист, не заменяющий полный Android runbook.

## Правила фиксации

1. Перед тестом запиши SHA проверяемого `main` или PR, SHA APK, `versionCode`, Android/модель телефона, способ запуска, ссылку на CI. Не называй результаты другого SHA текущими.
2. НИКОГДА не очищай реальные данные приложения, не делай `pm clear`, не переустанавливай с `-d`/удалением. Никакого destructive restore в рабочий профиль.
3. При падении backup **не продолжай** удаление/перенос пользовательских записей, очистку корзины или тесты восстановления. Оригиналы остаются.
4. Скриншоты и логи с личными данными, ключом восстановления, SQLCipher-дампом, API-ключами не прикладывай к PR. В отчёте указывай только безопасный код `BKP-XX`, версию, этап операции и воспроизведение.
5. В каждой строке укажи `PASS_AUTOMATED`, `PASS_PHYSICAL`, `FAIL`, `BLOCKED`, `NOT_RUN` (разделяй автоматическую/физическую проверки).

## DEF-1 — экспорт зашифрованной резервной копии (P1)

**Подготовка:** Android 16/vivo V2405A, действующий рабочий профиль, не удалять исходные данные. При наличии другого тестового устройства повторить также на нём.

1. Открой **Настройки → Резервные копии**. Создай НОВЫЙ код восстановления. Сохрани его **вне отчёта и вне PR**, отдельно от будущего файла.
2. Отметь «Я сохранил код отдельно». Нажми **«3 · Сохранить файл копии»** один раз. Зафиксируй: появился ли системный диалог, текст уведомления и код `BKP-XX` при ошибке.
3. Если системный диалог открылся, сохрани в «Файлы»/доверенное локальное хранилище. Убедись **через файловый менеджер**, что реальный файл существует, не нулевого размера и доступен после полного закрытия PersAI. Закрытие меню «Поделиться» само по себе НЕ означает успех.
4. Закрой и вновь открой PersAI: записи, разделы, фотографии, история остаются. Перезапусти экспорт с новым кодом, если требуется, и убедись в отсутствии второй копии с тем же именем, скрывающей старую.
5. ТОЛЬКО в отдельном пустом QA-профиле/устройстве выполни восстановление из сохранённого файла с правильным кодом; сравни контрольные количества записей/разделов, историю, связи и вложения до и после. Заявление `PASS` требует чтения восстановленных записей, не одного сообщения «Готово».
6. На отдельном пустом QA-профиле протестируй неверный код, повреждённый файл, повторное восстановление в непустую память и отмену выбора файла. В каждом случае требуй отсутствия частичного импорта/потери исходных записей.
7. Если экспорт падает, запиши **только** безопасный код: `BKP-01` сохранение чатов, `BKP-02` preflight, `BKP-03` attach, `BKP-04` шифрование, `BKP-05` манифест, `BKP-06` проверка файла/целостности, `BKP-07` системный обмен. Не записывай секреты. Пометь B02–B06 как `BLOCKED`.

**Критерий устранения DEF-1:** два успешных экспорта (на реальном устройстве), проверенное наличие файла и успешное восстановление в отдельный пустой профиль; при ошибке — чёткая стадия без утечки ключа, но это НЕ исправление самого экспорта.

## DEF-3 — пустой поиск без фильтра

1. Память → общий поиск по отсутствующему тексту «капучино» без тега: «Ничего не найдено» + **«Попробуйте другой поисковый запрос.»**, без требования снять несуществующий фильтр.
2. Включи существующий тег и сделай запрос без совпадений: подсказка вправе предложить **снять фильтр**.
3. Очисти поиск/тег: обычный список снова виден; переключение разделов/архива не меняет активный фильтр скрытно.

## DEF-4 — счётчики разделов, корректность LLM

1. Сделай временную заметку в дочернем `QA9-*` подразделе, но не в непосредственном родителе. Попроси LLM удалить родительский раздел.
2. Ожидание: отказ `section_has_children`, **никакой** карточки на удаление. Если инструмент не вернул счётчики, модель не должна утверждать «Активных заметок: 0» как установленный факт.
3. Если модель вызывает `count_local_notes` с `collectionId`, уточни, что число относится только к **непосредственному** разделу; проверь отличие от суммарного числа по дереву.
4. Проверь отказ на непустом листовом разделе, на разделе с архивной/корзинной записью и защищённом системном разделе. Удаление оригиналов запрещено.
5. Отдельно сопоставь ответы модели с SQLCipher reader и UI на тестовом дереве; пометь как `FAIL` любую неподтверждённую точную цифру.
