# S9-2 — адресная Android-приёмка поиска и объединения дублей

Статус: **NOT_RUN_PHYSICAL / NOT_RUN_LIVE_MODEL**. Использовать APK после завершения S9-2, указать точный SHA и реальный результат каждого пункта. Не использовать личные данные; синтетический профиль с AppLock. Не подменять подтверждение на телефоне Jest или эмулятором.

## Данные
Подготовить в двух обычных разделах:
- три активные записи с одинаковым текстом, но разным регистром и пробелами; оставить разные названия, теги и вложения (одно фото, один документ).
- две записи с одинаковым точным source_url, но различающимся содержимым.
- две записи с похожим смыслом, но не совпадающим нормализованным текстом; они **не** должны считаться same_text.
- записи с теми же URL/текстом в «Входящих», «Документах», архиве, корзине и в стандартном подразделе закрытого раздела. Они не должны появиться.
- отдельную группу из шести одинаковых URL, группу с суммой более 12 уникальных тегов, группу с зависимыми связями/свидетельствами.
- при возможности более 500 активных обычных тестовых заметок для проверки неполного same_text-сканирования.

## Чтение
1. В обычном чате попросить «Найди дубли по URL». Убедиться, что вызван только единый инструмент find_duplicate_candidates, а модель получает группы из 2–5 активных обычных записей, их ID/версии/заголовки/количество вложений и тегов — без текста.
2. Попросить «Найди дубли по точному тексту». Проверить совпадение после нормализации регистра/пробелов; семантически похожие, но разные заметки не объединяются в кандидатов.
3. Для группы из 6 ссылок убедиться в признаке incomplete/partial, без возможности подтвердить неполную группу. При 500+ заметках убедиться в честном указании границы сканирования и отсутствии заявления «проверены все».
4. Прервать поиск Stop или AppLock: после блокировки/смены профиля результаты не должны выдаваться; во вновь открытом ходе нужно повторное чтение.

## Предложение и подтверждение — выполнять только после реализации карточки
1. Вызвать propose_merge_notes на группе из трёх, выбрать сохраняемую запись и проверить, что модель не может придумать ID, версию, другую группу или подменить keepNoteId после просмотра. Появляется карточка с названием сохраняемой записи, источниками, тегами и вложениями, предупреждением об отмене.
2. Отклонить карточку: память не меняется. Подтвердить повторное предложение: только changeNotes('merge') по явному нажатию, CAS внутри BEGIN IMMEDIATE, суммарные уникальные теги не более 12.
3. После объединения проверить сохранение оригиналов, ссылок на Share, исходных метаданных, версии и FTS; затем Undo через исходный undoNotes и фактический возврат всех записей и вложений.
4. Изменить одну из версий до подтверждения; при смене приватности раздела, появлении связи, 13-м теге или повреждении вложений — отказ без частичной записи. Undo после более поздних изменений не должен их затереть.
5. Перезапустить PersAI после подтверждения: квитанция Undo сохраняется, но непотверждённая карточка и прежние поисковые полномочия не возвращаются сами собой.

## Протокол
Записать APK SHA, версию Android, профиль, используемую модель/провайдер (если запускались), ссылки на скриншоты/логи, результаты SQLCipher до/после/Undo и явный статус PASS/FAIL/NOT_RUN каждого сценария. Живую платную LLM не запускать автоматически: это отдельная проверка по решению владельца.
