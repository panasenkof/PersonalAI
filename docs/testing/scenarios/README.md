# Сценарии тестирования PersAI для ИИ-агента

В этой папке хранятся **исполняемые инструкции приёмки**, а не отчёты об успешном тестировании. Агент должен открыть нужный документ, выполнить шаги на указанном SHA/APK и создать отдельный датированный отчёт с доказательствами.

## Актуальный сценарий

- [Android: иерархия памяти, LLM-инструменты, автоматические теги и поиск (09.11.2026)](PERSAI_ANDROID_MEMORY_AI_ACCEPTANCE_2026-11-09.md) — приёмка PR #439/#441/#442 с проверкой SQLite/FTS, privacy, AppLock, миграций, backup и регрессий Android.

## Инструкция агенту

1. Перед запуском прочитать корневой [AGENTS.md](../../../AGENTS.md), [план](../../../PLAN.md), [статусы](../../../Plans/ROADMAP_STATUS.md) и [границы Android CI](../../ANDROID_UI_TESTING.md).
2. Установить точные SHA исходников и APK, проверить разрешения/доступ к тестовой модели и устройству, создать защищённую резервную копию. Не очищать и не перезаписывать рабочие данные ради теста.
3. Провести каждый сценарий по его ID; не подменять реальное устройство или реальную LLM результатами моков и unit-тестов.
4. Результаты положить в `docs/testing/reports/` с матрицей ID → статус → фактический результат → доказательства → дефект. Папка отчётов создаётся при **реальном запуске**, а не заранее. Не публиковать персональные данные, ключи, PIN или содержимое backup.
5. Использовать `PASS_AUTOMATED`, `PASS_LIVE_MODEL`, `PASS_PHYSICAL`, `FAIL`, `BLOCKED`, `NOT_RUN`, `NOT_IMPLEMENTED` в явном виде. Отсутствие возможности проверки не считается успешной проверкой.

При P0 (утрата данных, bypass AppLock/ACL, автоматическое разрушительное действие или скрытая передача личных данных) остановить опасную ветвь и завести дефект. Изменения исходников и фиксы выполнять отдельным согласованным PR, не смешивая их с отчётом приёмки.
