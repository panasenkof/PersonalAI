# Проверочный набор поиска по памяти

Меряет, насколько гибко помощник находит сведения о пользователе (п. 8 плана).

- `memory-fixture.ts` — память вымышленного пользователя Ивана (25 записей по разделам, включая личные «Документы») и 39 вопросов с ожидаемыми записями. Категории: другая форма слова, синоним, через человека, по смыслу, «нет в памяти», личные записи.
- `evaluate.ts` — прогоняет вопросы через тот же код, что и приложение (`searchApprovedNotes`, `prepareDirectContext`), на настоящей SQLite FTS5 (`node:sqlite`). Считает, попала ли нужная запись в пятёрку найденных, ушёл ли помощник в интернет и не попали ли модели личные записи.
- `__tests__/memory-eval.test.ts` — запускается вместе с `npm test`, печатает таблицу и падает, если какая-то категория опустилась ниже нынешнего уровня (`FLOORS`). Когда поиск улучшится, уровень поднимают.

Добавить вопрос: допишите `{ q, category, expect: [id записи] }` в `EVAL_QUESTIONS`, при необходимости запись в `EVAL_NOTES`.
