# Проверочный набор поиска по памяти

Меряет, насколько гибко помощник находит сведения о пользователе (п. 8 плана).

- `memory-fixture.ts` — память вымышленного пользователя Ивана (25 записей по разделам, включая личные «Документы») и 39 вопросов с ожидаемыми записями. Категории: другая форма слова, синоним, через человека, по смыслу, «нет в памяти», личные записи.
- `evaluate.ts` — прогоняет вопросы через тот же код, что и приложение (`searchApprovedNotes`, `prepareDirectContext`), на настоящей SQLite FTS5 (`node:sqlite`). Считает, попала ли нужная запись в пятёрку найденных, ушёл ли помощник в интернет и не попали ли модели личные записи.
- `__tests__/memory-eval.test.ts` — запускается вместе с `npm test`, печатает таблицу и падает, если какая-то категория опустилась ниже нынешнего уровня (`FLOORS`). Когда поиск улучшится, уровень поднимают.

Добавить вопрос: допишите `{ q, category, expect: [id записи] }` в `EVAL_QUESTIONS`, при необходимости запись в `EVAL_NOTES`.

## Расширенная автоматическая приёмка предметной памяти (29.10.2026)

- `domain-fixtures.ts` — **54 полностью вымышленные записи**, по автомобилю (договор, СТС, полис, заказ-наряды, гарантия, стоимость ремонта, ТО), рецептам, сохранённым статьям про ИИ и другие темы, домашним вещам и медицине трёх разных людей.
- `__tests__/domain-battery.test.ts` — реальные `SCHEMA_SQL`, `SqliteMemoryRepository`, FTS, версионное чтение источника, ACL, исправления, фотоприложения, хэши оригиналов, PDF extraction, истинные/неизвестные координаты, принадлежность лабораторных результатов и изоляция личных данных. **Не** заменяет реальный PDF parser, ASR, vision embeddings и LLM.
- `__tests__/live-memory-model.test.ts` — три отдельных слепых вопроса к реальной OpenAI-compatible LLM на **только синтетических данных** (рецепт, автомобиль, отсутствие сведений). Условно включается при наличии `PERSAI_EVAL_LLM_API_KEY`, `PERSAI_EVAL_LLM_BASE_URL`, `PERSAI_EVAL_LLM_MODEL`. Тест проверяет ответ, ограничение числа модельных вызовов, отсутствие веб-поиска и утечки секретного маркера; результаты оцениваются независимо от scripted-LLM тестов.
- `../src/direct-agent/__tests__/memory-dialogue-simulation.test.ts` — шесть последовательных агентных сценариев с подменой **только** провайдера и нативного SQLite bridge, но с реальным агентом/каталогом/FTS/записью.
- `.github/workflows/memory-acceptance.yml` — **только ручной запуск** через `workflow_dispatch`, без `schedule`, `push` или автоматических LLM-вызовов. По явной команде пользователя запускаются Jest/TypeScript/SQL, Android APK + emulator smoke. Платная реальная LLM проверяется только при одновременной установке `live_llm=true`, вводе `paid_confirmation=RUN_PAID_LLM` и наличии секретов провайдера. Наличие ключа само по себе ничего не запускает. В live-тесте установлен предел **9 API-запросов за запуск** (3 вымышленных вопроса, максимум 3 обращения каждый). Результаты сохраняются как JSON artifact и summary; неполные/проваленные проверки не считаются PASS.

**Важно о границах:** наличие 54 вопросов и проходящих SQL-тестов не означает, что живой ИИ понимает все их перефразировки. `phrase` — контролируемый термин поиска, `q` — слепой вопрос для будущего масштабирования live-LLM-eval; этот уровень пока не градуируется автоматически для всех 54. Поиск по содержимому **неподписанной** фотографии, отсутствие/качество распознавания реальных документов и медицинская интерпретация без врача также не считаются проверенными. Физический C2 остаётся отложенным до приёмки владельцем после инвентаризации.

### Конфигурация GitHub Actions без передачи ключа в чат

В **Settings → Secrets and variables → Actions** нужного репозитория:

- **Repository secret**: `PERSAI_EVAL_LLM_API_KEY` — ключ тестового провайдера, желательно с минимальным бюджетом и отдельной ротацией.
- **Repository variables**: `PERSAI_EVAL_LLM_BASE_URL` — публичный HTTPS API URL до префикса `/v1`, `PERSAI_EVAL_LLM_MODEL` — имя модели.

Запускать **только по запросу владельца**: Actions → Memory acceptance (real algorithms + optional live LLM) → Run workflow. По умолчанию `live_llm=false`: выполняются только бесплатные по отношению к LLM детерминированные проверки (расходуются минуты GitHub Actions). Для отдельно одобренной платной проверки нужно одновременно выбрать `live_llm=true` и вручную ввести `paid_confirmation=RUN_PAID_LLM`. Без обоих подтверждений job обращения к внешней модели пропускается. Отдельные секреты хранятся исключительно в GitHub. Не сохранять токены в git, CI artifacts, тикетах или чате. Запросы через API имеют предел 9 за один тестовый запуск, но окончательная стоимость зависит от тарифа модели, количества токенов и настроек провайдера; абсолютный денежный лимит дополнительно задаётся на стороне провайдера.
