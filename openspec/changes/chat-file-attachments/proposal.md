# №84: файлы в сообщении чата

26.10.2026. Самостоятельный пакет после #125, не новая версия импорта заметок.

## Сценарий

Скрепка в composer → системный выбор → имя и миниатюра в черновике → убрать любой файл или нажать обычную отправку. Выбор не вызывает LLM. Без текстового вопроса используется явный нейтральный запрос «Посмотри приложенные файлы». Отправленные файлы видны в сообщении и входят в последние 8 реплик для уточняющих вопросов. Модель без vision может отказать: ошибка провайдера показывается, вложение остаётся в истории.

Вместо прежнего плюса «В память» в composer теперь скрепка для сообщения. Канонический импорт в заметку остаётся в Память → Добавить; камера по-прежнему явно ведёт в импорт памяти. Кнопки и сфера не размножаются. Выбранные файлы не создают заметку; сохранение предложений агента в память — отдельное явное действие.

## Данные и границы

JPEG, PNG, WebP; текст UTF-8 (TXT/MD/CSV/JSON и подобные). До 3 файлов на сообщение, до 2 МБ каждый; текст до 24 000 символов вместе. PNG/JPEG/WebP проверяются по сигнатуре; внешние URI и бинарные/неподдерживаемые форматы отвергаются. На диалог до 24 МБ вложений (для текста консервативная оценка размера), затем новый диалог. PDF/аудио/видео пока не отправляются через этот путь.

Используется существующий SQLCipher snapshot диалога, без plaintext-файлов для постоянного хранения и без миграции таблиц. Picker cache удаляется в finally. Повторная проверка при чтении snapshot; повреждённые вложения оставляют исходную запись нетронутой и делают её нечитаемой с существующим сообщением восстановления истории. Отмена/блокировка/смена диалога не применяют поздний результат. Ошибка до транспортного запроса восстанавливает черновик и файлы; при ошибке провайдера отправленная реплика с файлами остаётся в истории.

В запросе реально передаются image content blocks и текстовые блоки с обозначением недоверенных данных. Протоколы Responses, Chat Completions, Anthropic Messages. Нет отдельной загрузки в Files API, автоматического OCR, поиска изображения или отправки вложений вспомогательным моделям. Поддержку vision произвольного совместимого сервера нельзя вывести из его названия; ответственность за выбор модели остаётся видимой в composer.

## Референсы и решение

Документальное сравнение 26.10.2026, не испытание чужих приложений:
- [ChatGPT: работа с файлами](https://openai.com/academy/working-with-files/) — вход у поля сообщения и вопрос к прикреплённому материалу; адаптируем в одну скрепку и локальный черновик.
- [Claude: загрузка файлов](https://support.claude.com/en/articles/8241126-upload-files-to-claude) — вход из composer, различие файла чата и постоянных материалов проекта; сохраняем различие чат/память. Их набор форматов и серверные лимиты не переносим.
- Android-перевод: системный DocumentPicker, Back отменяет выбор; доступные подписи и явное удаление чипа. Web drag/drop и платформенные Apple-контролы не копируем. Существующие Nebula tokens/клавиатура/нижняя панель сохранены.

Транспорт: [OpenAI images](https://developers.openai.com/api/docs/guides/images-vision), [Anthropic vision](https://platform.claude.com/docs/en/build-with-claude/vision). Форматы сверены по официальной документации; runtime-проверки запросов покрыты тестами трёх протоколов.

## Проверки

TypeScript; реальная сериализация запросов трёх протоколов с текущими и историческими вложениями; парсинг сохранённого диалога; отсутствие вызова модели при выборе; восстановление черновика при отказе до отправки; лимиты/повреждённые файлы; блокировка/отмена picker и очистка cache; browser с сохранением и отправкой настоящего текстового блока. Android picker, настоящий vision endpoint, TalkBack, большой шрифт и память на реальном устройстве NOT RUN локально. Required minimal Maestro не расширяется.
