# Устройство и границы

Оригинал хранится отдельными BLOB-частями по 256 КиБ в SQLCipher v4, вне JSON заметки
и поискового индекса. Метаданные связаны с записью FK ON DELETE CASCADE. Это выбранная
для первого этапа реализация зашифрованного бинарного хранилища: общий ключ, атомарное
сохранение и штатный sqlcipher_export без второго криптоконтейнера. Ограничение 80 МиБ
сдерживает рост базы; производительность, WAL и потребление диска измеряются на телефоне.
При больших объёмах следует сравнить отдельное шифрованное файловое хранилище.

Создание заметки, частей оригинала и квитанции происходит одной транзакцией.
SHA-256 каждой части проверяется при открытии; MD5 нативного файлового API используется
только как практический признак повторного импорта, не как гарантия целостности/защита.
При повторе учитываются источник, содержание файла, заголовок, текст и чувствительность.
Ошибка/отмена откатывает запись вместе с вложением; пустой созданный раздел может остаться.

Просмотр материализует только выбранное вложение в приватный кэш. При скрытии/закрытии
компонента копия удаляется, проигрыватель размонтируется. После сбоя процесса очистка
выполняется при следующем открытии навигации. Внешнему приложению оригинал не передаётся.
Фото — Image, аудио/видео — expo-video; реальные кодеки требуют нативной проверки.

Входящие принимаются через уже установленный expo-sharing 57.0.23, raw payload API.
useIncomingShare не используется: его resolver способен обращаться в сеть за URL.
Обработчик ждёт разблокировки/видимости, сохраняет личные записи во «Входящие» и только
после успеха очищает тот же native intent. Группы идут последовательно, повтор уже
завершённых элементов возвращает ранее сохранённую запись. Основной экран не заменяется,
открытие записи — отдельная кнопка. Поддержка iOS в плагине отключена.

Граница надёжности: ещё не обработанный intent держит Android/Expo, собственной
постоянной зашифрованной очереди ДО разблокировки в этом этапе нет. Убийство процесса
или истечение разрешения content URI до принятия может потребовать повторной отправки.
После успешного принятия оригинал независим от источника и переживает перезапуск.
Это ограничение явно включено в приёмку; гарантированная очередь до разблокировки
потребует отдельного нативного приёмника и управления ключом, её нельзя считать проверенной.

Резервные копии v4 включают BLOB-таблицы. Восстановление v1–v3 остаётся совместимым,
v4 импортирует вложения в той же транзакции. Лимит копии увеличен до 2 ГиБ. Квитанции
входящих не восстанавливаются на другом телефоне. Полная нативная приёмка бэкапа и
облачные провайдеры остаются п. 63; здесь добавлена обязательная совместимость вложений.

Источники: [Expo Sharing](https://docs.expo.dev/versions/latest/sdk/sharing/),
[Expo FileSystem](https://docs.expo.dev/versions/latest/sdk/filesystem/).
Точные API сверены с установленными исходниками и типами SDK 57, а не с latest SDK 58.
