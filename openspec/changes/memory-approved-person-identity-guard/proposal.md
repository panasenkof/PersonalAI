# №66.4 / M2 — имя не является идентификатором человека

**Обнаруженный дефект (REL-03/04, RE13, SAVE-02):** `saveApprovedNote` сохранял подтверждённую заметку и затем использовал `(await entitiesByAlias(name, "person"))[0]`. При двух Мариях, Максимах или Еленах первый результат зависел от порядка обновления и мог создать неверную постоянную связь. Похожая ошибка затрагивала связь стандартной заметки с закрытым человеком.

## Небольшое исправление, без параллельного графа
- Результаты точного поиска alias проверяются **до создания заметки**: при нескольких кандидатах отказ от автоматического связывания с понятным текстом «уточните человека или сохраните без связи»; ни одна запись/связь не создаётся.
- Для единственной известной персоны проверяются active record, стандартная коллекция и standard/inherit sensitivity. Совпадение с закрытым профилем/разделом не раскрывает подробности личности и не становится связью.
- Одобрение заметки в sensitive разделе с параметром person требует отдельного пользовательского разрешения связи; сама заметка может быть сохранена **без** person. Существующее сохранение документов без person не меняется.
- Единственное разрешённое совпадение `personId` связывается через **существующий** `db.linkEntities(...,"about")`. Никакой новой таблицы или второго поискового движка. `about` остаётся упоминанием/направленностью темы, не `participant_of`, `has_sister` или подтверждённым родством.
- Уже имеющийся `memoryErrorMessage` показывается в chat UI; хранимый черновик не удаляется при отказе.
- В рамках M1/M2 следующей задачей остаётся атомарность source save + identity/alias resolution + evidence/decision с CAS: создание новой person entity в текущем legacy API не полностью транзакционно. Это **не** повод создать второй граф/очередь до M1.
