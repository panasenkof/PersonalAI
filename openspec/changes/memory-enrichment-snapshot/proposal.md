# Актуальность модельного индекса памяти — №66.1 / M10

Если заметка изменена, удалена, перенесена или закрыта от модели во время запроса, поздний ответ не должен стать её текущим индексом. Проверка версии и прав, слова и автоматические связи записываются одной транзакцией на соединении выбранного профиля. Отмена до commit откатывает весь результат; новый проход получает актуальный источник.

Schema v6 добавляет `source_record_version` и `source_collection_name` к `memory_index_terms`. Timestamp не служит доказательством актуальности. Старые модельные строки без версии становятся pending; пользовательские слова, исходники, оригиналы и ключи сохраняются. Миграция атомарна, резервные копии v1–v6 читаются. Производные слова/новые автоматические связи старой версии исключаются из поиска.

Новые связи получают `source_kind=model:auto` и версию источника; неоднозначное имя или защищённая целевая запись не выбираются автоматически. Ручные и исторические связи без происхождения не удаляются по догадке. Полный reviewable relation pipeline остаётся №66.4.

Состав внешнего запроса прежний: заголовок, тело обычной заметки и название раздела; новые вложения и extracted text не добавляются. Видимая квота/политика №54а — отдельный остаток. Переключение профиля, AppLock и отключение обработки отменяют старый проход; после отмены он не открывает БД ради обновления счётчика.

Проверки: отложенный ответ после edit/archive/trash/delete/move/ACL/rename; одинаковые timestamps; отказ индекса и отмена внутри транзакции; повтор/ручные связи/неоднозначные имена; runner lock/disable/profile; v5→v6 с ошибкой и повтором. Node SQLite проверяет SQL/данные/откат, а не нативное шифрование или Android lifecycle.
