## Решения при реализации
- Запрос — тот же адрес и ключ, что у активного подключения, без инструментов и без памяти; текст записи помечен как данные, не инструкции. Ответ — JSON `{terms, people}`, до 25 слов.
- Слова модели хранятся одной строкой `model:auto` на запись: смена модели заменяет их. Пустой ответ тоже сохраняется — запись считается обработанной. Правка текста делает запись снова ожидающей (сравнение со временем правки).
- Люди из ответа связываются (`about`) только с уже существующими записями-людьми: новых записей без подтверждения не появляется.
- Поиск: найденный человек приносит связанные с ним факты (до трёх людей, по 8 фактов). Основа слова из трёх букв («шеф» из «шефа») ищется только среди индексных слов и имён.
- Фон: после сохранения записи, через 8 секунд после запуска, по кнопке «Подобрать сейчас»; по 10 записей, до первой ошибки, останавливается при блокировке приложения. Выключается в Настройки → Умный поиск по памяти.
- Проверочный набор с ответами модели из `EVAL_MODEL_TERMS` (механизм, а не качество модели): синонимы 100 %, через человека 100 %, по смыслу 100 %. Без индексных слов значения не изменились, «нет в памяти» — 100 % (служебное «работает»).
