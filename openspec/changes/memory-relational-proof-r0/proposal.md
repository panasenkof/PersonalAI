# №66.4 · R0 — доказательная цепочка «моя сестра → участник разговора»

**Этап:** pure typed deterministic contract + C1 fixtures, без SQLCipher-таблиц связей и без подключения UI/поискового инструмента. Зависит от безопасного профилированного memory-source read (#172).

## Правила

- Обобщённое sibling_of или brother_of не доказывает женское родство по запросу «сестра»; только явное sister_of (или позднее проверенное правило пола/роли).
- Работа строго со стабильными ID людей/разговоров, а не совпадающими именами. Отношение `sister_of` связывает **конкретного пользователя-персону** и родственника, а `participant_of` конкретное событие-разговор и персону.
- `mentioned_in` и `about` **никогда** не являются основанием для участника беседы. ASR или опечатка «Лзиой» без разрешённой идентичности — только потенциальная гипотеза на подтверждение.
- Для каждого ребра необходимы: статус confirmed, доказательство current, resolved identity, совпадающие source/target/evidence record_version и право читать источник. Derived/model candidate не получает confirmed без отдельной пользовательской операции.
- Read path возвращает только `conversationId`, `relativeId` и ID рёбер-подтверждений; **не** обещает, что у события есть аудио, таймкод или расшифровка. Открытие оригинала и source location — последующий отдельный проверяемый переход.
- Вход уже ACL-scoped и bounded; алгоритм дополнительно исключает закрытые/stale/retracted связи и ограничивает число подходящих ребер/путей. Не раскрывать причины отсутствия закрытой цепочки.
- Без собственной новой таблицы/очереди proposals: M1 согласует нормализацию этих proofs с имеющимися temporal claims/evidence/decisions и `memory_relations`, затем создаст физическую миграцию/restore один раз.

## C1

R1/R2: порядок внесения родства и беседы не влияет на подтверждённую цепочку. R4: две Лизы не смешиваются. R6: mention не participation. R7: изменение ревизии/отзыв свидетельства выключает путь. R8/R11: закрытый промежуточный источник не течёт через результаты. R9: bounded partial, без придуманных аудиоссылок и времени. Недостоверные/самоссылающиеся ребра отвергаются.

**Открыто:** реальное хранилище evidence/decisions/undo, источник ID себя, инкрементальное разрешение имён, reverse lookup к source-attachments, поисковая интеграция, M4-UX и physical Android C2. Этот PR только foundation, не исполнение пользовательского запроса ID01 end-to-end.
