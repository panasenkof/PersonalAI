# №66.4 R2a — reversible user retraction through common review journal

## Scope
- Preserve exactly one canonical edge (`memory_relations`) and witness (`memory_relation_evidence`). A retraction changes the existing witness's `state`, not the underlying relationship ID. Search and proof traversal already require state=confirmed, so the revoked path disappears without modifying original source or alternative witnesses.
- SQLCipher v13 adds one `decision_version` CAS column to existing witness rows and an immutable, **domain-neutral** `memory_review_actions` journal. It has a domain/target XOR CHECK: relation evidence now, temporal proposals later. No second relation graph, candidate table, source store, FTS or search algorithm. Existing temporal legacy journal remains authoritative for prior temporal decisions until a controlled C3 migration; do **not** duplicate those decisions into the new journal.
- Two explicit user actions via existing profile-leased `MemoryRepository`: `retractRelationWitness` and `undoRelationRetraction`. Both require userConfirmed=true, current positive decision version, three active standard-scope entity versions and still-existing literal quoted source. They perform one SQLCipher transaction, CAS state/version and append immutable action. Only the immediate latest retraction can be undone. Reject second undo, stale source edit/private witness, invalid/missing decisions, and tool-supplied unconfirmed operations. Do not silently re-accept a rejected witness.
- SQLCipher backup manifest v4 counts `memory_review_actions` before any destination writes and restores actions after the relation witness FK parent, all inside rollback-safe transaction. v12 ciphertext restores named witness columns (default decision_version=1); v11 manifest v2 and older archives remain supported. No plaintext sidecar.
- C1: original v12 installed file upgrades to v13 with IDs/key intact, two-witness graph retraction/undo CAS, stale evidence cannot be restored, one immutable journal entry per actual user action, foreign key constraints, old v12 export/restore and v13 forged/omitted review table count reject without mutation. Android-native physical device C2 remains unverified.

## Explicit incomplete work
This is an R2a **infrastructure slice**, NOT a full R2 review inbox or user-facing relation decision UI. R2b will add candidates/reject/defer (and durable suppression) to the same unified review inbox, without inventing a second independent acceptance workflow. R2c will integrate the accepted temporal and relation decision sources behind one user-visible queue. R3b adds source opening and conversation intent resolution through existing searchMemory and source reader. C3 removes legacy duplication only after M1–M4 pass.
