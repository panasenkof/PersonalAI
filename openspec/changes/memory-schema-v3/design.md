# Design: схема памяти v3

## Таблицы (все внутри SQLCipher)

| Таблица | Поля | Назначение |
| --- | --- | --- |
| `memory_entities` (есть) | + `kind TEXT NOT NULL DEFAULT 'note'` | Тип записи |
| `memory_chunks` (новая) | `id`, `entity_id` → entities, `ord`, `text`, `content_hash`, `created_at` | Куски для поиска и передачи модели |
| `memory_aliases` (новая) | `entity_id`, `alias`, `normalized`, UNIQUE(entity_id, normalized) | Имена и прозвища |
| `memory_index_terms` (новая) | `entity_id`, `terms`, `source` (`user` / `model:<имя>`), `created_at` | Индексные слова |
| `memory_vectors` (новая) | `chunk_id` → chunks, `model`, `dim`, `vector BLOB` (float32), `content_hash` | Векторы; пересчёт, если `content_hash` или `model` изменились |
| `memory_search_fts` (новая FTS5) | `entity_id UNINDEXED`, `chunk_id UNINDEXED`, `title`, `body`, `terms`, `aliases`; `prefix='2 3 4'` | Поиск: фраза, слова, основы, индексные слова, имена |

`memory_notes_fts` удаляется в той же транзакции переноса, когда новый индекс построен.

Решения при реализации:
- Тип по умолчанию берётся из раздела: «Люди» → `person`, «Важные даты» → `event`, «Предпочтения» → `preference`, «Документы» → `document`, «Обо мне» → `fact`, иначе `note`. При переносе старых записей — только `person` для «Людей», остальное `note`.
- Куски до 700 знаков: абзацы склеиваются, длинный абзац режется по предложениям. У куска id `<запись>:<номер>`; при смене текста кусок пересоздаётся, его векторы удаляются каскадом.
- Токенизатор SQLite не приравнивает «ё» к «е», поэтому индекс и запросы хранят «е».
- Вес столбцов bm25: название 4, текст 1, индексные слова 2, имена 4. Запись с несколькими кусками попадает в результаты один раз — с лучшим куском.
- Индексные слова хранятся по источнику (`user`, `model:<имя>`) — одна строка на источник.
- Резервная копия переносит записи, имена и индексные слова; куски, поисковый индекс и векторы строятся заново при восстановлении.

## Миграция
1. `BEGIN IMMEDIATE`; создать новые таблицы.
2. Для каждой записи: `kind` = `note` (или `person` для раздела «Люди»), куски из `payload.body`, строка в `memory_search_fts`.
3. `PRAGMA user_version = 3`; `COMMIT`. Ошибка — `ROLLBACK`, база остаётся v2.
4. Индексные слова и векторы для старых записей строятся позже, в фоне.

## Поиск
Ранжирование — RRF по спискам: FTS (bm25), имена/связи, векторы; поправка на свежесть (`updated_at`, `valid_until`) и раздел. В модель — не больше пяти кусков, только из обычных разделов.

## Помощник
Инструмент `draft_memory_fact` (вместо `draft_local_note`, старое имя тоже принимается): `title`, `body`, `section`, `kind` (без `document`), `person`, `date` (ГГГГ-ММ-ДД). Все поля обязательны, отсутствующее — `null` (строгая схема OpenAI). Факт о человеке после подтверждения связывается (`about`) с его записью в «Люди»; если записи нет, она создаётся тем же подтверждением. Неверный тип или дата отбрасываются.
