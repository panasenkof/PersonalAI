# Схема памяти v3

## Why
Сейчас каждая запись — заметка с заголовком и текстом. Поиск не знает, что запись про человека, что «Аня», «Анна» и «сестра» — один человек, и не может искать по смыслу или по синонимам. Для гибкого поиска нужна структура.

## What Changes
- Тип записи: `fact`, `person`, `event`, `preference`, `document`, `note`.
- Один факт — одна запись («Аня любит кофе»); длинные записи и документы делятся на куски 400–800 символов.
- Индексные слова записи (синонимы, связанные понятия, нормализованные даты) — отдельная колонка FTS.
- Имена и прозвища людей и проектов.
- Связи «факт — человек/проект» заполняются (таблица `memory_relations` уже есть).
- Векторы кусков с названием модели и хешем текста.
- `valid_from` / `valid_until` и уверенность заполняются для фактов.
- Миграция `user_version` 2 → 3 в транзакции, со старыми записями без потерь; резервная копия поддерживает v1–v3.

## Impact
- `mobile/src/local-memory/storage.ts`, `repository.ts`, `backup.ts`, `types.ts`, тесты миграции и резервных копий.
- Изменение формата резервной копии (с обратной совместимостью).
