# Решение по организации

Это сравнение возможностей текущей схемы на пользовательских сценариях,
а не результат измерения удобства на телефоне.

| Сценарий | Только дерево | Разделы + ключевые слова | Разделы + слова + связи |
|---|---|---|---|
| Рецепт одновременно «ужин» и «без сахара» | Нужны копии или выбор одной папки | Одна запись и несколько слов | То же, плюс связь с предпочтениями |
| Гарантия из фото и подпись | Папка помогает навигации, но не поиску внутри | Поиск по обоим текстам | Дополнительно связь с покупкой |
| Что любит конкретный человек | Путь зависит от выбранной папки | Нужны имя и синонимы | Есть тип person, альтернативные имена и связи |
| Приватная запись при переносе | Права легко спутать с путём | Права проверяются отдельно | То же, фильтрация также на переходе по связи |

Выбор: сохранить плоские разделы как основную навигацию, слова для поиска и
альтернативные названия как дополнительную классификацию, связи — для отношений
между записями. Уже существующие слова для поиска не выдаём за полноценный
интерфейс тегов: фильтрация по тегам пока отдельная доработка.

ID записей и вложений стабильны; перенос не изменяет ID и не снижает приватность.
Миграция в дерево сейчас не нужна. Существующие записи не перемещаем автоматически.

Пункт 56 остаётся отдельным расширением: версионируемый декларативный шаблон
раздела (имя, описание, поля, типы, обязательность) поверх payload_json,
предпросмотр изменений и явное подтверждение, история и обратимость.
LLM предлагает изменение шаблона, но не исполняет произвольный SQL.
В этой итерации шаблоны ещё не реализованы.

# Проверка поиска

При сохранении результата фонового вычисления сравниваем переданный hash
с embeddingHash текущего заголовка и текста. Поздний результат пропускается;
очередь продолжает видеть недостающий актуальный вектор.
При чтении также проверяем hash: это закрывает старые векторы в существующих БД
без полной миграции или очистки. Полнотекстовый поиск остаётся доступен.

SQL-тесты покрывают переименование, изменение текста во время вычисления,
перенос, корзину, восстановление, объединение, отмену и окончательное удаление.
Искусственные векторы проверяют корректность индекса и фильтрации, не качество
реальной модели. Порог сходства и top-k не меняем без измерений.
