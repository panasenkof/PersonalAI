# №72.2 / T2c1 — очередь подтверждения временных предложений

**Зависимости:** PR #168 (SQLCipher v11), #169 (user CAS/undo), #170 (typed same-scope staging) и #171 (source-backed history) объединены в main, обязательные CI PASS. Этот пакет не заменяет M4-UX и не одобряет изменение автоматически.

## Цель

Создать доступный прикладному слою `MemoryRepository` контракт «На проверке». Ранее методы создания и подтверждения временных фактов работали как внутренние низкоуровневые функции и не предоставляли безопасный список предложений.

## Инварианты

- `temporalReviewInbox({collectionId,limit,before})`: только standard коллекция, обе записи `active`, обе individual sensitivity `standard/inherit`, обе ревизии источника совпадают, у обоих claims есть прямое/derived свидетельство соответствующего источника.
- `pending` и `deferred` в одной ограниченной (до 25) выдаче; nextCursor строится только по видимым, достоверным версиям. Никаких заголовков или count для private, secret, sensitive, unclassified, разных коллекций. Ограниченная сортировка по созданию предложения и устойчивому ID.
- Карточка содержит исходные цитаты и значения, а также версии предложения/обоих claims для последующего CAS. Новое свидетельство после просмотра требует новой проверки при нажатии действия.
- `MemoryRepository` даёт `stageTypedTemporalFact`, `temporalReviewInbox`, `decideTemporalChange`, `undoTemporalChange`, `temporalKnowledgeHistory`. Все вызовы через существующий profile/session lease, не хранить за экраном старое SQLCipher соединение после lock/profile change.
- Публичные методы не включаются в инструментальный интерфейс LLM и не вызываются фоново. `accept` продолжает требовать явно подтверждённой пользователем границы окончания, не экстраполируя дату из новой заметки.
- Никаких новых таблиц, дублирующих индексов, глобальной миграции/рефакторинга.

## Критерии C1/C2

Синтетический регрессионный сценарий: работа А→Б→В даёт три proposal, стабильный cursor без дублей, цитаты и версии, explicit accept→undo через repository и видимость pending после undo. Изменение source version скрывает stale предложение до исправления. Проверка protected/cross-collection и некорректного cursor не раскрывает число закрытых кандидатов. CI exact SHA с TypeScript/Jest, браузером, Android APK и Maestro; физический Android и UI acceptance остаются открыты.

## Остаток до M4-UX

Показать source evidence в реальных карточках с действиями подтверждения/не связывать/позже, добавить выбор точной или неизвестной даты, явное редактирование фактов и identity relation proposals. Интеграция automatic extraction из чата/заметок требует source receipts/idempotency и правил sensitivity; отсутствие UI не позволяет назвать T2 завершённым. T3b current/as-of и №66.4 всё ещё отдельные этапы. Консолидация только после M1–M4 и соответствующего C1/C2, согласно PLAN §2 6.5.
