# №72.2 T2a — согласованное решение пользователя по временным фактам

**Зависимость:** PR #168 (SQLCipher v11 T1b) должен быть в `main` с зелёным CI точного SHA до слияния этого пакета. Это **первый доменный кусок T2**, не готовый интерфейс и не полная №72.2.

## Обязательные ограничения

- Решение вызывает только осознанное действие пользователя в приложении: модель и фоновая обработка могут предложить, но не подтверждают смену работы/жилья.
- Вход: `proposalId`, версии предложения, предыдущего и нового утверждения, выбор `accept | keep_both | defer | dismiss`. Начало/конец старого состояния не выводятся из даты новой записи.
- Для `accept` требуется **отдельная введённая пользователем** граница завершения. `unknown` и `approximate` допустимы **без выдуманной даты**, как и явно указанный день/месяц/год с исходной формулировкой. Для `keep_both` прежнее состояние не меняется.
- Под SQLCipher `BEGIN IMMEDIATE`: проверка текущей версии и существования активного источника, консервативного типа конфликта из T1a, CAS обновления состояния и статуса, новая неизменяемая запись `memory_temporal_decisions`. При любой ошибке всё откатывается.
- Отмена только последнего решения, при совпадении версий обоих утверждений, источников и статуса предложения. Отмена восстанавливает прежние границы, не стирает историю; новая версия утверждения фиксируется даже при возврате старого значения.
- `keep_both` сохраняет действие в журнале (`dismissed` + `action=keep_both`), не переспрашивает бесконечно на том же proposal. Отмена может вернуть карточку в pending.
- Никакой отправки данных наружу, нового источника индексации, сервера и экранов в этом PR. Проверяемая единица — операция и её версия, а не вся заметка целиком.

## Проверки C1/C2

Синтетические Node SQLite/Jest сценарии: точная/неизвестная граница; переход работы А→Б с `unknown`, старый текст/источник остаются; отмена оставляет две записи журнала; `keep_both` не завершает А; повторное действие со stale версиями не применяется; устаревший источник блокирует решение; отказ журнала откатывает claim, proposal и transaction. Дополнительные реальный SQLCipher/Android, UI acceptance и связь с семейным графом должны быть отмечены **NOT VERIFIED** до соответствующего прогона.

## Остаток T2 и T3

Доменный T2a API пока не подключён к экрану и не вызывается из сохранения заметки. Дальше: scoped поисковый подбор кандидатов, демонстрация исходного доказательства и причин, групповые карточки на редактирование, выбор/уточнение дат, CAS snapshot и согласование с relational №66.4. История текущих состояний, as-of/events/count и поиск «сестра → аудио» — T3/№66.4. Миграция и backup v11 принадлежат T1b, не дублировать.
