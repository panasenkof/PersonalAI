# №72.2 · T2b — локальный адресный поиск кандидатов при записи типизированного факта

Статус: отдельный кодовый пакет. Не подключён к автоматическому извлечению фактов из чата/заметок и к UI.

## Границы
- stageTemporalCandidateWithReview(db,candidate) внутри одного BEGIN IMMEDIATE для уже разблокированной SQLCipher-сессии.
- Валидирует ревизию источника, атомарно сохраняет claim и цитату, затем проверяет максимум 33 существующих факта с теми же подтверждённым subject ID, predicate, role/context и коллекцией.
- Только asserted, положительные, прямые, single-valued state. Event, hypothetical, отрицание, многозначное отношение, незавершённая идентификация и завершённое старое состояние не закрываются автоматически.
- Для одинакового значения возможен review reconfirmation; для разного — возможный change; предложение никогда не равняется подтверждению и не проставляет end date.
- Только standard collection с активными записями standard/inherit. Для private/secret/unclassified сохраняет факт без сканирования: skipped_privacy. Cross-collection ждёт scope/ACL-aware UI.
- Ответ: claimId,proposalIds,reviewScope,truncated. Не более 32 предложений и честный truncated при переполнении; используются существующие v11 индексы.
- Уже сохранённое решение не открывается автоматически повторно. Новый typed input — выбор вызывающего кода; механизм стабильных импортных receipts/idempotency для повторного извлечения остаётся T2c.

## C1/C2
Синтетическая C1: А→Б создаёт review, но не завершает А; повторный ремонт не пересматривает прошлый; закрытые источники/другая коллекция не перечисляются; stale revision блокируется; отказ записи proposal атомарно откатывает claim/evidence; лимит 33 выдаёт 32 + truncated=true.
Native Android реальный SQLCipher и сценарии user UI отдельно: C2 NOT VERIFIED до соответствующей проверки.
