# Дизайн: Nebula как неизменяемый UI-контракт

Полная нормативная спецификация: [docs/design/NEBULA_VISUAL_CONTRACT.md](../../../docs/design/NEBULA_VISUAL_CONTRACT.md). **Этот OpenSpec не является реализацией.**

## Границы и компоненты
- `NebulaBackground` — слой космического фона с depth/particles/star-flight, не интерактивен, quality mode.
- `NebulaCore` — высококачественный morphing-объект с visual state `idle|listening|transcribing|thinking|responding|offline|error`.
- `NebulaIdentity` — REF-ICON-A, assets/Android adaptive icon, splash, high-res reference.
- `ChatShell`, `ChatComposer`, `AttachmentPreview`, `ChatAttachmentCard` — содержание диалога, ввод, работа с файлами и состояния.
- `MemoryContent`, `SettingsSections` — общая система локальных карточек, фильтров и вложенных категорий.

## Инварианты
- Контент, ввод и экранная клавиатура выше любых визуальных эффектов; `pointerEvents` для декоративных слоёв отключены.
- При выключении анимации `NebulaCore` остаётся высококачественным статичным референсом, а не просто заливкой.
- Платформенная навигация Home / Memory / Settings и действующие данные не меняются.
- Вложения в chat не означают автоматическую запись в SQLCipher или отправку модели; для runtime требуется отдельная OpenSpec и capabilities/adapters.
- Первая сфера — иконка. Вторая — внутри приложения. Менять назначения нельзя без согласования.
- Дизайн не должен добавлять платежи, `Plus` badges, новой LLM, новой страницы, видимой по умолчанию, или лишние подсказки.

## Механизм реализации
1. Подтвердить оригиналы и активы источника, сравнить side-by-side при подготовке бинарных launcher assets.
2. В отдельном spike сравнить Skia shader/path vs pre-rendered frames vs Reanimated+Skia hybrid; сохранять morph-подобие, а не только круговое масштабирование.
3. Создать семантические токены и библиотеку компонентов. `NebulaCore` имеет логическое состояние отдельно от графики.
4. Затем вводить экраны небольшими PR со снимками до/после и нативной проверкой.
5. Если целевой FPS/энергопотребление не достигнуты, сообщить о компромиссе и показать два альтернативных визуальных результата вместо скрытого упрощения.

## Критерий завершения change
Документация готова тогда, когда визуальный контракт и его SHALL-сценарии опубликованы и приоритет в PLAN обновлён. Фактическое внедрение Nebula не является критерием завершения *документационного* change.
