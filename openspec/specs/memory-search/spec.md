# Поиск по памяти

## Purpose
Как помощник находит сведения о пользователе перед ответом и когда обращается к интернету.

## Requirements

### Requirement: Сначала память, потом интернет
Система SHALL перед каждым ответом искать в памяти телефона и обращаться к интернету, только если память ничего не дала или вопрос просит свежие данные.

#### Scenario: В памяти есть ответ
- **WHEN** поиск по памяти нашёл подходящие записи и вопрос не просит свежих данных
- **THEN** интернет-поиск не выполняется, модель получает найденные записи

#### Scenario: В памяти пусто
- **WHEN** поиск по памяти ничего не нашёл и интернет-поиск включён
- **THEN** в чате сразу появляется «В памяти ничего не нашлось. Ищу в интернете.», затем выполняется интернет-поиск

#### Scenario: В памяти пусто, поиск выключен или запрещён
- **WHEN** поиск по памяти ничего не нашёл, а интернет-поиск выключен в подключении или в вопросе сказано «не используй интернет»
- **THEN** в чате появляется сообщение, почему интернет не использован, и модель отвечает без него

#### Scenario: Вопрос о самом пользователе
- **WHEN** вопрос вида «что ты помнишь обо мне»
- **THEN** интернет не используется; при пустой памяти помощник предлагает рассказать о себе

### Requirement: Поиск всеми способами по словам
Система SHALL искать по всей фразе, по каждому ключевому слову и по основе каждого слова без русского окончания (префиксный поиск FTS5) и ставить выше записи, найденные бо́льшим числом способов; внутри поиска — по релевантности bm25.

#### Scenario: Другая форма слова
- **WHEN** в памяти запись «продала машину», а вопрос «где машина сестры?»
- **THEN** запись найдена

### Requirement: Служебные слова не находят записи
Система SHALL не искать по вопросительным и служебным словам («какой», «сколько», «зовут», «лет», «стоит»…) и по основам короче четырёх букв, кроме основ имён (слово с заглавной буквы не в начале вопроса).

#### Scenario: Ответа в памяти нет
- **WHEN** пользователь спрашивает «Сколько лет Роберту Де Ниро?», а в памяти есть запись «Маше 7 лет»
- **THEN** поиск по памяти ничего не находит, помощник сообщает об этом и ищет в интернете

#### Scenario: Имя в другой форме
- **WHEN** пользователь спрашивает «Сколько лет Маше?», а в памяти есть «дочка Маша, ей 7 лет»
- **THEN** запись находится по основе имени

### Requirement: Проверочный набор
Система SHALL при каждом прогоне тестов мерить поиск по памяти проверочным набором (`mobile/eval`) и падать, если доля найденных ответов в любой категории опустилась ниже зафиксированного уровня, если хоть одна запись личного раздела ушла модели или если помощник ищет в интернете, когда нужная запись уже найдена.

### Requirement: Только разрешённые записи уходят модели
Система SHALL передавать модели не больше пяти фрагментов и только активные записи из разделов с уровнем «обычный».

#### Scenario: Личный раздел
- **WHEN** совпадение найдено в разделе «Документы» (личный) или в архиве
- **THEN** оно не передаётся модели

### Requirement: Сбой интернет-поиска не отменяет ответ
Система SHALL при сбое интернет-поиска отвечать без него, передавать модели дословную причину сбоя и просьбу назвать её в ответе, а пользователю показывать строку «⚠ Интернет-поиск не удался — <причина>» перед ответом.

#### Scenario: Поисковик не ответил
- **WHEN** поисковый сервис не ответил за 12 секунд
- **THEN** в чате видно «<адрес>: ответ не завершился за 12 с», а ответ модели всё равно приходит

#### Scenario: Ключ поиска не принят
- **WHEN** Tavily или Яндекс вернули HTTP 401
- **THEN** причина звучит как «api.tavily.com: ключ API не принят …», ключ в тексте не появляется, модель в начале ответа называет эту причину

#### Scenario: Закончился бесплатный лимит
- **WHEN** Tavily вернул HTTP 432 или 433
- **THEN** причина — «исчерпан лимит тарифа — бесплатные запросы на этот месяц закончились»

### Requirement: Проверка поиска в настройках
Система SHALL в настройках подключения с включённым интернет-поиском давать кнопку «Проверить поиск», которая выполняет один настоящий поиск выбранным способом и показывает число найденных ссылок или точную причину сбоя.

#### Scenario: Поиск работает
- **WHEN** пользователь нажал «Проверить поиск», а сервис вернул результаты
- **THEN** видно «Поиск работает: найдено ссылок — N, первая: <адрес>»

#### Scenario: Поиск выключен
- **WHEN** «Искать в интернете» выключено
- **THEN** запрос не отправляется, видно, что поиск выключен

#### Scenario: Запрос отклонила защита сервиса
- **WHEN** поисковый сервис вернул HTTP 403 со страницей защиты (например, Cloudflare) вместо ответа API
- **THEN** причина говорит, что запрос отклонила защита сервиса, обычно из-за страны или сети, советует проверить с VPN и показывает заголовок страницы; другой текст ответа не показывается

### Requirement: Способы интернет-поиска
Система SHALL предлагать поиск через Яндекс (Yandex Cloud Search API), Tavily и, для подключения OpenAI, встроенный поиск OpenAI; ключ поиска SHALL принадлежать одному сервису и никогда не отправляться другому.

#### Scenario: Поиск через Яндекс
- **WHEN** выбран Яндекс, введены API-ключ и идентификатор каталога
- **THEN** запрос уходит на `searchapi.api.cloud.yandex.net/v2/web/search` с заголовком `Authorization: Api-Key …` и `folderId`, результаты разбираются из XML в `rawData`, ссылки только https

#### Scenario: Нет каталога
- **WHEN** выбран Яндекс, а идентификатор каталога пуст
- **THEN** настройки не сохраняются и просят ввести идентификатор каталога

#### Scenario: Старая настройка Bing или Brave
- **WHEN** в сохранённом подключении был выбран Bing или Brave
- **THEN** выбирается Tavily; ключ Brave удаляется и не отправляется Tavily

#### Scenario: Смена способа поиска
- **WHEN** пользователь переключился с Tavily на Яндекс и обратно
- **THEN** у каждого сервиса остаётся свой ключ; в запрос уходит только ключ выбранного сервиса

#### Scenario: Ключ, сохранённый до раздельных ключей
- **WHEN** в подключении сохранён один ключ поиска старого формата
- **THEN** он становится ключом того сервиса, который был выбран
